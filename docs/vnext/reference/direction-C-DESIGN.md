# c407 — Service cabinet

## 1. Metaphor in one line, and the main gesture.
Worlds is a service cabinet whose fixed bays file distinct owners; each selected bay docks its own app beside the shared fact card that explains how its observations appear elsewhere. The main gesture is **open a labeled bay and inspect its docked app and facts**. The inset frame and owner/fact pairing remain recognizable without movement.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
The first render has exactly `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`). `#add-service` starts the third-service Connect flow for `notes-sync` (Notes Sync, `unavailable`). Render six steps: (1) Discover lists Notes Sync and its Memory owner; (2) Credential reference is labeled, accepts a reference only, rejects a secret value with the explanation “Worlds stores a credential reference, never the secret,” and shows dirty/submitted-pending/validation-on-blur states; (3) Safe test shows run/running/passed/failed and recovery; (4) Preview lists `sync.provider-reachable` (`unavailable`), `sync.local-pending` (3 notes, `live`), and `sync.last-synced` (`stale`); (5) Choose to publish provides a checkbox for each fact and states what will be shared; (6) Publish creates the Notes Sync bay with the selected fixture fact IDs. This is mock UI; no provider call occurs.

All bays are independent owners in a fixed reading order, not locations on a map: nothing unfolds, routes between services, or traces connections. The selected bay docks the embedded app and shared fact card together. Home, service bay, and Agent facts read one in-memory store keyed by fact ID. `#simulate-change` applies `lock-back-door` to `frontdoor.back-door` from fixture `crossViewExample`; in the same state update, Front Door becomes `healthy`, the fact becomes `locked`, and Home shows `attentionCount: 0`. The Agent facts row updates at the same time. This is a mock review/handoff only; Worlds does not lock anything. `#disconnect` confirms the selected service by name, removes its bay and app frame, and leaves remaining bays and shell destinations usable.

## 3. Navigation between Worlds and a service (phone and desktop).
Desktop keeps Home, Connect, Memory, and Settings in a persistent shell rail; the equal-order cabinet register and selected bay detail occupy the main area. The docked shared fact card sits adjacent to the embedded frame but remains a Worlds-owned view. At 390px, the register becomes a one-column list; a selected bay replaces it with a one-column detail screen, persistent shell destinations and explicit Back. Focus moves to the detail heading and returns to the invoking bay control. Source order follows navigation, main, complementary facts. All actions work by keyboard with visible focus and 44px targets.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The bay contains a sharply bounded inset screen for the owning app; a static cabinet lip, service name, state, and fallback identify its owner. No press/release or drawer travel is a recognition cue. Keep the owner fallback visible at the frame edge: Media Shelf — “Open Media app” (`app://media`); Front Door — “Open Home app” (`app://home`); Notes Sync — “Open Memory app” (`app://memory`). Fixture links use `app://` only. By design the frame receives no Worlds credential; whether the browser enforces that boundary, the exact sandbox flags, and app messaging are UNKNOWN. If embedding is unavailable, retain the shell and shared fact card, explain the failure, and show the owner link. Approvals hand off to Project Home; other actions hand off to the owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
The shared card and Agent facts view read the same fact records as Home. Each row separates source, observed/checked time, freshness, Agent can see, Human can see, and Who can act. `frontdoor.back-door`: agent `read`, human `act`, with fixture reason “Locking the door changes the external system and is the person's decision.” `frontdoor.guest-code-used`: human `read`; agent `none` rendered as a named disabled, focusable control with its exact reason: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” `frontdoor.unlocked-for`: both `read`. The mock `lock-back-door` routes to Project Home and records mock review only. `sync.provider-reachable` can be unavailable while local `sync.local-pending` remains live; preserve both records. Notes Sync retry is an owner-app handoff, never an approval.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
Zero services shows a vacant bay, Connect invitation, and the local Worlds/Memory baseline; zero providers means no invented readings. Quiet is Media Shelf's `healthy` state. Needs-you is Front Door's exact `needs_attention` state and fixture reason. Notes Sync remains `unavailable`, while its local pending count stays `live` and last successful sync stays `stale`; do not collapse provider failure into local-data failure. Unknown is not inferred for these composed services and is never shown as blank. Disconnect identifies the removed service; the other bays and shell stay usable; historical retention is UNKNOWN. Loading, safe-test failure, empty preview, and long-copy states each get recovery copy. The signature is static, and `prefers-reduced-motion` removes all nonessential motion.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr's one integration feeding multiple surfaces, Dashy's in-place app opening, HA cards' literal state words, and MCP ext-apps' contained UI and host permission boundary. Cabinet bays are independent owners in fixed reading order: no map, route tracing, unfolding place, or cross-service topology. The docked frame-plus-fact card makes the cabinet earn its metaphor by binding the independent UI to the shared fact view. Unlike round-one `foldout-atlas`, nothing unfolds into a selected place and the app is not a window floating over an atlas.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `design-taste-frontend` + `ds-skeumorphism`. The skill explicitly excludes dashboards and multi-step product UI, so use only brief-first and anti-default discipline; the product shell governs structure. Reconcile the playful source system with a calm personal appliance by using its physical metaphor only as one flat, static inset bezel, with no texture, raised/pressed state, or simulated mechanics. Use its 4/8/12/16/24/32 spacing, 12/14/16/20/24/32 type scale, `#111827` text, and `#FA3C00` primary only for restrained non-text edging/action marker; keep the `#FFFFFF` surface token to small frame interiors, never large surfaces. CTA text remains dark on a neutral surface. Measure text contrast at 4.5:1, large text and controls at 3:1, and focus at 3:1; if orange fails, it loses text/fill use and remains a non-text marker. Apply 390px no-side-scroll, 44px targets, keyboard operation, explicit state words, visible focus, static loading, reduced motion, no invented values, and MOCKUP label.

## 9. Signature element, hero thesis, reference lock.
Signature: the static inset screen and shared fact card dock together inside the selected owner bay, with owner and fallback permanently visible. Hero thesis: “The cabinet gives every service a place and every fact a source.” Reference lock: Teenage Engineering OP-1's labeled control-surface hierarchy (labels only, no tactile interaction) and Apple Home's accessory-to-home state handoff. The cabinet is a fixed owner register, not a map or drawer animation.

## 10. Risks and UNKNOWNs.
Actual embed support, browser-enforced isolation, service protocol, Connect API, and disconnect history are UNKNOWN. Skeuomorphic cues can imply unsupported controls; one static bezel is the full depth budget. Fixture data is synthetic and must remain labeled MOCKUP, never a real reading. Contrast must be checked on implemented pairs before review.
