## Your DESIGN.md

# v4629 — Windowsill

MOCKUP. Synthetic fixture data only (`docs/vnext/fixture/fixture.json`); nothing here is a real reading. Single self-contained HTML later; this file pins decisions first.

## 1. Metaphor in one line, and the main gesture.
Worlds is a sunny windowsill of paper-wrapped seed packets: one labelled packet per service, each owned by its app, each with a tiny drawn sprout whose posture says how it is doing (the words say it first). The main gesture is **pick a packet, and its app opens in a clipped frame with the fact slip tucked beside it**. Warmth is in the sprouts and the copy; the structure stays a calm app.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
Start: `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`, "Needs a human"). `#add-service` starts Connect for `notes-sync` in five real `<button>` steps: Discover → Credential reference (reference only; a pasted secret is refused with "Worlds keeps a reference, never the secret") → Safe test (idle/running/failed/passed; first run shows the fixture error "provider timed out" with "Try again") → Preview (`sync.provider-reachable` `unavailable`, `sync.local-pending` 3 notes `live`, `sync.last-synced` `stale`) → Publish (a checkbox per fact). Success is the "connected" moment: the new packet's seed sprouts (one 400ms transform, static under reduced motion) and the line "Notes Sync is on your sill." One in-memory store keyed by fact id feeds Home, the packet, the fact slip and Agent facts. No provider is called.
`#simulate-change` applies `lock-back-door` to `frontdoor.back-door` (`crossViewExample`): fact → `locked`, Front Door → `healthy`, `attentionCount` → 0, in one update across Home, the Front Door packet/slip and Agent facts, with a polite live-region announcement. It is a mock handoff recorded for review; Worlds locks nothing. `#disconnect` is on the first screen for the selected service (Front Door at first load), opens a confirm naming it, and its confirming button reads "Disconnect".

## 3. Navigation between Worlds and a service (phone and desktop).
Persistent destinations: Home, Connect, Memory, Settings (Agent facts is a tab of Home and of each service). Desktop: left rail. Phone: bottom tab bar, and a selected service opens as a full-height sheet with explicit Back; focus goes to the sheet heading and returns to the invoking packet. Source order: nav, main, facts.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The owning app is drawn as a framed window "clipped" to the packet, titled with its owner. Fallback sits at the frame edge, verbatim from the fixture: Media Shelf "Open Media app" (`app://media`), Front Door "Open Home app" (`app://home`), Notes Sync "Open Memory app" (`app://memory`); links are `app://` only. The frame is meant to carry no Worlds credential; browser-enforced sandbox flags and messaging are UNKNOWN. If it cannot load, the packet, slip, status and Back stay, and the failure and owner link are shown. Approvals hand off to Project Home; other actions to the owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Fact slip and Agent facts read the same records. Columns: source, checked time (live-recomputed), freshness word, Agent can see, Human can see, Who can act. `frontdoor.back-door`: agent `read`, human `act` ("Locking the door changes the external system and is the person's decision."). `frontdoor.guest-code-used`: agent `none` is a named, focusable, disabled control with its exact reason ("Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who."). `frontdoor.unlocked-for`: both `read`. Provider failure and local data stay separate records (`sync.provider-reachable` `unavailable` beside `sync.local-pending` `live`).

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
- First run (zero services): an empty sill with one bare pot, "Nothing planted yet", and an Add service button; no invented readings.
- Quiet: Media Shelf, "Healthy". Needs-you: Front Door, "Needs a human" plus its fixture reason.
- Stale (live feed): every tick ages "checked 2s ago" → "12s ago"; once a service passes 45s unchecked it moves to "Stale" in words, the sprout droops, and "Check now" resets it. Unknown: never blank; reads "Unknown" with the reason. Error: safe-test failure, embed failure, and Notes Sync `unavailable` each give cause and a next step, and keep input.
- Disconnected: the packet is removed, the sill closes up, and a line says "Front Door is no longer connected; its facts are gone from Home and Agent facts." Everything else keeps working. Retention after disconnect is UNKNOWN.
- Feed: ON by default; `#live-toggle` shows "Live: on / paused" and a "Paused" word beside the clock. Reduced motion stops animation, not data. Actions are optimistic ("Locking… → Locked"), then settle visibly.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Homarr: one integration feeds the UI and the assistant. Dashy: app opens in place. HA cards: literal state words. MCP ext-apps: contained UI under a host boundary. Different: no map, routes or topology; independent owners in a flat list, joined only by the shared fact store.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Skill `soft-skill` (high-end visual design) and `ds-paper`. Kept from the skill: the double bezel (outer hairline tray, inner core, concentric radii) for packets and the frame; pill buttons; custom cubic-bezier, transform/opacity-only motion; macro-whitespace; collapse to one column under 768px with `100dvh`. Rejected, because this is a daily app: scroll-blur entrances, glass blur on content, the floating-island nav, huge section padding, dark/glow archetypes. Fonts: Roboto/Montserrat (ds-paper) and Inter/Helvetica (skill) both conflict with the no-external-fonts rule, so system serif for headings (`ui-serif, Georgia`) and `system-ui` for UI. From `ds-paper`: tokens `#111111` primary/CTA, `#111827` text, `#FFFFFF` surface, 4/8/12/16/24/32 spacing, 14/16/18/24/32/40 type; success `#16A34A`, warning `#D97706`, danger `#DC2626` are only for small marks beside a state word (contrast checked on built pairs; failures fall back to `#111827`). Purple `#8B5CF6` is dropped (anti-slop indigo list); at most two accent uses per screen. Paper feel comes from hairlines and radii, no grain. Also applied: state-coverage (five states per surface), animation-discipline (≥150ms, motion only for change of state), accessibility-baseline, no emoji icons, no lorem, no invented metrics.

## 9. Signature element, hero thesis, reference lock.
Signature: the seed packet with its drawn inline-SVG sprout (upright, drooping, flagged, bare soil, sprouting on connect), always paired with a state word. Hero thesis: "Every service gets a packet, and every packet tells the truth." Reference lock: Apple Home's accessory-to-room status handoff (mechanics) and a Muji-style labelled stationery layout (labels and hairlines only).

## 10. Risks and UNKNOWNs.
Embed support and isolation, the Connect API and its real lifecycle, and disconnect history are UNKNOWN. The sprout cute factor could outrun the words, so words lead and the sprout never carries status alone. Live ticks could be noisy for screen readers, so only state changes are announced, politely. White-on-white relies on hairline contrast of 3:1, to be measured. Fixture is synthetic.

## 11. How it differs from C, and what it keeps
Keeps: the persistent Home / Connect / Memory / Settings shell, the app docked beside the shared fact card, owner and fallback always visible, the six-step Connect story for Notes Sync, the exact permission rows, and honest states. Changes: C's static cabinet bezel becomes a warm packet-and-sprout object with a drawn character per state; C is explicitly motionless, while this one is live (tick, stale drift, optimistic settle, connect sprout) and calm under reduced motion; the selected packet and Disconnect live on the first screen, not behind a register; copy is kind and specific ("Nothing planted yet"); the fact slip clips to the frame as a paper note rather than a fixed card; and the mobile layout is its own design.

## 12. Desktop and mobile layouts
**Desktop (1440px):** three columns. Left rail (Home, Connect, Memory, Settings, the MOCKUP label, and `#live-toggle` with the live clock). Centre: the sill, a grid of packets (Home summary on top: "1 needs you" and the quiet count, `#add-service` as a bare-pot packet). Right, the selected-service dock: header with name, state word and `#disconnect`, then the framed owning app with the owner fallback link, then the fact slip, then `#simulate-change`. Agent facts is a tab beside Home. Hover shows a lift, focus a 3px ring.
**Mobile (390px):** one column, own reading order: status line and clock with `#live-toggle`, "needs you" first, then the selected service card with its sprout, state word and `#disconnect`, then the list of other packets, then `#add-service` as a full-width button. Bottom tab bar (four 44px+ targets). Tapping a packet opens a sheet: heading, state, fact slip (facts before the app because it reads faster), framed app, owner link, Back. `#simulate-change` sits in a "Try it" row under the selected card. Connect steps are full-screen, one at a time, sticky Continue above the tab bar. No sideways scroll. Tablet (~768px, bonus): rail collapses to icons; the dock becomes a sheet.

Checker ids: `#add-service`, `#disconnect` (first screen, confirm button "Disconnect"), `#simulate-change`, `#live-toggle` (ON by default).

## CRITIQUE.md (another engine)

# CRITIQUE — v4629 "Windowsill"

Scope: a critique of the v4629 `DESIGN.md` against `concept-brief-v3.md`, `concept-brief-v2.md`, `docs/vnext/reference/direction-C-DESIGN.md`, `docs/vnext/fixture/fixture.json`, and the assigned OpenDesign pack (`skill-soft-skill`, `ds-paper`). Decisions-first: no code exists to review yet, so every gap is a gap in the pinned decisions. Five gaps, most important first.

Verdict in one line: the metaphor is warm and the signature is real, but the design stops at the sill — two destinations lead nowhere, the live feed is not tied to the fixture's provenance rules, the one governed action is modelled backwards, no action can fail, and the OpenDesign pack is used mostly as a list of things to reject.

---

## Gap 1 — Settings and Memory are named as destinations but never designed.

**Missing or wrong.** `concept-brief-v3.md` ("What 'the real rounds' add", item 1) requires "Real navigation, a settings screen, a first-run / empty state, an error state". v4629 lists Settings and Memory as persistent destinations (`§3`) and puts Settings in the desktop rail (`§12`), but no screen is specified for either. `§12` describes the sill, the Connect steps, the dock and the fact slip only; `§6` gives states for the sill and Connect, not for Settings or Memory; and `§3` actively muddles Memory with the agent view: "Memory, Settings (Agent facts is a tab of Home and of each service)". So a reader cannot tell whether Memory is a destination, whether it is the agent-facts view, or what either contains. Nothing states the "sensible defaults" the brief asks for.

**Why it matters.** A daily-use shell is judged at its second click. Home is designed to a high standard, then Settings and Memory are dead ends — and Memory is the wrong thing to leave blank, because the protected invariant is that local Memory is the zero-provider baseline that keeps working when nothing else does. The one surface that proves "Worlds still works with no provider" has no design. Requirement 4's agent-facts view is also only half-located: it exists as a "tab", but the destination it is tabbed beside (Memory) is undefined.

**Concrete fix.** Pin both screens in `DESIGN.md`:
- **Settings** (real content, five states): Worlds baseline and version; connected services with their owner and state word; the live-feed default (ON) and pause default; motion preference and reduced-motion behaviour; "data and disconnect history — UNKNOWN" stated plainly; the MOCKUP note; a local-first line that says what still works with zero providers.
- **Memory**: say in one sentence whether Memory is the agent-facts view or a separate local-notes surface. If separate, give it content (local records, the same fact records with source/freshness/who-sees/who-acts) and the empty/first-run state. If it is the agent-facts view, say so and drop the duplicate "tab of Home and of each service" wording.
- Both must carry the five required states and reach by keyboard.

---

## Gap 2 — The live feed drifts every service the same way and is not derived from the fixture's provenance.

**Missing or wrong.** `concept-brief-v3.md` item 4 asks for "a simulated live feed from the fixture" that "changes freshness … occasionally moves a service to stale, and updates every view that shows it without a reload". v4629 `§6` implements this as a flat rule: "every tick ages 'checked 2s ago' → '12s ago'; once a service passes 45s unchecked it moves to 'Stale' in words, the sprout droops". Three things are wrong with that as written:
1. It is unattached to the fixture's own rules. `fixture.json` `_meta.provenanceFields.ageSeconds` says "A viewer should recompute age from checkedAt rather than trusting this number", and `statesVocabulary` says "A blank value is never a state". The design never says the tick recomputes from `checkedAt`/`source`; it reads as a timer that increments a counter.
2. It is unscoped, so it will contradict the fixture's baselines. Applied uniformly, `media-shelf` — fixture state `healthy`, summary "Library reachable and indexing is current" — drifts to Stale ~45s after load; `garden-camera` (`unknown`, source `none`) would be pushed to Stale, which the fixture forbids; and `front-door` (`needs_attention` with a `live` freshness record) would show two competing state words with no rule for which leads.
3. "Check now" resets it, but nothing says which permission may reset. The fixture scopes retries as `allowed: "human"` (`notes-sync.retry`, `studio-printer.retry`); a reset reachable by anyone/anything is the same authority leak requirement 5 exists to prevent.

**Why it matters.** "No invented status" is a protected invariant, and a feed that manufactures a stale state the fixture does not support is exactly the invented reading the MOCKUP rule bans. It is also the most visible reactive behaviour on screen, so a reviewer will see the contradiction immediately.

**Concrete fix.** Define the feed as a derived view, not a counter: recompute `ageSeconds` from each fact's fixture `checkedAt` and `generatedAt`; age only facts whose fixture `state` is `live` and whose `source` is `local` or `external`; facts with `source: "none"` or a non-live baseline never drift (they render Unknown/Unavailable with their fixture reason). Keep the service's own state word separate from a freshness word so `needs_attention` + a stale freshness can coexist without ambiguity. Scope "moves to Stale" to the fixture's own stale candidate (`nightly-backup`) or to a fact crossing the threshold, never to the whole service by default. Make "Check now" a mock human action, announced politely (`role="status"`, no focus move), and say in one line that the mock does not call a provider.

## Gap 3 — `#simulate-change` mutates Worlds' own store, so the prototype demonstrates a decision made inside Worlds.

**Missing or wrong.** `concept-brief-v2.md`, integration requirement 5: "A decision is never made in Worlds; it links/hands off to the owning system (Project Home for approvals, the service itself otherwise)." v4629 `§2` says `#simulate-change` "applies lock-back-door to frontdoor.back-door … fact → locked, Front Door → healthy, attentionCount → 0". `§4` says "Approvals hand off to Project Home", but the control itself is a direct, one-press mutation of Worlds' in-memory store, with no handoff screen, no pending state from the owning system, and no visible owner link on the control. The prose "It is a mock handoff recorded for review; Worlds locks nothing" asserts a boundary the interaction contradicts: on screen, pressing a Worlds button changes a fact and a service state. The fixture's only governed fact — `frontdoor.back-door`, agent `read` / human `act`, "Locking the door changes the external system and is the person's decision" — has no affordance on the slip that expresses that split; the design never shows the human being routed to Home to act.

**Why it matters.** This single gesture is where requirements 4 and 5 collide: one change must light up Home, the service and agent facts (req 4) *and* it must originate in the owning system (req 5). v4629 satisfies 4 and only claims 5. A checker or reviewer pressing the one obvious button will see Worlds lock a door, which is the exact anti-pattern the brief names.

**Concrete fix.** Split the gesture into a handoff and a recorded result:
- The control reads as a handoff, not an action: "Lock in Home" with the owner and `app://home`, carrying the verbatim reason "Locking the door changes the external system and is the person's decision."
- Pressing it shows an "Awaiting Project Home" state (mock, "Worlds does not act; this belongs to Home"), then the recorded result appears: `frontdoor.back-door` → `locked`, Front Door → `healthy`, `attentionCount` → 0, propagated in one store write across Home, the packet/slip and Agent facts, with a polite live-region note that this is a mock record, not a Worlds action.
- Keep the fixture's `crossViewExample` result; change the framing from "Worlds applies" to "Home acted; Worlds recorded".

## Gap 4 — Optimistic actions have no failure or rollback path, and a connected service "dropping off" is undesigned.

**Missing or wrong.** `concept-brief-v3.md` item 1 names the error state to design: "a service that fails its test or drops off". Item 4 adds that "actions give instant optimistic feedback and settle visibly". v4629 `§6` gives "Actions are optimistic ('Locking… → Locked'), then settle visibly" but never defines a *failed* settle, and `§2`/`§4`/`§6` cover only the Connect safe-test failure and an embed-load failure. There is no state for a service that is already connected and then drops off mid-session — which is the case the brief explicitly calls out, and which the fixture already makes plausible (`notes-sync` provider `unavailable`, `sync.provider-reachable` `unavailable`, `lastError: "provider timed out"`). The design also invents retry copy ("Try again") where the fixture supplies real labels (`notes-sync.retry.label` "Check provider now"; `studio-printer.retry.label` "Retry last job", with last errors "provider timed out" and "job rejected: no media loaded"). `state-coverage.md` requires every error to give cause, recovery and preserved input, and to announce it politely.

**Why it matters.** An optimistic UI with no failure branch is a demo that always succeeds — the opposite of the honesty the concept claims, and the opposite of what a real daily app must do when a provider times out. With the live feed running, this state *will* be reached, so leaving it out is not an edge case; it is the main loop.

**Concrete fix.** Add three things:
- A settle-failed path: optimistic value → rollback to the last known value, inline cause, a retry using the fixture's own label, input preserved, announced with `role="status"` and no focus jump.
- A drop-off path: a connected packet whose provider stops answering shows its own state word (`Stale`/`Unavailable`/`Unknown`) with the fixture reason and the owner fallback, updates Home's attention count and the agent-facts row in the same write, and keeps the rest of the shell usable. Reuse `notes-sync` for it rather than inventing a service.
- Use the fixture's retry vocabulary verbatim instead of "Try again", so the error copy is real, not authored.

## Gap 5 — The OpenDesign starting point is used mostly as a rejection list, and `§8` contradicts itself.

**Missing or wrong.** `concept-brief-v2.md` ("Your OpenDesign starting point") says the assigned skill and design system should "shape the concept; say how in DESIGN.md", and the prompt guidance binds each concept to its design system ("do not invent values outside it"). The owner's decision in force repeats this: "take into account prompt guidance and the opendesign options". v4629 `§8` names what it rejected at greater length than what it kept, and the kept list contains an internal contradiction: it claims to keep "macro-whitespace", but `skill-soft-skill` defines that as `py-24`–`py-40` section padding (`§4C`), a marketing-landing scale that never appears in `§12`'s dense rail / sill / dock app — so the skill is listed as applied and then not applied. The soft-skill's actual structural core (`§3` Vibe + Layout archetype selection, `§7` execution protocol) is never chosen, so the concept could have been built without the pack. From `ds-paper`, the secondary `#8B5CF6` is dropped (correctly — it is on the anti-slop indigo list), but no token is named as the accent in its place, and "paper feel" is reduced to hairlines and radii while the system's defining paper texture is discarded without saying what carries the identity instead.

**Why it matters.** The pack is one of the few levers that makes 30 concepts differ from each other rather than from a default; a pack used only to subtract leaves no trace, and a self-contradicting §8 is exactly the "decision stated but not carried through" failure the prompt guidance warns about.

**Concrete fix.** In `§8`:
- Name the applied archetype and apply it: soft-skill "Soft Structuralism" (white/silver ground, airy components, soft diffused depth) with the "Asymmetrical Bento" layout, and its own mobile collapse rule (single column, `w-full`, `min-h-100dvh`) as the 390px basis — note that the skill already specifies this collapse, so it *does* shape the phone layout.
- List which soft-skill rules survive in a productivity shell (double bezel with concentric radii, pill CTA, custom cubic-bezier, transform/opacity-only motion, GPU-safe blur discipline) and explicitly drop macro-whitespace, eyebrow tags and scroll-blur entrances as marketing-only, so the contradiction goes away.
- Name the `ds-paper` token that serves as the accent and where its two permitted uses land; state plainly that the paper identity is carried by hairlines, radii and system serif rather than grain, so the choice to omit texture is a decision, not an omission.
