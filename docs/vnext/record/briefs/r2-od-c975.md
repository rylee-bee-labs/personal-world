## DESIGN.md

# c975 — The Triage Chart (MOCKUP, design only) — round 2 revision

Starting point: OpenDesign skill `hand-drawn-diagrams` + design system `doodle`. Data: `docs/vnext/fixture/fixture.json` only (ids, names, states, facts, permissions verbatim; nothing added). New concept; not an evolution of switchboard, strata or orrery. This revision fixes the five gaps in `CRITIQUE.md`; see "Critique fixes" at the end.

## 1. Metaphor and main gesture
Worlds is a **hand-drawn flowchart that answers questions about your services**: "Does anything need a human?" (Q1) "Is anything out of date?" (Q2) "Is anything broken?" (Q3). Each service is a sketched box at the end of the branch its state answers.
**Main gesture: follow the arrow.** Step through the chart question by question (tap a question, or arrow keys along the path); open a box by following its arrow. When a fact changes, the box **re-routes**: its arrow is erased and redrawn to the branch its new state belongs to.

## 2. Integration model
- A service is a **box**: name, state word, one summary line, all from the fixture, plus a **fact tally line** derived from its facts (e.g. "2 live, 1 unavailable").
- **Routing and roll-up (named rule: owner's state wins, tally disclosed).** A box's branch is the service's own reported `state` (the owning system's claim, verbatim): needs_attention → Q1 yes; stale or unknown → Q2 yes; unavailable → Q3 yes; healthy → "All fine"; not_configured/disabled → a dashed "Not set up" box. Fact states never move a box, but they are never hidden: the box's tally line and the Facts board show each fact's own state word, so the chart cannot disagree with the board. Mixed cases rendered explicitly: **Notes Sync** sits under Q3 "Unavailable" with tally "1 unavailable, 1 stale, 1 live" (`sync.local-pending` live, 3 notes; the line says "Local notes still work"); **Studio Printer** sits under Q3 with tally "1 unavailable, 2 live" (`printer.queue` and `printer.last-error-code` live). Q answers count services and say so ("Yes: 2 services") with the tally beneath.
- **One store, one `render()`.** Boxes, the open page, the Facts board, the text outline and the chart counts read one in-memory store (a copy of the fixture; the fixture is never mutated).
- **Start:** Media Shelf (`media-shelf`, healthy) and Front Door (`front-door`, needs_attention) connected.
- **Discover's source:** the fixture services not yet connected, name and state verbatim: Nightly Backup (stale), Garden Camera (unknown), Studio Printer (unavailable), Notes Sync (unavailable), Local Weather (not_configured). **The scripted path adds Nightly Backup (`nightly-backup`)**, listed first; the others are connectable and render per §6.
- **Add a box (Connect):** a dashed empty box "+ new service" opens a 5-step side sheet, ticked like a drawn checklist: Discover → Credential reference (a name like `ref:backup-reader`; secret-looking text refused with a plain note; nothing stored) → Safe test (read-only; result in words) → Preview (facts and capabilities, proposed see/act) → Publish (tick facts, "Publish N of M"). On Publish the dashed box inks in and its arrow routes to its branch.

## 3. Navigation
- **Phone (390px, no sideways scroll):** the chart is one vertical column (questions as speech-bubble headers, boxes beneath each answer, arrows down). A bottom tab row of three tabs, each at least 44px: Chart, Facts board, Add. Opening a box opens a full-width "pinned page" over the chart; "Back to chart" is its first control; hash `#/box/<id>`; browser Back closes it.
- **Desktop:** chart left (two answer columns under each question); pinned page opens right so the chart stays visible and re-routes live.
- **Keyboard:** boxes in path order; Enter opens, Esc closes and returns focus to the box; visible focus ring (primary `#49B6E5`, 2px, offset 2px) plus a "step 2 of 4" word.

## 4. Embedded-app frame
The service app is a **pinned page**: a taped-corner rectangle labelled "EMBEDDED: Front Door (owned by Home)", sandbox note in the label ("sandboxed, cannot read the chart"). **Open in the owning app** (`https://example.invalid/home/...`; fixture route `app://home` as route text) is a drawn button, always visible; if the app is unavailable or disabled, the page shows only the fallback and the reason. Worlds keeps: the chart (live), the tab row, the back control, and a Worlds-owned status stamp (state word, freshness). The mock app UI (Front Door: lock panel; Media Shelf: library list; Nightly Backup: run history) **redraws from the store** and posts events to it.

## 5. Agent/human shared facts
The **Facts board** is a sheet of sticky labels, one per fact: label, value, source stamp (LOCAL / EXTERNAL / NONE), the fact's own state word, "checked 28 s ago" (from `checkedAt`), and two separate rows, **Agent** and **Human**, each with drawn tick-marks and words for see / act (human also write). `none` is a crossed-out label with its fixture reason. A just-changed fact wears a "just changed" tag. Tapping a label highlights its owning box on the chart.

## 6. States
- **First run:** empty board: Q1 with a dashed empty box and "Nothing connected. Worlds still works." and an Add button. Zero providers is the same state.
- **Quiet:** Q1 "No" with a plain tick; boxes under "All fine".
- **Needs-you:** Q1 "Yes: 1 service", box under it, **Hand off** on its page (§6a). The answer is written in words.
- **Stale:** dashed outline, "Stale" plus age. **Unknown:** dotted outline, "?" glyph beside the word "Unknown", values "unknown" (fixture `unknownReason` shown).
- **Unavailable:** under Q3 with the tally above; the fixture `retry` is a **Hand off: Retry last job / Check provider now** control showing `lastError` and attempts.
- **Not configured** (Local Weather): dashed "Not set up" box; its page has no facts and prints the fixture `emptyReason`. No placeholder value.
- **Disconnected** (`#disconnect`, on every pinned page): the box is erased to a ghost outline: "Disconnected. Gone: its facts, its warning. Kept: its data stays with its owning app." Counts update; the chart still works.

### 6a. Governed hand-off (Req 5)
Worlds never decides or acts. Approvals → **Project Home** (`https://example.invalid/project-home/approvals`; none in the fixture). `act` facts (`frontdoor.back-door`) and `retry` → the **owning app route** (`https://example.invalid/home/...`, route text `app://home`). The button says "Locking the door is decided in Home." Worlds only **records the returned result**.

### 6b. The one-fact demo (Req 4)
`#simulate-change` ("Simulate: Home reports the back door locked") posts the fixture `crossViewExample`: `frontdoor.back-door` → `locked`, `front-door` → healthy, `attentionCount` → 0. One store write redraws: (1) the chart: Front Door's arrow **re-routes** from Q1 to "All fine", Q1 flips to "No"; (2) the pinned page and its mock lock panel (locked, status Healthy); (3) the Facts board label (locked, "just changed", checked just now); (4) the text outline. `frontdoor.unlocked-for` keeps its last value, marked stale ("last observed 47 minutes"). The mock's lock button posts the same event. "Reset demo" restores the copy.

## 7. Borrowed vs different (including uniqueness)
- Homarr: one integration for UI and assistant. Borrow: box and label share one record. Different: no widget grid.
- Dashy: apps open in place. Borrow: pinned page. Different: the chart persists and re-routes beside it.
- HA cards: shared subscription. Borrow: the store. Different: routing is derived from state, so the layout is the subscription.
- MCP ext-apps: sandbox + events. Different: fallback always drawn.
- **Not a tech tree, not `foldout-atlas`.** A tech tree is progression: levels, prerequisites, unlocks, a path you climb. Here **a position is a verdict, not a level**: a box sits under "Yes" or "No" for the question asked *now*, can move up or down both ways at any time, nothing is locked or unlocked, and there is no root-to-leaf progress or completion state. Routing is derived from live state; nobody lays it out. `foldout-atlas` is an invented map with a traced route over terrain; c975 has no map, no terrain, no route to trace, and its geometry is a short fixed questionnaire (3 questions, never more than 2 columns), so a rougher stroke on the atlas is not what this is. The rough stroke is a style; the spine is a triage decision list.

## 8. OpenDesign starting point and rules applied
- Skill `hand-drawn-diagrams` (catalogue entry only; upstream not read, so UNKNOWN beyond rough boxes, arrows, animated SVG). Used: rough-stroke SVG boxes, arrows that draw in on change, no PNG/hosted edit link.
- Design system `doodle`: primary `#49B6E5` for interaction (focus, primary button, active arrow), secondary `#263D5B` for strokes, text `#111827`, surface `#FFFFFF`, success `#16A34A`, warning `#D97706`, danger `#DC2626` only as stroke accents beside words; spacing 4/8/12/16/24/32; type 14/16/18/24/32/40; display Delius Swash Caps with fallback `"Segoe Print","Bradley Hand",cursive` (headings only), plain system sans body, monospace stamps. 150–250 ms transitions.
- Guide rules: single job, hero thesis, one signature, no emoji icons (hand-drawn SVG glyphs), no invented metrics; under `prefers-reduced-motion` arrows appear fully drawn.

## 8a. Text alternative for the chart (accessibility-baseline)
The chart ships an **ordered text outline** (`<ol id="chart-outline">`, visible via a "Read as list" toggle on desktop and always present in the document for assistive tech): each question with its answer count ("1. Does anything need a human? Yes: 1 service. Front Door, Needs a human, 3 facts live."), then each box under each answer with name, state word, freshness and tally, then the "All fine" and "Not set up" groups. The SVG chart has `role="img"` with `aria-labelledby` its title and `aria-describedby="chart-outline"`; question and box nodes are real focusable elements in the same order as the outline. The outline re-renders from the store with the chart, and a polite live region (`#chart-live`) announces re-routes ("Front Door moved to All fine").

## 9. Signature, hero thesis, reference lock
- **Signature:** the re-routing arrow (§1, §6b).
- **Hero thesis:** "The layout is the answer: where a box sits tells you what to do about it."
- **Reference lock:** Excalidraw's rough-stroke look and a paper decision tree (question nodes, branch labels), mechanics only.

## 9a. Control ids the prototype will use
`#add-service` (the dashed "+ new service" box and the Add tab), `#disconnect` (on each pinned page), `#simulate-change` (§6b). Also `#chart-outline`, `#chart-live`, `#reset-demo`.

## 10. Risks and UNKNOWNs
- Looks: "playful" may read unserious beside a door lock; counter with plain labels and the hand-off wording.
- Rough filters (SVG turbulence) hurt legibility and perf: wobble on strokes only, never text.
- Warning amber `#D97706` on white may miss text contrast: strokes beside words only; to verify.
- Doodle fonts unavailable offline: fallback rendering UNKNOWN across devices.
- With 7 services the phone chart gets long: "All fine" and "Not set up" groups collapse (the outline keeps all).
- Real ext-app sandbox behaviour UNKNOWN; hrefs use `example.invalid`.

## Critique fixes
1. **Plug-in names no service/source (fixed):** §2 gives Discover's source and the added service, `nightly-backup`.
2. **Routing from service state only (fixed):** §2 names the rule (owner's state places the box, fact states always disclosed in a tally and on the board) and renders Notes Sync and Studio Printer explicitly. Not changed to worst-fact-wins: it would override the owning system's own claim and contradict the fixture's `state`.
3. **Hand-off destination (fixed):** §6a.
4. **Uniqueness (fixed):** §7 argues not a tech tree and not `foldout-atlas`.
5. **No text alternative (fixed):** §8a adds the ordered outline, accessible name and live region.
