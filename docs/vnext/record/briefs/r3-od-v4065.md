## DESIGN.md

# v4065 — Annotated plates (MOCKUP)

Status: MOCKUP design. Synthetic fixture (`docs/vnext/fixture/fixture.json`) is the only data; nothing here is a real reading. Builds on `concept-brief-v3.md` + `concept-brief-v2.md` and keeps direction C's shell.

## 1. Metaphor in one line, and the main gesture.
Worlds is a studio wall of hand-drawn plates: each service is a small ink drawing of its own object (a shelf, a door, a notebook), and every fact is a numbered callout on that drawing. The main gesture is **tap a callout to read its source, freshness, who can see and who can act**. The drawing is the fact card; the pencil line is the provenance. The drawing never replaces the state word.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
**Start:** `media-shelf` (Media Shelf, `healthy`, "Healthy") and `front-door` (Front Door, `needs_attention`, "Needs a human"). Ids, names, states, facts and fixture strings verbatim; nothing added. Plate Nº follows connect order: Nº 01 Media Shelf, Nº 02 Front Door, Nº 03 Notes Sync.

**Connect (`#add-service`)**, six steps, each a real `<button>` ("Next: Credential reference", "Run safe test", "Back", "Publish"):
1. *Discover.* Finds one candidate, Notes Sync (`notes-sync`, kind `sync`, `unavailable`), owner Memory.
2. *Credential reference.* Labelled input accepting a reference name only. A pasted secret (anything that looks like a token or contains `=`/whitespace-free 24+ chars) is refused on blur with "Worlds stores a credential reference, never the secret". States: pristine, dirty, submitted-pending, invalid (message + the field kept, nothing stored).
3. *Safe test.* Run / running / passed / failed. Passed copy: "Reached it. Nothing was changed." Failed copy (reachable via a "Simulate a failed test" link-button under the Run button): "That didn't work, and nothing was saved. Check the reference and try again." with a "Try again" button and the fixture reason `provider timed out`. Recovery never leaves the flow.
4. *Preview.* `sync.provider-reachable` (`unavailable`, source `external`), `sync.local-pending` (3 notes, `live`), `sync.last-synced` (`stale`). Empty-preview state: "This service offered no facts. Nothing to publish."
5. *Choose what to publish.* One checkbox per fact, all checked by default; a line states "Worlds will share N of 3 facts with the agent and with you. The service keeps the data." Publish is disabled with the reason "Choose at least one fact" if none are checked.
6. *Publish.* Plate Nº 03 appears, Notes Sync selected, the connect moment plays (§6). Mock only; no provider call.

**One store.** A single in-memory store keyed by fact id feeds Home, the plate, Agent facts, Settings and Memory. Every view re-renders from it; no view keeps its own copy.

**Simulated clock (replaces wall-clock ages).** The store holds `simNow`, starting at the fixture's `generatedAt` (2026-10-13T14:24:26Z). Age of anything = `simNow − checkedAt` (the fixture's own rule: recompute from `checkedAt`). First paint therefore reads Media Shelf "checked 28s ago", Front Door "checked 24s ago". Ages are shown as `Ns ago` under 120s, then `Nm Ns ago`.
- **Tick:** every 4s of real time while Live, `simNow += 10s` and any scripted event for that tick fires. **Pause** stops the tick; `simNow` and all ages freeze. Real time never feeds an age.
- **Stale rule (stated, not random):** a `live` fact becomes `stale` when its age exceeds **180s** (fixture-consistent: Nightly Backup at 30266s and Notes Sync at 266s are stale, Media Shelf at 28s and Studio Printer at 106s are live). A service whose every live fact is stale changes its **state word** to "Stale" (a service already `unavailable` keeps "Unavailable"; `needs_attention` keeps "Needs a human" and adds "· checked Ns ago, stale" after it). The window is shown read-only in Settings.
- **Scripted feed** (24-tick cycle, ≈96s real, then repeats; events for services not connected are skipped). Every event is built only from fixture records and captioned "Simulated" in the feed line and in Memory:
  - t3 and t18: Front Door re-checked: `checkedAt = simNow`, values unchanged.
  - t8 and t20: Notes Sync: local queue re-checked (`sync.local-pending` stays 3, `live`); provider "timed out again" (`lastError: provider timed out`, attempts +1); `sync.provider-reachable` stays `unavailable`.
  - t20: Media Shelf re-checked (it has crossed 180s at ≈t16 and shows "Stale" for ≈4 ticks, then returns to "Healthy"). The settle is visible, which demonstrates the rule.
  - Nightly Backup window passing is not in the script (that service is not connected).
- **Feed line:** under the status strip, one polite live-region line: "Simulated: Front Door re-checked." Paused reads "Paused — ages frozen". The strip shows "Simulated time 14:24:26Z". Neither is ever called a real reading.

**`#simulate-change` — an inbound decision, not a Worlds decision.** Label: "Simulate: Project Home approves lock". It applies `lock-back-door` to `frontdoor.back-door` as if the owner reported back: the fact becomes `locked`, Front Door becomes `healthy` ("Healthy"), attention count 0, `checkedAt = simNow`; Home, the plate and Agent facts change in the same store update. Copy next to it: "Project Home approved the lock; Worlds recorded it (mock). Worlds did not lock anything." with the handoff link "Open Project Home" (`app://project-home`, mock link). Nothing in Worlds ever says Worlds decided. The button disables after use (label "Lock recorded (mock)"); a "Reset demo" link in Settings restores the fixture start.

**Optimistic → settle, one pattern for every user action.**
Press feedback ≤100ms (pressed state); the row/callout/checkbox flips at once (≈150ms colour-free confirmation: the stroke redraws or the word swaps); then it settles with one plain line in the Memory notebook and inline under the control: "Recorded (mock)" (Worlds-local changes) or "Handed to <owner> (mock)" (handoffs). On failure it reverts and says so ("Couldn't record that. Nothing changed.").
| Action | Instant | Settles as |
|---|---|---|
| `#simulate-change` | callout flips to `locked`, word Healthy, count 0 | "Recorded (mock)" + Project Home link |
| Publish step 6 | plate appears | "Notes Sync is on the wall." / "Recorded (mock)" |
| Publish / unpublish a fact (Settings checkbox) | checkbox flips; callout appears/disappears; Agent facts row appears/disappears | "Recorded (mock)" |
| Retry (Check provider now) | button shows "Handing over…" | "Handed to Memory (mock)"; the owner decides; no state change in Worlds |
| `#disconnect` | dialog closes; plate redraws to blank | "Recorded (mock)" in Memory |
| `#live-toggle` | label and aria-pressed swap | feed line "Paused — ages frozen" / "Live" |

## 3. Navigation between Worlds and a service (phone and desktop).
Four persistent destinations: **I. Home, II. Connect, III. Memory, IV. Settings**. Selected service defaults to Front Door at first paint, on both widths.

**What each renders (1440 / 390):**
- **Home** — the daily screen. A one-sentence status line first: "1 thing needs you: Front Door." (0: "Nothing needs you. Go and have a cup of tea."). Then the register (name, state word, freshness) and the selected service workspace.
  - *1440:* register (320px) beside the selected plate + docked app frame + fact card; `#disconnect` and `#simulate-change` in the plate header.
  - *390:* **landing sentence: Home opens on the status line, then the selected service card (Front Door: plate thumbnail, state word, summary, `#disconnect`, `#simulate-change`), then the other services as rows.** So `#disconnect` is on the first screen without scrolling or opening anything, and the screen is truthfully "Home". "Open plate" on that card (or tapping any row) pushes the full-screen plate. The action buttons are one component rendered in exactly one place at a time (Home's selected card, or the plate header when the plate screen is open), so the ids stay unique.
- **Connect** — the six-step flow (§2) with a step indicator "Step 3 of 6". 1440: stepper left, step body right. 390: one step per screen, sticky bottom Next/Back above the tab bar. Reached from `#add-service` (in the register header on 1440; a labelled "Add a service" button at the top of Home's list and on this tab on 390). Zero services shows the first-run invitation.
- **Memory** — Worlds' own notebook of what it recorded this session: connects, disconnects, "Recorded (mock)" and "Handed to … (mock)" lines, and the Simulated feed events, newest first, each with its simulated time and the caption "Simulated" where it is. Empty state: "Nothing recorded yet. Worlds writes here when something changes." When Notes Sync is connected, a link "Open Memory app" (`app://memory`) sits at the top (the owner's own Memory app is separate; this notebook is Worlds' own). 390: single list, no table.
- **Settings** — labelled sections, each a heading with a short description:
  1. *Live feed:* "Live feed" switch (same state as `#live-toggle`, not a second id), "Tick every 4s (simulated +10s)", read-only "Stale after 180s without a re-check", "Replay feed from the start", "Reset demo".
  2. *Motion:* "Follow system reduced-motion" (default on) / "Always reduce motion" / "Allow motion". Never disables the data tick.
  3. *Published facts:* per connected service, one checkbox per fact (same publish choices as step 5, same store; unticking removes the callout and the Agent facts row). Unticked facts show "Not shared. The service keeps the data."
  4. *Services Worlds does not hold:* fixture services present but not connected, shown as owner handoffs only, not as connected tiles: **Local Weather**, "Not configured", with the fixture reason ("No provider configured, so there are no facts to show.") and link "Open provider settings" (`app://settings/providers`); **Nightly Backup**, "Stale", "Last successful run is older than the configured daily window.", link "Open Backup settings" (`app://settings/backups`).
  5. *About this mock:* MOCKUP, synthetic fixture, UNKNOWNs list (§10).
  - 1440: section nav on the left of the main area, sections on the right. 390: sections stacked, each collapsible with real `<button aria-expanded>` headings, first two open.
- **Agent facts** is a tab inside Home beside the plate ("Plate | Agent facts") on 1440, and a second segmented control on the 390 plate screen; it is not a fifth destination.

**Phone chrome.** Bottom tab bar, four tabs, each ≥44px high with an icon + word. Top bar: "Worlds", MOCKUP label, `#live-toggle`. A selected plate is a full screen with explicit Back; focus moves to its heading and returns to the invoking row/button. `#disconnect` asks "Disconnect Front Door?" with buttons "Disconnect" and "Cancel", focus trapped, Esc cancels.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The owning app sits in a plain inset frame beside (1440) or below (390) the plate, titled "<owner app> · <state word>". The fallback sits at its edge, always visible: Media Shelf "Open Media app" `app://media`; Front Door "Open Home app" `app://home`; Notes Sync "Open Memory app" `app://memory`. The frame is given no Worlds credential by intent; real enforcement, sandbox flags and app messaging are UNKNOWN. A "Simulate: embed unavailable" link-button in the frame header demonstrates failure: shell, tabs, plate, callouts and facts stay; the frame body says "This app can't be shown here. Open it in its own app." with the owner link. Worlds keeps nav, Back, status strip and `#live-toggle` around the frame. Frame content is mock markup built from fixture strings (e.g. Front Door's summary), labelled "Mock of the owning app".

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Agent facts is a table over the same store records (390: stacked rows). Columns: Fact · Source (`local` / `external` / `none`) · Observed (time + freshness word, from `simNow`) · Agent can see · Human can see · Who can act.
- `frontdoor.back-door`: agent read, human act. Reason shown: "Locking the door changes the external system and is the person's decision."
- `frontdoor.unlocked-for`: both read. `frontdoor.guest-code-used`: human read; agent `none` rendered as a named, focusable, `aria-disabled` control "Agent can't see who" with the verbatim reason "Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who."
- `media.*`: both read. Notes Sync keeps `sync.provider-reachable` (`unavailable`, source `external`) and `sync.local-pending` (`live`, 3 notes, `local`) as separate rows; `sync.last-synced` `stale`.
- Acting hands off to Project Home (approvals) or the owning app; never decided in Worlds. "Check provider now" is an owner handoff ("Handed to Memory (mock)"), not an approval. Unticked (unpublished) facts are absent from this table.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
Every state is a word first, a persistent drawn mark second, motion last (motion only confirms).
**Persistent drawn states (static; survive reduced motion):**
- *Quiet / Healthy:* the object is complete; a small sparrow sits settled on the shelf edge; a drawn tick in the plate corner. Word "Healthy".
- *Needs a human:* the door ajar with the latch open and a drawn hand-pointer to the latch; a bracket-and-bar mark. Word "Needs a human" + fixture `attentionReason`. After `#simulate-change` the door is drawn latched, the bolt across, the sparrow now on the lintel.
- *Stale:* outline dashed, pencil hatching across the object, a small clock mark. Word "Stale" + age.
- *Unavailable:* the connector stub of the drawing ends in a gap with two small break ticks (Notes Sync's notebook with its line to the provider cut); local-notes part stays solid. Word "Unavailable"; "Local notes still work."
- *Unknown (never blank):* dotted outline, a question-mark mark; word "Unknown" and the age/reason; used for any fact with no value.
- *First run (zero services, zero providers):* one blank dotted plate with the sparrow asleep, "A plate waiting for its drawing.", "Connect a service and it will be sketched in.", and a Connect button. No invented readings.
- *Error:* failed safe test: reason, "Try again", "nothing was saved".
- *Disconnected:* plate redraws to blank; "Front Door is gone from Worlds: its facts, plate and frame. Other services are untouched." Retention UNKNOWN. If it was the last service, the first-run state appears.
**Pinned kind copy (exact strings):** "A plate waiting for its drawing." · "Notes Sync is on the wall." · "Nothing needs you. Go and have a cup of tea." · "Reached it. Nothing was changed."
**Motion (confirmation only, ≤250ms, ≤0.25s transitions):** on connect a pencil sketches the last connector line; on a state change the stroke redraws. Under `prefers-reduced-motion` (or Settings "Always reduce motion") both become an instant swap, and the persistent drawn states and strings above carry the warmth. The data tick always runs.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Homarr: one integration feeding UI and agent view. Dashy: open the app in place. HA cards: literal state words. MCP ext-apps: contained UI under a host boundary. Different: facts are not a widget grid; each is annotated on the drawing of that service's own object, and nothing routes or maps between services.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
**Skill `hand-drawn-diagrams`:** wobbly monoline SVG strokes (hand-written path jitter, stroke-linecap round), numbered leader-line annotations, the animated-stroke idea (static fallback). Its Excalidraw output and hosted link are not used; drawings are inline SVG.
**System `atelier-zero`, structure not just tokens:**
- *Top metadata strip (adopted; mandatory in the system):* one hairline bar above the shell. 1440: "Worlds · Vol. 1 · Nº 4065 · Filed under: Services · MOCKUP · Simulated time 14:24:26Z · `#live-toggle`". 390: collapses to the top bar "Worlds · MOCKUP · `#live-toggle`" (the rest moves to Settings > About). MOCKUP is visible in both at all times.
- *Plate devices:* "Plate Nº 02", "FIG. 02 / WORLDS-4065" in the system-mono stack at 10.5px, corner brackets on each plate, a "Filed under: Home access" badge (the fixture `kind`), numbered callouts with leader lines.
- *Roman numerals as the chapter walk:* I. Home, II. Connect, III. Memory, IV. Settings, and in-plate sections I. Plate, II. Facts, III. App. Used as headings of a sequential walk, not nav decoration.
- Tokens: Paper `#efe7d2`, Bone `#f7f1de` (cards), Ink `#15140f`, Ink-soft `#2a2620`, Ink-mute `#5a5448`, Coral `#ed6f5c`, hairline rules, 9.5–38px scale, 18px card radius, transitions ≤0.25s.
- Adjustments: no external fonts (system serif italic for Playfair; system sans for Inter Tight; system mono for JetBrains Mono); drop the paper-noise overlay and 36px side rails (they cost mobile width); no collage photos; mustard/olive unused.
**Contrast, measured (WCAG relative luminance):**
| Pair | Paper `#efe7d2` | Bone `#f7f1de` |
|---|---|---|
| Ink | 14.95 | 16.33 |
| Ink-soft | 12.2 | 13.31 |
| Ink-mute | 6.09 | 6.65 |
| Ink-faint `#8b8676` | 2.95 (fails) | 3.22 |
| Coral | 2.42 (fails) | 2.64 (fails) |
| Ink on Coral | 6.17 | — |
Decisions from these numbers: body, labels, Roman numerals, plate numbers and every meaningful mark use **Ink or Ink-mute** only. Ink-faint is never used for text or meaning. **Coral is decorative only** (the end-of-heading period, a pulse dot, the sparrow's accent, hatch fills) and never carries a state or a boundary alone. Coral buttons: label Ink (6.17:1) with a 1.5px Ink border (the fill alone is under 3:1 against Paper). Focus ring: 2px Ink with a 2px Bone gap (≥3:1 on both surfaces). State marks drawn in Ink.
**Rules applied:** anti-ai-slop, state-coverage, accessibility-baseline (4.5:1 text, 3:1 controls/focus, 44px targets), animation-discipline (150ms confirmation, motion never the only signal, reduced-motion), laws-of-ux (settings grouped in labelled sections), no emoji, no invented metrics.

Signature: the annotated plate, a drawn object with numbered callouts tied to fact records. Thesis: "Every fact is pinned to the thing it came from." ## 10. Risks and UNKNOWNs.
UNKNOWN: embed support, enforced isolation and sandbox flags, the Connect API shape, retention after disconnect. Risks: wobbly drawings must stay legible and never replace the text state; leader lines on 390 collapse into numbered rows (markers on the drawing, list below); scripted stale/timeouts are simulated, not fixture data, and are captioned "Simulated"; the 180s window is inferred from the fixture's own live/stale states. Fixture is synthetic; the page stays labelled MOCKUP.

## 11. How it differs from C, and what it keeps.
**Keeps:** the real shell (Home / Connect / Memory / Settings), fixed owner-labelled services, the app docked beside a shared fact view, honest state words, the fixture's exact permissions, calm structure. **Differs:** C's bezel and fact table become a hand-drawn plate whose callouts carry the facts; type and paper come from Atelier Zero rather than skeuomorphism; there is a live feed on a simulated clock, with warmth carried by persistent drawn states; mobile has its own navigation and reading order.
**Anti-repeat, nearest neighbours:**
- *Round 2 hand-drawn triage chart:* borrowed mechanism is leader-line annotation only. The plate is a drawing of one service's own object, not a chart of a process or a ranking by urgency; order is fixed and owner-labelled, and nothing is sorted into triage lanes.
- *Round 2 editorial ledger of facts:* borrowed: Roman-numeral/print devices. Facts live as callouts on an object and as a table only in Agent facts; there is no running ledger or column of entries as the home.
- *Round 1 field atlas map / foldout-atlas:* nothing unfolds, no places, no map; no cross-service routing or connectors between plates; the app is a docked frame, not a window over a map.
- Same `hand-drawn-diagrams` skill as the triage chart, so the look is differentiated by subject (objects, not flows), paper-and-plate print devices, and the persistent drawn states.

**Checker ids (each exactly once in the DOM at any moment):** `#add-service`, `#disconnect` (visible on first screen at 1440 and 390), `#simulate-change`, `#live-toggle`; MOCKUP label always visible. Default view: Home, Front Door selected, feed Live.

## 13. Critique fixes

3. *Optimistic action vs. Worlds not deciding:* `#simulate-change` is an inbound "Project Home approved the lock; Worlds recorded it (mock)" with a handoff link; one optimistic→settle pattern for every action (§2 table).
4. *Anti-repeat:* §11 names the triage chart, ledger of facts and field atlas, with the borrowed mechanism and the difference for each.
5. *Warmth/system as surface:* persistent drawn states and four pinned strings survive reduced motion; metadata strip adopted with plate numbers, FIG labels, corner brackets and "Filed under"; Roman numerals are a chapter walk; contrast measured and coral made decorative-only (§8).
