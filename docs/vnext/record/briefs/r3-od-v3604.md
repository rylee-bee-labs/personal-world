## DESIGN.md

# v3604 — The service shelf

## 1. Metaphor in one line, and the main gesture.
A calm service shelf puts the service that needs a person first, then lets them open its own screen; the source tab is the one control that opens the adjacent Worlds fact slip. The main gesture is **notice what needs you, open its service, then deliberately follow “from this app” to inspect the shared facts**. Warmth comes through the exact kind copy and small hand-drawn inline-SVG tab, not a storybook theme. On a state change, the selected service’s plain-text status line settles from the old state to the new one; reduced motion makes it an immediate text swap. Nothing decorative carries status.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
The initial shelf contains fixture services `media-shelf` (Media Shelf) and `front-door` (Front Door), plus `garden-camera` (Garden Camera) and `local-weather` (Local Weather) so unknown and zero-provider states are reachable without invented records. `#add-service` starts a six-step Connect flow for `notes-sync` (Notes Sync): Discover; Credential reference (reference only, never a secret); Safe test; Preview; Choose what to publish; Publish. Preview names `sync.provider-reachable` (`unavailable`), `sync.local-pending` (3 notes, `live`) and `sync.last-synced` (`stale`). Publish adds the selected fixture facts. At every width the six steps use real `<button>` controls labelled “Back”, “Continue”, and, on the final step, “Connect Notes Sync”.

Every service owns its data and actions. Worlds composes selected facts from one in-memory fixture store into Home, the selected service and Agent facts. Fixture inventory (all state labels are literal; values and states are not synthesized):

| Service ID / name | Fixture state label | Fact IDs, values and states |
|---|---|---|
| `media-shelf` / Media Shelf | Healthy | `media.items` 1284 items (`live`); `media.indexing` 0 items (`live`); `media.played-recently` 12 items (`live`) |
| `front-door` / Front Door | Needs a human | `frontdoor.back-door` unlocked (`live`); `frontdoor.unlocked-for` 47 minutes (`live`); `frontdoor.guest-code-used` value `visitor-3` (`live`, human-only value) |
| `garden-camera` / Garden Camera | Unknown | `camera.last-frame`, `camera.reachability`, `camera.human-detected-today` have no value (`unknown`) |
| `local-weather` / Local Weather | Not configured | no facts; render `emptyReason` verbatim: “No provider configured, so there are no facts to show. The concept must render the empty state honestly rather than a placeholder value.” |
| `notes-sync` / Notes Sync, after Connect | Unavailable | `sync.provider-reachable` no value (`unavailable`); `sync.local-pending` 3 notes (`live`); `sync.last-synced` `2026-10-13T13:58:00Z` (`stale`) |

`#simulate-change` applies fixture `lock-back-door` to `frontdoor.back-door`: pending “Locking…” appears on Home, Front Door and Agent facts in the same store update, then after about 900ms the fact settles to `locked`, Front Door to `Healthy` / `healthy`, and Home `attentionCount` to 0. This is mock handoff/review, never a real lock action. `#disconnect` confirms the service by name and removes its shelf entry; all other Worlds destinations remain usable.

## 3. Navigation between Worlds and a service (phone and desktop).
Desktop (1440px): persistent left rail for Home, Connect, Memory and Settings; the main canvas has a need-ordered service index and a generous service region with the owner frame. The “from this app” tab opens the complementary fact slip adjacent to the frame; it is closed until deliberately requested. Source order is navigation, main, complementary facts. The index sorts needs-you first, then least-recently-checked; healthy and unknown remain explicitly labelled.

Mobile (390px): persistent bottom bar carries Home, Connect, Memory and Settings. The app opens directly on the Front Door detail because it is the only `Needs a human` service. Back returns to the need-ordered index. Detail order is service name and state, `#disconnect`, owner frame, then facts; the tab opens facts inline. The index also has a per-row disconnect control. Both launch the same confirmation dialog with the service name and exact confirm button “Disconnect”. After confirmation from detail, return to the index and leave “Front Door left the shelf” visible; Home’s attention count becomes 0 at that same transition. All targets are at least 44px, safe areas are respected, keyboard focus follows semantic order, and 200% zoom reflows without horizontal page scroll. No critical action is in hover or overflow.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The owner app sits in a restrained frame labelled by service name, state and owning app. Shell navigation, current service state and fact slip remain outside it. Fixture fallback links stay at the frame edge, including when embedding fails: “Open Media app” (`app://media`), “Open Home app” (`app://home`), “Open Home cameras” (`app://home/cameras`), “Open provider settings” (`app://settings/providers`), and “Open Memory app” (`app://memory`). A missing frame leaves its explanation and owner link in place. The mock frame receives no Worlds credential; browser isolation, sandbox flags and app messaging remain UNKNOWN. Governed Home decisions hand off to Project Home; other service actions hand off to their owner app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Home, service detail and Agent facts read identical fact IDs. Each row states value and fact state, source, observed time, checked time, freshness in words, Agent visibility, Human visibility, and who can act. Permission examples: `frontdoor.back-door` is Agent `read`, Human `act`, reason “Locking the door changes the external system and is the person's decision.” `frontdoor.unlocked-for` (47 minutes) is Agent `read`, Human `read`. For `frontdoor.guest-code-used`, the Human sees `visitor-3` (`read`); the Agent value is not shown and its cell is a named, disabled, focusable control labelled “Agent cannot read this”, carrying verbatim reason “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” Garden Camera’s `camera.human-detected-today` similarly renders Agent’s `none` as a named disabled control with “The agent may not assert a detection while the source is unknown.”

The live feed is ON by default and `#live-toggle` visibly pauses/resumes data updates. Tick every 3 seconds and recompute age from `checkedAt`, never an incrementing counter. For the demonstration, Front Door begins live; at 45 seconds its facts become `stale`, its chip says “Needs a human · checked 45s ago”, and a polite inline nudge reads “Nothing has heard from Garden Camera since 11:02.” At 60 seconds Front Door is rechecked and returns to `live`, with “Re-checked just now.” All views update from the same store without reload. The age display updates locally, but routine timestamp ticks and poll results are not announced; meaningful state changes may be announced politely. With feed paused, every freshness line says “Feed paused · last checked 45s ago” using its actual last age. The decorative state-chip transition and service-index reorder last at most 200ms; the live need-order places stale services first and announces the move in visible text, e.g. “Front Door moved to the top — checked 45s ago.” The index can settle without rearranging keyboard focus.

Optimistic actions are explicit: `#simulate-change` shows “Locking…” across all three views, then the fixture result after ~900ms; `#disconnect` shows “Disconnecting Front Door…” before the entry leaves with a calm fade and the notice lands; Connect publish shows “Adding Notes Sync…” before its entry appears. Each settles visibly and keeps an error/recovery explanation if mock completion fails. Only the status chip, fact-row settle, need-order change, disconnect fade and connected tab’s 200ms settle are animated. Under `prefers-reduced-motion`, these become immediate swaps while the data tick continues.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
Zero services shows a small inline-SVG shelf outline, the line “Nothing is connected yet. Worlds will not guess.” and a Connect button. Zero providers is Local Weather’s zero-fact state and its fixture `emptyReason`; no reading is drawn. Quiet uses Media Shelf’s fixture label “Healthy”. Needs-you preserves Front Door’s label “Needs a human” and reason “A decision is required; the local app will not act on its own.” Stale names what is old and when it was checked. Unknown uses Garden Camera’s label “Unknown” and verbatim reason “The device stopped answering at the fixture's baseline; no source has answered since.” Unavailable is distinct from stale: Notes Sync’s provider can be unavailable while three local notes remain live. Disconnected says which service left and what remains. Connect includes loading, validation, failed safe-test, empty-preview and long-copy states with cause and recovery; loading is static and has a timeout/retry path. Every state has words as well as restrained semantic color.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr’s one integration reused across surfaces, Dashy’s in-place app access, Home Assistant cards’ shared state, and MCP ext-apps’ contained UI boundary. The need-ordered shelf visibly moves when a service needs attention; it is not a fixed register, map, cable patchbay or floating window collection. Worlds frames and composes; each service remains its owner.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `skill-minimalist-skill.md` supplies the flat editorial hierarchy and warm-monochrome palette; `ds-storytelling.md` supplies concise, product-specific voice and a restrained narrative accent. Use the minimalist canvas `#F7F6F3`, `#FFFFFF` only inside small app-frame interiors, structural border `1px solid #EAEAEA`, radius no greater than 8px, text `#111111` / `#2F3437`, and secondary `#787774`. Keep only Storytelling’s `#111827` for the small “from this app” fact-slip label; reject its large white surfaces, Inter/Abril Fatface pairing and saturated blue/purple/green/orange accents because they conflict with the selected minimalist binding and low-glare shell. Use minimalist system-native sans with an editorial serif only for the page heading; no external fonts. Keep flat surfaces, no gradients, no `rounded-full` containers, no shadows above 0.05 opacity, and no emoji; tabs and marks are inline SVG or text. Apply specific fixture copy, state coverage, native labelled controls, semantic order, 44px targets, visible focus, static loading, reduced-motion behavior, and Laws of UX grouping/proximity. Confirm final text pairs at WCAG AA before build; no token is permission to ship a failing contrast pair.

## 9. Signature element, hero thesis, reference lock.
Signature: the “from this app” tab is the only control that opens facts, making provenance a deliberate step rather than a caption. Its text, accessible name and source relationship remain present without animation. Four warmth moments: first run says “Nothing is connected yet. Worlds will not guess.”; Connect success says “Notes Sync is on the shelf. Three local notes are still live; the provider is not answering.” with a tiny SVG tab settling into the index over 200ms; the stale nudge is “Nothing has heard from Garden Camera since 11:02.”; state-change settle says “Front Door is clear. The back door is locked.” Each becomes a static swap under reduced motion, and none encodes status. The illustrated empty shelf is an inline SVG with no semantic/status content. Hero thesis: **“Every service keeps its own screen; every shared fact keeps its source.”** Reference lock: Homarr 2.0’s reusable integration mechanic and Apple Home’s accessory-to-home state relationship; borrow the relationship, not their styling.

## 10. Risks and UNKNOWNs.
Real Connect protocol, provider sandbox enforcement, app messaging, disconnect history retention and exact production freshness policy are UNKNOWN. The live schedule above is prototype behavior only. The fixture is synthetic; label every view MOCKUP and never imply a real reading. Verify contrast, 390px reflow without horizontal scroll, 44px targets, keyboard/focus behavior and reduced-motion treatment in the built artifact.

## 11. How it differs from C, and what it keeps
C uses a fixed owner register, a register-to-detail substitution on phone, and a permanently docked app/fact pair. v3604 keeps C’s real Worlds shell, independent service ownership, honest fixture states, owner fallback, and framed app, but breaks its fixed-register invariant: services sort by need and freshness, and the index visibly reorders when a live tick makes one stale. That changing priority makes this a service shelf organized around what deserves attention now, rather than a cabinet of stable places. On phone the initial route is the selected Front Door detail so the required disconnect is immediately available; Back still returns to the index. The source tab replaces C’s permanently docked fact card with a deliberate, keyboard-operable provenance step.

## 12. Desktop and mobile layouts
At 1440px, use the persistent left navigation, need-ordered service index and selected-service region split between owner frame and the fact slip opened by its source tab. Keep service state and `#disconnect` visible on the first screen. At 390px, open on Front Door detail (the only `Needs a human` service) with `#disconnect` visible on that first screen; Back returns to the index. The index row also offers disconnect. The same confirmation identifies Front Door and has a button labelled exactly “Disconnect”; confirming on detail returns to index with “Front Door left the shelf” visible and Home `attentionCount: 0`. `#add-service`, `#simulate-change`, `#live-toggle`, and the six Connect stepper buttons (“Back”, “Continue”, “Connect Notes Sync”) are real, named buttons at every width. Connect uses one-column screens on phone. The 3-second feed, 45-second stale transition, 60-second recheck, ~900ms action settles and 200ms reorder/connected-tab feedback follow §5; reduced motion removes those animations but never pauses data. Keep all targets at least 44px, respect safe areas and reflow at 200% zoom without sideways page scroll.
