## DESIGN.md for v1802

# v1802 — The glaze shelf (MOCKUP)

## 1. Metaphor in one line, and the main gesture.
Worlds is a studio shelf of glazed pots: each connected service is its own pot, with its own glaze, a small face that shows how it is doing, and a paper tag hanging from it that names the owner. The main gesture is **lift a pot's lid**: select a service and its owning app opens in a frame beside (desktop) or over (mobile) the shelf, with its tag directly under it. The prototype carries a visible MOCKUP label throughout.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
Start state: `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`, "Needs a human"). `#add-service` (header, both layouts) opens Connect for `notes-sync` (Notes Sync, `unavailable`); other unconnected fixture services appear in Discover but only Notes Sync is the scripted path. Six real `<button>` steps: Discover → Credential reference (reference only; a pasted secret is refused with "Worlds keeps a reference to the credential, never the secret"; validates on blur, input kept on error) → Safe test (idle/running/passed/failed; the first run fails with the fixture's "provider timed out" and offers "Try the test again", the second passes; no provider is called) → Preview (`sync.provider-reachable` unavailable, `sync.local-pending` 3 notes live, `sync.last-synced` stale) → Choose what to publish (one checkbox per fact id, plain sentence on what is shared) → Publish. Publishing puts a new pot on the shelf with a short settle animation and a "Notes Sync is on the shelf" line.

One in-memory store keyed by fact id feeds three views: Home (shelf and attention count), the service dock (app frame plus its tag), and Agent facts. `#simulate-change` applies `lock-back-door` to `frontdoor.back-door` from `crossViewExample`: Front Door becomes `healthy`, the fact reads `locked`, `attentionCount` becomes 0, and all three views change in one state update (optimistic at once, then a "settled" mark about a second later). It is a mock owner report; Worlds locks nothing. `#disconnect` is on the selected service's dock header and, on mobile, on the first-screen selected strip. It opens an inline confirmation naming the service, with a button labelled "Disconnect"; afterwards the pot is gone, a line says what is gone ("Media Shelf's facts and app frame are no longer here; Media still has its data"), and the rest keeps working.

## 3. Navigation between Worlds and a service (phone and desktop).
Four shell destinations persist: Home, Connect, Memory, Settings. Home has two views, Shelf and Agent facts. Desktop: left rail, shelf centre, dock right, the dock being part of Home rather than a route, so selection changes in place. Mobile has its own pattern: a bottom tab bar for the four destinations, and a pot opens as a full-height bottom sheet with an explicit Close button (focus moves to the sheet heading and returns to the pot). Memory shows what Worlds keeps from published facts; its contents beyond fixture facts are UNKNOWN and said so. Settings holds the live feed default (on), a "calmer motion" switch that follows `prefers-reduced-motion`, credential references (names only), and "Start over from the beginning" (empty state).

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The frame is a drawn, rounded, white inset (iframe/ext-app style) with the owner named in its top bar. The owner link sits permanently at the frame's bottom edge: Media Shelf "Open Media app" (`app://media`), Front Door "Open Home app" (`app://home`), Notes Sync "Open Memory app" (`app://memory`). The frame gets no Worlds credential by design; browser enforcement, sandbox flags and app messaging are UNKNOWN. When the embed fails (Settings has a "Pretend the app didn't load" demo switch), the frame becomes a kind sentence plus the owner link, while the tag, shell and Back/Close keep working. The shell always keeps nav, the live toggle, the tag and Disconnect. Approvals hand off to Project Home; other actions to the owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
The tag is the signature component and the facts model made visible: it appears on the shelf pot (short), under the dock frame (full) and as a row in Agent facts (full, tabular on desktop, stacked on mobile). Each shows source, observed time and freshness (recomputed from `checkedAt` against the live clock), "Agent can see", "Human can see" and "Who can act", as separate words. `frontdoor.back-door`: agent `read`, human `act`, reason "Locking the door changes the external system and is the person's decision." `frontdoor.guest-code-used`: agent `none` as a named, focusable disabled control carrying "Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who." `frontdoor.unlocked-for`: both read. Provider unreachable and local pending stay separate rows. The mock lock hands off to Project Home; Notes Sync "Check provider now" hands off to the owning Memory app.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
- First run / zero services: one empty pot, "Nothing on the shelf yet. Worlds will not invent readings," and the Add a service button; no readings anywhere.
- Quiet: Media Shelf, state word "Healthy", sleepy-content face.
- Needs-you: Front Door, "Needs a human", the fixture reason, alert-eyed face; it is the largest tile and first in reading order.
- Stale: facts with `stale` freshness say "Stale" in words and show age; the live feed occasionally moves Media Shelf to Stale, then recovers on the next check.
- Unknown: never blank; reads "Unknown" with a reason. Error: failed safe test, with cause, recovery action and preserved input. Loading: static skeleton pot, plus a "taking longer than expected" line after 15 s. Edge: long names and long reasons wrap; nothing clips.
- Disconnected: described above. Historical retention is UNKNOWN.
Every state shows a word and a face shape, never colour alone.

**Whimsy, in the details:** the pot faces are small inline SVGs, and the face changes with a blink. "Connected" is a lid that settles onto the new pot. Copy is kind and specific ("Front Door is waiting on you. Nothing else is."). Live ticks change "checked 2s ago" quietly. Reduced motion removes the blink, lid and tilt but keeps all data updates; `#live-toggle` ("Live: on/paused") is in the header, on by default.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Homarr: one integration drives the shelf, the dock and the agent view. Dashy: apps open in place. HA cards: literal state words and a shared subscription. MCP ext-apps: contained UI with host-owned permissions. Different: the shell owns the tag, so a service cannot restyle its own status, and nothing here is a dashboard of charts, only owned things with honest state.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Skill `gpt-tasteskill`, design system `ds-clay`. The skill is a marketing/GSAP landing skill, so I take its discipline and drop the rest. **Taken:** a deterministic seed to pick the variations instead of the first default (seed = 1802 mod options: hero "Artistic Asymmetry", component "inline pill in the heading", gapless bento shelf); the premium nav bar; a 2-3 line max heading on a wide container; the gapless grid (`grid-auto-flow: dense`, spans checked so the 12-column shelf has no void for 2, 3 and 7 pots); no meta-labels like "SECTION 01"; button text always high contrast; no emoji; no horizontal overflow. **Dropped:** GSAP and scroll pinning, picsum images, CDN, the marketing AIDA page. This is an app, with vanilla JS, no external assets, and inline SVG for any image. Fonts: Satoshi/Roobert are unavailable offline, so a system rounded-geometric stack with a mono for ids; no Inter. **Clay used:** cream `#faf9f7` canvas, oat borders `#dad4c8` (solid for live things, dashed for empty slots), 24px card radius, 12px controls, 8px spacing base, the three-layer clay shadow, weights 600/500/400, and swatch fills with black text only (Matcha 300 `#84e7a5` healthy, Lemon 400 `#f8cc65` needs-you, Ube 300 `#c1b0ff` stale/unknown; at most two swatches per view region). Hover/focus tilt is softened to -2deg with the hard `-4px 4px` shadow, no translateY jump, so targets do not run from the pointer; removed under reduced motion. Focus ring `#146ef5` 2px. Uppercase 12px labels only where they name something real (state words), never as numbering. Craft rules applied: state-coverage (five states), accessibility-baseline (44px, keyboard, contrast 4.5:1 checked on built pairs), animation-discipline (state-change motion only, under 300ms), anti-ai-slop, laws-of-ux (needs-you first).

## 9. Signature element, hero thesis, reference lock.
Signature: the **tag**, one component, three places, always showing owner, freshness, who sees and who acts. Hero thesis (2 lines, wide): "Every service in its own pot, with its owner's name on the tag." The pot-with-a-face is the hero shape, with the Front Door pot largest. Reference lock: Clay's hand-glazed craft surfaces (mechanics: oat borders, hard offset shadow) and Apple Home's accessory-state clarity (mechanic: one state word plus a short reason). No palettes are copied from either.

## 10. Risks and UNKNOWNs.
Embed enforcement, Connect API, retention and Memory contents are UNKNOWN. Faces could read as decoration, so each carries the state word beside it. The Clay swatches are loud: contrast on the built fills must be measured, and the fills may be dropped to a thin band if a pair fails. Fixture data is synthetic and a MOCKUP, never a real reading. Simulated staleness is clearly labelled as the demo feed.

## 11. How it differs from C, and what it keeps.
Keeps: the persistent shell (Home, Connect, Memory, Settings), owner-labelled services, the owning app docked beside its shared fact card, six-step Connect for Notes Sync with the same preview ids, fixture wording and fallback links verbatim, one fact store, honest named-disabled permissions, the same checker ids. Differs: C is a flat, fixed-order register of bays with a static bezel and a no-motion signature; v1802 is a warm, gapless tile shelf whose tile size follows need (Front Door first and largest), with a living face per service and a swing-and-settle on state change. C's fact card is a panel; here it is a reusable tag that is the same object on Home, in the dock and in Agent facts. C's palette is white with a restrained orange edge; this one is cream, oat and named swatches. C's mobile is a one-column list with Back; this has a bottom tab bar and a bottom sheet. C used no live feed; this one ticks every 4 s. It borrows C's honesty and structure, not its look.

## 12. Desktop and mobile layouts.
**Desktop, 1440px:** a 232px left rail (wordmark, four destinations, MOCKUP badge). Top bar across the main area holds `#live-toggle`, `#simulate-change` and `#add-service`. Below, a 12-column gapless shelf (about 600px): Front Door spans 7 columns by 2 rows, Media Shelf 5 by 1, with the empty "add a pot" slot filling the gap, and Notes Sync after it makes 5 by 1. At the right, a 440px dock (the selected service, Front Door by default) shows the service name and state word, **`#disconnect` on the first screen**, the app frame, its owner link, and its tag. A Shelf / Agent facts switch swaps the centre area for the facts table, with the dock staying put.
**Tablet, 768px:** the rail shrinks to an icon rail with visible text labels under 56px icons; the shelf is two columns; the dock slides over from the right as a 420px panel.
**Mobile, 390px:** reading order is top bar (MOCKUP, Live toggle), a compact demo row (Simulate change, Add a service), the **selected-service strip** with state word, one-line reason, **`#disconnect`** and Open, then the shelf as a single column (needs-you first), with a 64px bottom tab bar for the four destinations. A pot opens as a bottom sheet (frame, owner link, tag), and Agent facts stack each tag as a card. No sideways scroll, 44px minimum targets, and the sheet's content scrolls inside it.
