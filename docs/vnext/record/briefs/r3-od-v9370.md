## DESIGN.md

# v9370: The service workbench

## 1. Metaphor and main gesture

Worlds is a warm, practical workbench where a short, changing work queue brings the next useful service into reach. Select a service to open its owner app and the shared facts, then use the labeled hand-off seam to inspect or request an action. Read this as a daily personal application for one person: calm structure, small crafted warmth, and no workshop props that behave like real hardware. Design Read: a reactive personal product shell for one person, with calm, warm utility, leaning toward the assigned skeuomorphic design language. The skill's closest dial signal is trust-first/accessibility-critical; variance 4, motion 2, density 4. Motion is 2 rather than the skill's 6 baseline because this is a long-use, low-stimulation product surface: only short state-confirmation movement is allowed.

## 2. Integration model and shared state

The checker-facing native buttons use the exact DOM ids `add-service`, `disconnect`, `simulate-change`, and `live-toggle` (referenced below as `#add-service`, `#disconnect`, `#simulate-change`, and `#live-toggle`).

Start with exactly two connected fixture services: `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`). Select Front Door on Home initially. `studio-printer` is an available fixture service in Discover and can be connected as the third service, satisfying the two-service start and the three-service composition requirement without inventing a service. A live work queue sorts connected services by `needs_attention`, `unavailable`, `unknown`, `stale`, `not_configured`, then `healthy`; ties keep the local station order. Selection opens one station in place and temporarily replaces the queue. Returning restores its prior order. Settings keeps the stable registration order. The queue is a decision surface, not a shelf; live state changes may reorder it.

`#add-service` opens the real six-step Connect flow: Discover → Credential reference → Safe test → Preview → Choose what to publish → Publish. Discover lists only remaining fixture candidates by exact id, name, and state: Studio Printer (`studio-printer`, `unavailable`), Notes Sync (`notes-sync`, `unavailable`), Nightly Backup (`nightly-backup`, `stale`), Garden Camera (`garden-camera`, `unknown`), and Local Weather (`local-weather`, `not_configured`). Step buttons are labeled “Choose [service name],” “Save reference and continue,” “Run safe test,” “Review offered facts,” “Choose facts to publish,” and “Publish [service name]”; Back buttons name the destination step. The reference input accepts a reference, rejects secret-shaped values with “Worlds stores a credential reference, never the secret,” and visibly supports dirty, submitted-pending, and validate-on-blur states. Safe test has run, running, passed, and failed states; failure names the error and offers Retry or Back. Notes Sync test uses its fixture timeout; Studio Printer test reports its fixture rejection. Each may be published only with its fixture state intact. Preview is service-specific and shows that service's fixture fact IDs, literal values, and states; Notes Sync preview includes `sync.provider-reachable` (`unavailable`), `sync.local-pending` (3 notes, `live`), and `sync.last-synced` (`stale`). Each fact is independently selectable for publication. Publish adds the service and selected fact IDs, then lands on that station. All step controls are native buttons with clear labels. No provider call occurs.

One in-memory store keyed by fixture fact ID feeds Home, the service station, Memory, and Agent facts. A labeled “Agent facts” link from every fact view opens a dedicated view over these same records; it is not a second store. `#simulate-change` applies only the fixture's `lock-back-door` example: `frontdoor.back-door` becomes `locked`, Front Door becomes `healthy`, and attention count becomes 0 in one state update across Home, Front Door, and Agent facts. This is a mock review/handoff, not a Worlds command to the lock. A governed action crosses the seam: it checks the fact permission, shows an immediate “Checking permission…” receipt, then settles in words as “Hand off to Project Home” or “Not allowed: [fixture reason].” It never decides or changes the external system.

The Studio Printer row shows the exact failure `job rejected: no media loaded`, and a human-only `Retry last job` control. Activation changes the row immediately to “Retry requested…” and then, after 900ms, settles to “MOCKUP only: no retry was sent.” The printer remains `unavailable` with the same fixture error and the fixture attempt count of 1. This visible optimistic-to-settled interaction does not claim an external operation or invent a successful job. Notes Sync offers its fixture's human-only “Check provider now” action; its last error is `provider timed out`, while “Local notes still work” and the 3 pending notes remain visible.

## 3. Worlds navigation and return behavior

Desktop has a persistent 224px left rail for Home, Connect, Memory, and Settings. Home starts as a broad queue-led canvas with the selected station preview and its first-screen actions; selecting a service replaces the queue with its workspace. The active workspace gives the owner app 60% of available width and shared facts 40%, joined by the hand-off seam. Back restores queue order, selection, scroll offset, and focus. Connect likewise returns to the invoking service row with its scroll and focus restored.

Mobile has a persistent four-item bottom navigation. Home is a queue of full-width decision rows; selecting one opens a full-screen station page with a labeled Back button, not a squeezed desktop pane. Back restores the same row, scroll position, and focus. The detail has compact facts first and full provenance behind “Show all facts”; a sticky action bar sits immediately above the bottom navigation. On mobile the desktop queue preview and split app/facts columns are dropped on purpose; state words, ownership, fallback, provenance access, permissions, and all actions remain available. Settings includes a live-feed preference and motion comfort.

## 4. Embedded app and hand-off seam

The owner app sits in a bounded, clearly titled frame with a plain fallback link always visible: Media Shelf, “Open Media app” (`app://media`); Front Door, “Open Home app” (`app://home`); Studio Printer, “Open Studio printers” (`app://studio/printers`); Nightly Backup, “Open Backup settings” (`app://settings/backups`); Garden Camera, “Open Home cameras” (`app://home/cameras`); Notes Sync, “Open Memory app” (`app://memory`); Local Weather, “Open provider settings” (`app://settings/providers`). The fixture's fallback is the route when the embedded app is unavailable. If loading fails, say so plainly and keep the facts and fallback visible. No credential value enters the frame. Actual embed protocol, browser-enforced isolation, app messaging, and history retention after disconnect remain UNKNOWN.

The seam is a functional hand-off channel, not a decorative divider. Its fixed labels are “Owner app” and “Worlds shared facts”; its action receipt has visible pending, handed-off, and denied words. Approval actions route to Project Home; service actions otherwise route to the owning app. Permission controls precede hand-off. The shell remains around the owner frame.

## 5. Shared facts, permissions, and live feed

Every full fact row shows label, literal value or explicit `unknown`/`unavailable`, source, checked time, recomputed age, freshness state, Agent can see, Human can see, and Who can act. Recompute age from `checkedAt` against the fixture's `generatedAt` plus simulated elapsed time; never trust stored `ageSeconds`. Blank/null values render as the fixture's explicit state and reason, never as empty space or a last-known value. Media Shelf rows are `media.items` = 1284 items, `media.indexing` = 0 items, and `media.played-recently` = 12 items, all `live`. Front Door's `frontdoor.unlocked-for` = 47 minutes, `live`. `frontdoor.back-door` is agent `read`, human `act`, with the exact reason “Locking the door changes the external system and is the person's decision.” `frontdoor.guest-code-used` is human `read`, agent `none`; show a named disabled, focusable agent control and its exact reason: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” The value `visitor-3` is never exposed to the agent view. Studio Printer rows are `printer.status` = `error`, `unavailable`; `printer.queue` = 1 job, `live`; and `printer.last-error-code` = `E-MEDIA-02`, `live`. Garden Camera's `camera.last-frame` and `camera.reachability` render `unknown`, source `none`, with its fixture reason: “The device stopped answering at the fixture's baseline; no source has answered since.” `camera.human-detected-today` is also `unknown` and has an independently named disabled agent permission with the exact fixture reason: “The agent may not assert a detection while the source is unknown.” Other fact permissions remain independent.

The live feed starts ON. `#live-toggle` pauses/resumes age updates. A tick runs every 5 seconds; age and “checked … ago” recompute from the parsed checked time in every visible view without reload. At simulated age 60 seconds, Media Shelf and each of its three fact freshness states change from `healthy`/`live` to `stale` together; Home, station, and Agent facts update in one store transaction and the queue resorts. “Re-check Media Shelf” gives immediate “Checking…” feedback, then returns the service and facts to the fixture baseline `healthy`/`live` and resets simulated checked time, across those same views. No other service drops off by timer. The feed changes data even with reduced motion; reduced motion removes travel and transition effects. Routine ticks are not announced; one meaningful state change may be announced politely, no more than approximately once per 30 seconds.

## 6. Screens and states

**First run / empty.** Zero connected services has a clear “Connect a service” action into Discover, with no provider facts invented and a local Worlds/Memory baseline. After Publish, land on the created service. Disconnecting the last station returns Home to the same invitation; shell and Memory remain usable, history retention is UNKNOWN. `local-weather` is `not_configured` with zero facts and its exact empty reason, never a placeholder reading.

**Memory.** Memory is a Worlds destination, not just Notes Sync's owner app. It filters the shared store to facts whose owner is Memory plus `sync.*` facts, with the same source, freshness, and permissions as their service view. If Notes Sync is connected, show “3 notes waiting to upload” while `sync.local-pending` is present and equals 3, alongside the fixture's last successful sync timestamp, even while the provider is unavailable; link to Notes Sync. If it is not connected, show a Connect invitation and no inferred count.

**Settings.** One settings screen has four named groups: (1) Live feed, ON by default, with the fixed five-second interval and pause effect; (2) Motion comfort, explaining that reduced motion removes travel/transition effects but not data updates and OS preference overrides; (3) What the agent may see, listing every connected fact's exact agent permission and fixture reason, including both disabled guest-identity and camera-detection controls; (4) Data and demo, with the always-visible MOCKUP notice and a “Start over” button that returns to first run after confirmation. These groups change no provider fact values.

**Quiet.** Media Shelf says “Library reachable and indexing is current.” Its service and facts say `healthy` and `live` explicitly.

**Needs you.** Front Door says “Back door has been unlocked for longer than the person's usual window.” Show the exact attention reason: “A decision is required; the local app will not act on its own.”

**Unavailable/error.** Studio Printer is unavailable with the literal last error and human retry. Notes Sync's provider is unavailable while its three local pending notes remain `live`; its last successful sync is `stale`. A failed Notes Sync test states `provider timed out`; local notes still work. A failed test or retry states what failed and what still works, with retry/back or owner-app fallback.

**Stale / unknown.** Nightly Backup says “Last successful run is older than the configured daily window.” Show `backup.last-success` as `2026-10-09T06:00:00Z`, `backup.last-attempt` as `failed: destination unreachable`, and `backup.size` as `4.2 GB`, each `stale`. Garden Camera says “Disconnected since a restart; the local app has no current observation and will not invent one,” plus its exact unknown reason and source `none`. Never imply unknown is healthy. Local Weather's empty reason is “No provider configured, so there are no facts to show. The concept must render the empty state honestly rather than a placeholder value.”

**Disconnected.** Confirmation names the selected service and requires a button labelled “Disconnect”; it explains that the station and embedded app disappear here. Then focus moves to the next queue row, or Home's empty invitation if none remain. History retention is UNKNOWN.

**Warmth cues.** Each service has a tiny inline SVG station glyph that is decorative and never carries state. Each gets an engraved state plate: the literal state word is the truth; a flat edge means healthy/live, a hairline edge marks needs-attention/stale, and a shallow inset edge marks unavailable/unknown/not-configured. `#simulate-change` settles Front Door's plate from “Needs a human” to “Healthy” in a single 150ms ease; the sprout mark settles into the plate. After Publish, show “All set; Notes Sync has a place here.” The disabled guest identity row has the quiet hint “The agent can't see this one.” On initial load, show “Checked just now” only when the simulated checked-time calculation supports it. Under reduced motion, plate and label change without travel. MOCKUP is always visible; loading is static, no shimmer or looping motion.

## 7. Borrowed mechanics and deliberate difference

Borrow Homarr's one integration feeding multiple surfaces, Dashy's in-place app opening, Home Assistant cards' readable state, and MCP ext-apps' contained app boundary. The distinct mechanism is a priority work queue that selection replaces, plus a permission-checking hand-off seam that produces a worded receipt. The changing queue prioritizes current need; fixed registration order remains in Settings and breaks queue ties. This is not a cabinet register, widget wall, map, or repeated bay grid; the object that organizes the experience is the next decision and the safe boundary between owner action and shared fact.

## 8. OpenDesign starting point and craft choices

Starting point: `skill-taste-skill.md` (`design-taste-frontend`) and `ds-skeumorphism.md`. The skill explicitly excludes dense product UI and multi-step forms, so its brief-first inference and anti-default discipline apply; the v2 product requirements and Worlds contracts govern structure and forms. The design system positively supplies the physical state plate: shallow edge treatments make state legible without color, while words carry the state truth. Use its `#111827` text and `#FA3C00` accent only as a non-text marker after adjacent contrast review; no status depends on orange. Confine `#FFFFFF` to small owner-frame interiors; use native CSS `Canvas`/`CanvasText` system colors for the large page field so the browser and OS supply a neutral field without adding a palette value or painting a large pure-white surface. Use the supplied spacing scale 4/8/12/16/24/32 and type scale 12/14/16/20/24/32. Since external fonts are prohibited, substitute local system sans for Roboto, local display sans for Germania One, and system monospace for JetBrains Mono; keep a coherent fallback chain. Use one shape system and no added palette colors, textures, gradients, fake hardware controls, external images, or fonts. Apply the anti-slop rule against generic colored-left-border cards, color discipline, semantic grouping, explicit states, static loading, named errors, labeled controls, visible 2px focus, 44px targets, keyboard access, skip link, landmarks, 390px reflow, 200% zoom, safe areas, and reduced-motion rules. Check text pairs at 4.5:1 and components/focus at 3:1 in implementation; the orange accent loses any use that fails. Small local inline SVG glyphs and sprout are decorative, with no state meaning.

## 9. Signature, thesis, and reference lock

Signature element: the labeled hand-off seam that checks permission and returns a plain-language receipt between an owner app and Worlds' shared facts. Hero thesis: “Every service keeps its own hands; Worlds keeps the shared picture.” Reference lock: Homarr 2.0's one integration reused across surfaces, and MCP ext-apps' host-mediated app boundary. Borrow mechanics only, not their visual language.

## 10. Risks and UNKNOWNs

Discover protocol, credential-reference format, real provider test behavior, embed isolation, service messaging, Project Home hand-off protocol, whether fixture permissions map to a production authorization policy, and disconnect history behavior are UNKNOWN. The app and all events are demonstrative; Worlds does not operate the lock or printer. The fixture is the only data source; transient UI states do not add readings or mutate fixture values. Label the prototype MOCKUP and never imply real readings.

## 11. How this differs from C, and what it keeps

C files fixed owner bays and opens one selected bay beside a fact card; this design replaces that mechanism with a need-sorted work queue that temporarily gives way to the selected workspace. The seam now checks permission and returns a receipt, rather than marking a visual join. The queue reorders as shared state changes, while Settings preserves registration order. It keeps C's Home / Connect / Memory / Settings shell, explicit ownership, docked owning app, shared facts, honest state words, Connect lifecycle, and focus on one service at a time. Warmth is woven into state plates, restrained settling feedback, service glyphs, and humane copy instead of changing the shell structure.

## 12. First-class desktop and mobile layouts

**Desktop, 1440px.** Use a persistent 224px navigation rail and a flexible main canvas. Home places a compact, ranked queue across the upper canvas (not a 300px fixed register), with the selected Front Door workspace below: app frame at 60%, shared facts at 40%, joined by the labeled seam. At least the service title, state plate, `#disconnect`, `#simulate-change`, `#live-toggle`, `#add-service`, and MOCKUP label appear in first-screen context. Selecting a queue row replaces the queue region with that service workspace; Back restores the queue. On a service page, owner app and facts share the first screen, and `#disconnect` is visible without opening a panel. Connect flow occupies the main canvas with named steps and back/forward buttons.

**Mobile, 390px.** Use the four-item bottom nav and a full-width queue with generous decision rows. Service detail is a separate full-screen view with sticky actions above the bottom nav. Its semantic and visual reading order is:

1. Back, service title, literal state plate, and owner summary.
2. Bounded owner app frame with its fallback link.
3. Compact facts strip with two or three priority rows, each showing label, value, and state word.
4. “Show all facts” disclosure with source, checked time, computed age, freshness, Agent can see, Human can see, and Who can act.
5. Sticky actions: `#disconnect`, `#simulate-change` when applicable, `#live-toggle`, and the worded seam receipt.

The first-screen Home service preview exposes `#disconnect` for initially selected Front Door. `#add-service` is prominent on Home and Connect. Service actions stay in the sticky bar, not a secondary panel. Long values wrap, no sideways scrolling at 390px or 200% zoom, targets are at least 44px, safe-area insets are respected, focus follows source order, and the MOCKUP label remains visible. Desktop's queue preview and two-column split are intentionally absent on mobile; none of the state, permission, fallback, or action information is removed.

### Critique fixes

- Replaced C's fixed station register with a need-sorted, reactive queue that gives way to the selected workspace; Settings alone preserves registration order.
- Kept the v2 requirement of exactly two connected services at startup despite the critique's recommendation to preload Studio Printer; it is the explicitly named third fixture service in Discover.
- Made the seam a permission-checking hand-off with pending, handed-off, and denied receipts.
- Added Studio Printer's fixture-backed unavailable error and a visible optimistic retry request that settles by stating the mock sent nothing; no unsupported provider result is invented. Pinned Media Shelf's stale transition and re-check interval, and bound Garden Camera to the explicit unknown case.
- Recomputed age from checked times and specified atomic Home, station, and Agent facts updates for timer and fixture action changes.
- Defined Memory, a four-row Settings screen, first-run/last-disconnect routes, and scroll/focus restoration.
- Designed separate 1440px and 390px information layouts, including mobile compact facts, disclosure, and sticky actions.
- Bound skeuomorphism to state plates and warm moments; named tokens/scales and local font substitutions, then derived the dials from the trust-first brief.
