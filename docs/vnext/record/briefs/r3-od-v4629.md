# v4629 — Windowsill

MOCKUP. Synthetic fixture data only (`docs/vnext/fixture/fixture.json`); nothing here is a real reading. Single self-contained HTML later; this file pins decisions first. Revised after critique (see "Critique fixes" at the end).

## 1. Metaphor in one line, and the main gesture.
Worlds is a sunny windowsill of paper-wrapped seed packets: one labelled packet per service, each owned by its app, each with a tiny drawn sprout whose posture says how it is doing (the words say it first). The main gesture is **pick a packet, and its app opens in a clipped frame with the fact slip tucked beside it**. Warmth is in the sprouts and the copy; the structure stays a calm app.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
Start: `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`, "Needs a human"). `#add-service` starts Connect for `notes-sync` in five real `<button>` steps: Discover → Credential reference (reference only; a pasted secret is refused with "Worlds keeps a reference, never the secret") → Safe test (idle/running/failed/passed; first run fails with the fixture error "provider timed out" and offers the fixture retry label "Check provider now") → Preview (`sync.provider-reachable` `unavailable`, `sync.local-pending` 3 notes `live`, `sync.last-synced` `stale`) → Publish (a checkbox per fact). Success is the "connected" moment: the new packet's seed sprouts (one 400ms transform, static under reduced motion) and the line "Notes Sync is on your sill." Notes Sync arrives in its fixture state `unavailable` (see "drop-off" in §6): connecting does not make it healthy. One in-memory store keyed by fact id feeds Home, the packet, the fact slip and Agent facts. No provider is called.

**Governed action = handoff, never a Worlds decision.** `#simulate-change` is the control on the Front Door slip/dock, labelled "Lock in Home", with the owner and `app://home` beside it and the verbatim fixture reason "Locking the door changes the external system and is the person's decision." Flow:
1. Press → the control becomes "Awaiting Project Home" (mock; line: "Worlds does not act; this belongs to Home"). The framed Home app shows its own "Locking…" step. `frontdoor.back-door` still reads `unlocked`. About 700ms.
2. Settle (the build must keep this at or under 800ms and set `data-settled="true"` on the result region) → ONE store write applies `crossViewExample`: `frontdoor.back-door` → `locked`, Front Door → `healthy`, `attentionCount` → 0, across Home, the packet/slip and Agent facts at once. A polite `role="status"` note: "Home locked the back door. Worlds recorded it. Mock record, not a Worlds action." Framing everywhere: **Home acted; Worlds recorded.**
3. Failure branch: see §6 "Settle failed".
`#disconnect` is on the first screen for the selected service (Front Door at first load), opens a confirm naming it, and its confirming button reads "Disconnect".

## 3. Navigation between Worlds and a service (phone and desktop).
Four persistent destinations: **Home** (the sill; has the tabs "Sill" and "Agent facts"), **Connect**, **Memory**, **Settings**. Agent facts is a tab of Home only; each service's fact slip shows the same records for that service (a slice, not a second destination). Memory is its own screen (§5b). Desktop: left rail. Phone: bottom tab bar, and a selected service opens as a full-height sheet with explicit Back; focus goes to the sheet heading and returns to the invoking packet. Source order: nav, main, facts. Every destination, tab, packet and control is reachable by keyboard with a 3px focus ring.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The owning app is drawn as a framed window "clipped" to the packet, titled with its owner. Fallback sits at the frame edge, verbatim from the fixture: Media Shelf "Open Media app" (`app://media`), Front Door "Open Home app" (`app://home`), Notes Sync "Open Memory app" (`app://memory`); links are `app://` only. The frame is meant to carry no Worlds credential; browser-enforced sandbox flags and messaging are UNKNOWN. If it cannot load, the packet, slip, status and Back stay, and the failure and owner link are shown. Approvals hand off to Project Home; other actions to the owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Fact slip and Agent facts read the same records. Columns: source, checked time (recomputed live, §6), freshness word, Agent can see, Human can see, Who can act. A service's **state word** (fixture `state`/`stateLabel`) and a fact's **freshness word** (fixture fact `state`) are two separate labelled fields and never merged: Front Door can read "Needs a human" and, beside one fact, "Stale". The service word leads on packets and Home; freshness appears on slip/Agent rows and as a small "1 fact stale" line on the packet, which never changes the attention count. `frontdoor.back-door`: agent `read`, human `act` ("Locking the door changes the external system and is the person's decision."). `frontdoor.guest-code-used`: agent `none` is a named, focusable, disabled control with its exact reason ("Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who."). `frontdoor.unlocked-for`: both `read`. Provider failure and local data stay separate records (`sync.provider-reachable` `unavailable` beside `sync.local-pending` `live`).

### 5b. Memory and Settings (designed screens)
**Memory** is a separate screen, not the agent-facts view. It is the local-first baseline: "What Worlds holds on this device, with no provider." Content: (a) the list of fact records whose source is `local`, grouped by owner, each with value, checked time, freshness word and who can see/act (no invented notes; for Notes Sync only the count "3 notes waiting to upload", `sync.local-pending`, `live`); (b) the line "These keep working with zero providers"; (c) the owner link "Open Memory app" (`app://memory`). States: first run (zero services) → "Nothing remembered yet" with a bare-pot sprout and an Add service button; quiet → the list; needs-you → a row carrying "Needs a human" for Front Door; stale/unknown → rows show "Stale" / "Unknown" with reason; error → if the list cannot render, cause + "Reload list" + owner link; disconnected → a disconnected service's rows are gone with "Front Door is no longer connected; its facts are gone from Memory." Retention is UNKNOWN.
**Settings** (sensible defaults, all labelled controls, keyboard reachable): (1) About: "Worlds vNext — MOCKUP", fixture version `1`, "Synthetic data only". (2) Connected services: each with owner app, state word, and a Disconnect row (same confirm). (3) Live feed: toggle, default ON (the same state as `#live-toggle`), tick every 4s. (4) Motion: "Follow my device" (default) / "Always calm"; the line "Calm stops animation, not data." (5) Demo switches: "Make the next handoff fail" (default off) and "Make the Home frame fail to load" (default off), so error paths can be seen. (6) Data and disconnect history: "UNKNOWN: what is kept after a disconnect has not been decided." (7) Local-first: "With zero services and zero providers, Worlds, Memory and Settings still open and show nothing invented." States: first run → services list says "No services connected"; quiet/needs-you → list with state words; stale/unknown → state word with reason; error → a failed toggle write reverts with cause; disconnected → list updates in the same write.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
- First run (zero services): an empty sill with one bare pot, "Nothing planted yet", and an Add service button; no invented readings.
- Quiet: Media Shelf, "Healthy". Needs-you: Front Door, "Needs a human" plus its fixture reason.
- **Live feed (derived, not a counter).** A simulated clock starts at the fixture `generatedAt` and advances with real time; every 4s tick it recomputes each fact's age as `clock − checkedAt` (never the fixture `ageSeconds`) and re-renders "checked 2s ago" → "12s ago" ("1m 5s ago" past 60s). Only facts whose fixture `state` is `live` with `source` `local` or `external` age. Facts with `source: "none"` or a non-live baseline do not drift: `nightly-backup`/`notes-sync` stale facts stay `stale` at their fixture time; `garden-camera` stays `Unknown`; `sync.provider-reachable` stays `unavailable`; `local-weather` stays `Not configured`. A simulated local heartbeat re-checks live local facts every 20s (updating `checkedAt` only) so a healthy service does not go stale by default. One scripted event: the heartbeat is skipped for `media.played-recently`, so about 17s after load that single fact crosses the 45s threshold and its freshness word becomes "Stale" (sprout on Media Shelf gets a small drooping leaf; the service word stays "Healthy"; slip says "1 fact stale"). This is announced once, politely. **Check now** (on a stale fact or in the slip) is a mock *human* action: it re-observes the fact, `role="status"` announcement "Checked just now (mock)", no focus move, and the line "Mock: no provider was called." No agent control resets it.
- Unknown: never blank; reads "Unknown" with the reason (`unknownReason`, or "No source has answered").
- **Settle failed (optimistic rollback).** Every optimistic action shows an optimistic value ("Locking…", "Checking…"), then settles. On failure: the value rolls back to the last known value, an inline cause appears with the fixture words where they exist, the control is re-offered with its original label (input and selections preserved), announced via `role="status"` with no focus jump. Examples: the "Lock in Home" handoff with the demo switch on → rolls back to `unlocked`, "Home did not answer. Nothing was changed." with "Lock in Home" and "Open Home app" offered. "Check provider now" on Notes Sync → "Checking…" → rolls back to `unavailable`, cause "provider timed out", attempts count rises (2 → 3), `sync.local-pending` stays `live`.
- **Drop-off (a connected service stops answering).** Notes Sync is the drop-off case, reusing the fixture: its provider fact is `unavailable`, state word "Unavailable", sprout bent with a small break mark, reason "The sync provider did not answer its last two checks. Local notes still work; retry is offered." It shows "Check provider now" (human only) and "Open Memory app". In the same store write it counts toward Home's "needs a look" line and updates its Agent facts rows; Home, Memory and Settings stay usable.
- Other errors: safe-test failure and embed-load failure each give cause and a next step, and keep input.
- Disconnected: the packet is removed, the sill closes up, and a line says "Front Door is no longer connected; its facts are gone from Home and Agent facts." Everything else keeps working. Retention after disconnect is UNKNOWN.
- Feed: ON by default; `#live-toggle` shows "Live: on / paused" and a "Paused" word beside the clock. Pausing stops ticks, heartbeat and the scripted event. Reduced motion stops animation, not data.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Homarr: one integration feeds the UI and the assistant. Dashy: app opens in place. HA cards: literal state words. MCP ext-apps: contained UI under a host boundary. Different: no map, routes or topology; independent owners in a flat list, joined only by the shared fact store.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
**Roll of the soft-skill variance engine:** Vibe = **Soft Structuralism** (white ground, airy components, soft diffused depth); Layout = **Asymmetrical Bento**. Applied: the sill is a bento grid on desktop: the needs-you packet (Front Door) is a double-width, double-height cell, quiet packets are single cells, and the bare-pot `#add-service` is a single cell. The page itself is three asymmetric columns (rail ~240px, fluid sill, ~400px dock), not an even three-column grid. Mobile collapse is the skill's own rule and is the 390px basis: `grid-cols-1`, all spans reset to 1, `w-full`, `px-4`/`py-8`-scale padding, `min-height:100dvh` (never `100vh`), no rotation or overlap.
**Kept from the skill** (they work in a daily app): double bezel (outer tray with hairline ring and padding, inner core, concentric radii, e.g. 24px outer / 18px inner) for packets and the frame; pill buttons (the nested trailing-icon circle only on the one primary CTA); custom `cubic-bezier(0.32,0.72,0,1)` at 150–400ms; transform/opacity-only motion; blur only on the fixed phone tab bar and sheet scrim, never on scrolling content; soft diffused shadows (`0 12px 32px -16px rgba(17,24,39,0.12)`); thin-line custom inline-SVG icons (about 1.25px stroke), not thick stock sets.
**Dropped as marketing-only**: macro-whitespace (`py-24`–`py-40`; spacing stays on the ds-paper 4/8/12/16/24/32 scale), eyebrow tags, scroll-blur entrance reveals, the floating glass-island nav and full-screen menu overlay, magnetic hover, grain overlay, Ethereal Glass/dark archetypes. This removes the earlier contradiction: macro-whitespace is no longer claimed.
**Borders:** the skill bans generic 1px grey borders; packets use the tray ring and diffused shadow. Anything that identifies a control (inputs, buttons, focus) keeps a boundary at 3:1 or better against its ground.
**Fonts:** Roboto/Montserrat (ds-paper) and Inter/Helvetica/Arial (skill ban list) conflict with the no-external-fonts rule, so headings use `ui-serif, Georgia, serif` and UI uses `system-ui, sans-serif`.
**From `ds-paper`:** tokens `#111111` primary, `#111827` text, `#FFFFFF` surface, spacing 4/8/12/16/24/32, type 14/16/18/24/32/40. **The accent is Primary `#111111`** (it replaces dropped Secondary `#8B5CF6`, which is on the anti-slop indigo list). Its two permitted uses per screen: (1) the single filled pill CTA (e.g. "Add service", Continue, Disconnect-confirm), (2) the 2px selection outline on the selected packet. Success `#16A34A`, warning `#D97706`, danger `#DC2626` appear only as small marks beside a state word (contrast checked on built pairs; failures fall back to `#111827`). **Paper identity is a decision, not an omission:** it is carried by hairlines, concentric radii, the packet's drawn folded top edge and system serif headings; grain/texture is deliberately omitted because ds-paper's own anti-patterns forbid decoration that reduces readability and the skill restricts grain to fixed pseudo-elements.
**Also applied:** state-coverage (five states per surface, each error with cause, recovery, kept input, polite announcement), animation-discipline (≥150ms, motion only for change of state), accessibility-baseline, no emoji icons, no lorem, no invented metrics.

## 9. Signature element, hero thesis, reference lock.
Signature: the seed packet with its drawn inline-SVG sprout, always paired with a state word. Postures: upright (`healthy`/`live`), flagged (`needs_attention`), drooping leaf (`stale`), bent with break mark (`unavailable`), bare soil (`unknown`, `not_configured`, empty sill), sprouting (connect). Hero thesis: "Every service gets a packet, and every packet tells the truth." Reference lock: Apple Home's accessory-to-room status handoff (mechanics) and a Muji-style labelled stationery layout (labels and hairlines only).

## 10. Risks and UNKNOWNs.
Embed support and isolation, the Connect API and its real lifecycle, and disconnect history are UNKNOWN. The sprout cute factor could outrun the words, so words lead and the sprout never carries status alone. Live ticks could be noisy for screen readers, so only state changes are announced, politely. White-on-white relies on hairline contrast of 3:1 for controls, to be measured. The 700ms handoff delay could trip an automated checker; mitigated by the 800ms cap and `data-settled`. Fixture is synthetic; heartbeats and the scripted stale event are simulated and labelled as such.

## 11. How it differs from C, and what it keeps
Keeps: the persistent Home / Connect / Memory / Settings shell, the app docked beside the shared fact card, owner and fallback always visible, the Connect story for Notes Sync, the exact permission rows, and honest states. Changes: C's static cabinet bezel becomes a warm packet-and-sprout object with a drawn character per state; C is explicitly motionless, while this one is live (tick, derived staleness, optimistic settle with rollback, connect sprout) and calm under reduced motion; the selected packet and Disconnect live on the first screen, not behind a register; copy is kind and specific ("Nothing planted yet"); the fact slip clips to the frame as a paper note rather than a fixed card; the governed action is shown as a visible handoff to Home; and the mobile layout is its own design.

## 12. Desktop and mobile layouts
**Desktop (1440px):** three columns. Left rail (Home, Connect, Memory, Settings, the MOCKUP label, and `#live-toggle` with the live clock). Centre: the sill as a bento grid of packets (Home summary on top: "1 needs you" and the quiet count; Home tabs "Sill" / "Agent facts"; `#add-service` as a bare-pot packet). Right, the selected-service dock: header with name, state word and `#disconnect`, then the framed owning app with the owner fallback link, then the fact slip, then `#simulate-change` ("Lock in Home", Front Door only). Memory and Settings take the centre and right columns as one screen (two-column Settings sections). Hover shows a lift, focus a 3px ring.
**Mobile (390px):** one column, own reading order: status line and clock with `#live-toggle`, "needs you" first, then the selected service card with its sprout, state word and `#disconnect`, then the list of other packets, then `#add-service` as a full-width button. Bottom tab bar (four 44px+ targets). Tapping a packet opens a sheet: heading, state, fact slip (facts before the app because it reads faster), framed app, owner link, Back. `#simulate-change` sits in a "Try it" row under the selected card. Connect steps are full-screen, one at a time, sticky Continue above the tab bar. Memory and Settings are single-column stacks of sections. No sideways scroll. Tablet (~768px, bonus): rail collapses to icons; the dock becomes a sheet.

Checker ids: `#add-service`, `#disconnect` (first screen, confirm button "Disconnect"), `#simulate-change`, `#live-toggle` (ON by default).

## Critique fixes
- **Gap 1 (Settings/Memory undesigned):** §5b specifies both screens with content, defaults and states; Memory is a separate local-first screen, Agent facts is a tab of Home only, so the muddled "tab of each service" wording is gone.
- **Gap 2 (feed not derived from fixture):** §6 recomputes age from `checkedAt`, ages only live local/external facts, leaves `source: none` and non-live baselines still, separates service state word from fact freshness word (§5), scopes the one scripted stale to a single fact, and makes Check now a mock human action with a polite status and "no provider called".
- **Gap 3 (`#simulate-change` modelled backwards):** §2 reframes it as "Lock in Home" handoff with owner, link and verbatim reason, an "Awaiting Project Home" state, then one recorded write: "Home acted; Worlds recorded."
- **Gap 4 (no failure/drop-off):** §6 adds settle-failed rollback with inline cause and kept controls, a drop-off path reusing Notes Sync, and fixture retry vocabulary ("Check provider now", "provider timed out"); "Try again" is removed.
- **Gap 5 (OpenDesign pack as rejection list):** §8 names Soft Structuralism + Asymmetrical Bento and its mobile collapse, lists what survives and what is dropped (macro-whitespace no longer claimed), names Primary `#111111` as the accent with its two uses, and states that omitting grain is a decision.
