## DESIGN.md

# c616 — Service ledger

## 1. Metaphor in one line, and the main gesture.
Worlds is a service register printed on an ink-paper work surface: each row identifies an owner, while the selected owner's app and shared facts stay in the surrounding shell. The main gesture is **open an owner row, then inspect its app and the same facts Home and agents read**.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
Start with exactly `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`). `#add-service` starts Connect for the third service, `nightly-backup` (Nightly Backup, `stale`). Render six steps: (1) Discover lists Nightly Backup and its Settings owner; (2) Credential reference accepts a reference only, visibly refuses secret values, and presents labeled dirty, submitted-pending, and blur-validation states; (3) Safe test has a user-triggered run, running, success, and failure/recovery states; (4) Preview names `backup.last-success`, `backup.last-attempt`, and `backup.size`, all `stale`, with their fixture values; (5) Choose what to publish checks each fact and summarizes selection; (6) Publish adds the third row and the chosen fixture IDs to shared views. No real connection or secret is used.

One in-memory state object keyed by fact ID drives Home, the selected service pane, and Agent facts. The prototype's second working interaction, `#simulate-change`, applies the fixture `crossViewExample` action `lock-back-door` to `frontdoor.back-door`: the mock result changes that fact to `locked`, `front-door.state` to `healthy`, and `attentionCount` to 0 in one commit, visible simultaneously in all three views. It records mock review only; it does not lock anything. `#disconnect` confirms the selected service's name, removes its row and embedded app, and leaves the remaining shell working.

## 3. Navigation between Worlds and a service (phone and desktop).
The shell header and Home, Connect, Memory, Settings navigation persist. Desktop places the owner register beside a selected service pane; rows navigate to service detail rather than opening an action console. At 390px the register becomes a single-column list and the selected service is a single-column page with Back and persistent shell destinations. Focus enters the service heading and returns to the invoking row. Reading order is navigation, register/main, then complementary Agent facts. No horizontal scrolling, hover-only controls, or drag; all targets are at least 44px and have visible keyboard focus.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The selected service's UI is visibly framed in the service pane. Worlds navigation, service identity/state, Back, and Agent facts remain outside the frame. Fixture owner fallbacks stay visible at the frame edge: Media Shelf — “Open Media app” (`app://media`); Front Door — “Open Home app” (`app://home`); Nightly Backup — “Open Backup settings” (`app://settings/backups`). The fixture specifies `app://` links only. No Worlds credential is provided to the frame by design; enforceability, sandbox flags, origin policy, and cross-origin protocol are UNKNOWN. When embedding fails, show an explanation and the exact fallback. Governed approvals hand off to Project Home; all other service actions hand off to the owner.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Agent facts is a live view of the same fact-ID store as Home and the service pane. Each row names source, observed/checked time, freshness, Agent can see, Human can see, and Who can act as separate fields. For `frontdoor.back-door`, agent is `read`, human is `act`, with the fixture's reason verbatim: “Locking the door changes the external system and is the person's decision.” For `frontdoor.guest-code-used`, human is `read`; agent is `none`, shown as a named, disabled, focusable control with verbatim reason: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” `frontdoor.unlocked-for` is `read` for both. `lock-back-door` is a mock Project Home approval handoff, not an in-Worlds decision or real lock action.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
Zero services offers Connect and names the local-only baseline; zero providers creates no placeholder values. Quiet is the Media Shelf `healthy` state. Needs-you is Front Door's fixture `needs_attention` reason. Nightly Backup and all three of its facts remain explicitly `stale`, with the failed destination attempt visible as fixture data. This selected set has no unknown, unavailable, or not-configured service; do not render Garden Camera or imply that one is connected. Every absent value is named as an applicable explicit state, never a blank masquerading as status. Disconnect states what left and keeps remaining services/shell routes active; history policy is UNKNOWN. Safe-test loading/failure, empty preview, and long content each have bounded status and recovery. No decorative or ambient motion; honor `prefers-reduced-motion`.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr's one integration reused in UI and assistant, Dashy's in-place owner app and file-like service configuration, HA's explicit state vocabulary, and MCP ext-apps' host boundary around contained UI. This register is a table of owners, not the round-one `the-desk`: no sheet, caret, or shared tally line; rows do not become a plain-text work queue. Each row opens an actual service-owned frame while the Worlds shell and fact source remain visible.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `industrial-brutalist-ui` + `trading-terminal`. Keep the assigned skill's Swiss industrial print mode: hard grid, ink-paper substrate, compact mono metadata, and clear rules. Drop the terminal's dark surface, neon data colors, market/buy-sell semantics, ticker, and market density outright. Use its spacing scale (4/8/12/16/24/32), sharp border-based separation, and typography roles: JetBrains Mono display (28px) and body/data, Inter headings/labels, with body at 16px and labels at 12px; omit 10px microcopy. For color, the system has no compliant large paper token, so the page uses the browser's semantic `Canvas` surface rather than authoring a new brand color or a pure-white fill; this lets the user's platform surface preference govern. Use ink `#111827` text, not terminal white/neon. Verify 4.5:1 normal text, 3:1 large text/components, and 3:1 focus against adjacent colors; use `#72b1b1` comfortable focus from the Worlds accessibility contract only where it passes. Use a static, low-density register, explicit words for all states, 44px targets, keyboard operation, no-scroll 390px layout, visible MOCKUP label, and no motion by default.

## 9. Signature element, hero thesis, reference lock.
Signature: one fact ID rendered as an owner row, a Home attention summary, and an Agent facts row, then changed in one state commit. Hero thesis: “A service owns its work; Worlds makes its facts findable.” Reference lock: Things 3's clear separation of area/project/task ownership and Apple's Files provider document-browser handoff; mechanics only, not their visual styling. The signature is a reactive binding, not a drawn connector.

## 10. Risks and UNKNOWNs.
Real iframe capability/isolation, service manifest and API, actual Connect validation/test semantics, disconnect retention, and live runtime behavior are UNKNOWN. Values, timestamps, and result are synthetic fixture data. The selected set demonstrates healthy, needs-attention, and stale, not unknown/unavailable/not-configured; it must not claim broader state coverage. This is a design for a MOCKUP, not a tested integration.

### Critique fixes
- **Fact/action instantiation:** names `frontdoor.back-door`, `lock-back-door`, all three simultaneous views, exact resulting values, one store/one commit, and explicitly marks the action mock-only.
- **Start state / third service:** pins Media Shelf + Front Door at start and Nightly Backup as the third, with all six Connect screens, states, and preview fact IDs/values.
- **Uncomposed Garden Camera/state copy:** removed Garden Camera from populated-state claims; states plainly which fixture states the three selected services do and do not cover.
- **Permission accuracy:** records the exact independent permissions for the three Front Door facts and the verbatim `none` reason in a named, disabled, focusable control.
- **Assigned system conflict / repeated desk:** keeps Swiss print craft and the grid while dropping incompatible trading terminal colors/semantics; states the neutral surface decision and contrast checks. Defines the register against `the-desk` and replaces the redundant Bloomberg/HA reference lock with distinct mechanics.
