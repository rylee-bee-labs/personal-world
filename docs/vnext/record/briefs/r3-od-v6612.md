## DESIGN.md

# v6612 — The Welcome Shelf

## 1. Metaphor in one line, and the main gesture.
Worlds is a warm daily welcome that gathers what needs attention before opening any service in its own workspace. The main gesture is **notice what needs you, then open its named owner with the shared facts in view**. “Welcome back” is the shell greeting; “Front Door” remains only the fixture service name. The first-run greeting says “A good place to begin”; a small inline SVG wren gives one kind line and one quiet 320ms settle on successful connection. Its presence and movement never communicate status by themselves.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
At first paint, load exactly `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`), with Front Door selected. The Home attention summary, service list, service workspace, Memory, and Agent facts are views over one in-memory store keyed by the fixture fact IDs; changing a record updates all views in the same render. `#add-service` launches a six-step Connect flow: Discover → Credential reference → Safe test → Preview → Choose what to publish → Publish. Discover lists all five remaining fixture services verbatim: `nightly-backup` / Nightly Backup / `stale`, `garden-camera` / Garden Camera / `unknown`, `studio-printer` / Studio Printer / `unavailable`, `notes-sync` / Notes Sync / `unavailable`, and `local-weather` / Local Weather / `not_configured`, each with its fixture owner. Any may be selected as the third service; the default highlighted choice is Notes Sync.

Credential reference accepts a reference string only, explains “Worlds stores a credential reference, never the secret,” and rejects a pasted secret-looking value. Safe test is simulated and visibly labeled; its failure state names the chosen service and cause, preserves the reference, and offers “Retry test.” Preview shows that service’s exact fixture facts, values, and states; Local Weather has an honest empty preview because `facts: []`. Choose what to publish uses one labeled checkbox per fact, starts from the fixture facts selected, and states the sharing consequence. Publish first shows a pending state, then adds the service and selected fact IDs to the shared store. The wren settles once and says “Notes Sync is on. Three notes are waiting.” when Notes Sync is published. No provider call occurs and no secret value is accepted or passed to a frame.

`#simulate-change` applies only the fixture `crossViewExample`: `frontdoor.back-door` becomes `locked`, Front Door becomes `healthy`, and attention count becomes zero together in Home, the Front Door workspace, and Agent facts. This is a mock handoff/review, not a lock command. A governed action first displays “Locking… waiting on Home app” with the Agent permission row marked pending and disabled, then settles all three shared records together; the action still hands off to Project Home and Worlds does not decide or execute it. Other service actions hand off to their named owner. Disconnect removes only the named service after confirmation and leaves the shell usable.

## 3. Navigation between Worlds and a service (phone and desktop).
The persistent shell destinations are Home, Connect, Memory, and Settings. On desktop they occupy a left rail; on mobile they are a fixed, safe-area-aware bottom bar. The Home service list exposes a clear “Open [service] workspace” action and a separate “Agent facts” link. Each workspace provides the owner app beside its shared facts and an explicit Back to Home control. Back returns focus to the invoking service row; opening a workspace moves focus to its heading. Focus follows semantic source order.

Memory is the durable local baseline, independent of provider availability: its 1440px view places “3 notes waiting to upload” (`sync.local-pending`, live) beside “Last successful sync” (`sync.last-synced`, stale) when Notes Sync is present, with its source, time, and owner link. At 390px these become a list then a selected detail, with local pending notes first and the stale sync record second. Before Notes Sync is connected, Memory explains that local notes remain available and shows no invented count.

Agent facts is a first-class view reachable from Home and every service workspace. It lists every connected/published fact ID with value, source, observed or checked time, freshness word, Agent can see, Human can see, and Who can act as separate labeled fields. On desktop rows use aligned columns; on mobile each fact becomes a stacked row and the permission triple is its last line, never a truncated badge.

Settings is a real screen with five groups: Feed, Agent visibility, Comfort, Fixture, and First run. Feed owns the single persisted-in-session pause state used by Home and all views. Agent visibility lists the per-fact “Agent may see this” settings mirrored from fixture permissions; `frontdoor.guest-code-used` shows `none` with its exact fixture reason. Comfort states reduced motion follows the OS preference. Fixture says all values are synthetic and simulated. “Reset to first run” restores the initial two-service fixture state, removes added services, clears mock action state, and returns Home to zero connected services/providers in the demonstration baseline; it is reversible by adding an example service through Connect. First-run Home has no invented readings, names the local Worlds/Memory baseline, and offers “Connect a service.”

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
Each service workspace has a bounded, clearly titled owner-app frame beside a Worlds-owned shared-facts panel. Keep service name, owner, state word, and fixture fallback visible: Media Shelf → “Open Media app” (`app://media`); Front Door → “Open Home app” (`app://home`); Notes Sync → “Open Memory app” (`app://memory`); and all other services use the exact fallback label and href in the fixture. Navigation, Back, and status remain Worlds-owned around the frame. No credential is passed to it. Actual embed protocol, browser isolation flags, and messaging are UNKNOWN. If embedding fails, retain the facts, explain that the owner app could not be embedded, and keep its owner link visible. Approval and the mock lock review hand off to Project Home; all other actions go to their owner.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Home, each service workspace, Memory, and Agent facts read the same records. Every record exposes its exact fixture ID, value or explicit unavailable/unknown value, source (`local`, `external`, or `none`), observed/checked time (or “No observation”), freshness as a word, Agent can see, Human can see, and Who can act. For `frontdoor.back-door`, show Agent `read`, Human `act`, with the reason “Locking the door changes the external system and is the person's decision.” For `frontdoor.unlocked-for`, both can `read`. For `frontdoor.guest-code-used`, Human can `read`; Agent `none` appears as a named disabled, focusable control with the verbatim reason: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” Do not disguise `visitor-3` as agent-visible. Notes Sync’s `sync.provider-reachable` can be unavailable while `sync.local-pending` remains live and `sync.last-synced` stale; provider failure never erases the local pending count or last successful sync.

For fixture actions with `allowed: human`, show the fixture label, named owner, and permission; activating it presents the owner handoff affordance. Studio Printer’s “Retry last job” goes to Studio. Notes Sync’s “Check provider now” goes to Memory. They are owner-app actions, distinct from Connect’s simulated test retry.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
First-run is reachable via Settings → “Reset to first run”: Home has zero connected services and providers, an inviting wren illustration, the local Worlds/Memory baseline, and one primary “Connect a service” action; no provider reading is invented. Quiet uses Media Shelf’s exact fixture state word `healthy` and summary “Library reachable and indexing is current.” Needs-you uses Front Door’s `Needs a human` label and exact explanation “A decision is required; the local app will not act on its own.” Nightly Backup is `stale` with its failed destination reason and last successful run; Garden Camera is `unknown` with “The device stopped answering at the fixture's baseline; no source has answered since”; Studio Printer is `unavailable`, with the exact last error and owner retry; Notes Sync is `unavailable`, while local notes still work and its local pending fact remains live; Local Weather is `not_configured`, has zero facts, and explains no provider has been configured. Each state is reachable by selecting that service in Discover and publishing it. A failed Connect test is a distinct error with named cause, retained input, and “Retry test.”

Disconnect confirmation names the service and explains its removal from Worlds; its affirmative button is exactly “Disconnect.” After removal, show the remaining service list or the first-run empty screen. The fixture does not define retention/history behavior, which remains UNKNOWN. Status and recovery copy always use words as well as any color or icon.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr’s one integration feeding several surfaces, Dashy’s in-place app opening, Home Assistant cards’ shared state, and MCP ext-apps’ contained UI boundary. Unlike a widget dashboard or tool host, Worlds names each owner, shows provenance and separate permissions, and hands consequential choices to their owner. Provider APIs remain mechanics; they do not become Worlds concepts.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `skill-ui-ux-pro-max.md` and `ds-duolingo.md`. The Pro Max entry is catalog-only; its upstream search workflow and pattern library are not bundled, so none is claimed. Use a deliberately restrained, named Duolingo subset instead of deleting its grammar: Snow `#ffffff` only for card surfaces, Eel `#f7f7f7` for the page, Swan `#e5e5e5` for 2px borders, Eel Black `#3c3c3c` primary ink, Wolf `#777777` secondary ink, Owl Green `#58cc02` only as a non-text marker, Owl Green Deep `#58a700` for the 4px bottom edge of the single primary action, and Owl Green Pale `#dbf8c5` for a soft success/attention surface. Use 16px card radii, 12px button/input radii, Feather Bold (or its documented DIN Round / Helvetica Neue / sans-serif fallback) at weight 800 for headings and button labels, reduced page-title sizes of 32px desktop / 28px mobile, and Mona Sans (or Helvetica Neue / system-ui fallback) for body. Keep the 4/8/12/16/24/32 spacing scale; no new colors, fonts, or spacing tokens.

Contrast rule: the bright Owl Green never carries text, and no status depends on it. Use `#3c3c3c` text on Snow or Owl Green Pale; use `#58a700` for dark green text/edges only where measured contrast passes. The supplied palette pairs measure approximately 11.1:1 for `#3c3c3c` on `#ffffff`, 8.1:1 for `#777777` on `#ffffff`, 10.4:1 for `#3c3c3c` on `#dbf8c5`, and 3.1:1 for `#58a700` against `#dbf8c5` (non-text boundary only). `#58cc02` on white is about 2.3:1 and is therefore never text or a required control boundary. Maintain 4.5:1 for normal text and 3:1 for large text and non-text controls; verify actual implemented pairs. Apply the craft rulebooks’ named-token discipline, real fixture copy, state coverage, readable 50–75 character line lengths, semantic controls and focus, 44px targets, visible MOCKUP label, and no gradients, emoji icons, invented metrics, or motion-only feedback. Warmth comes from the wren, specific copy, gentle rounded geometry, and one satisfying connection moment, not a gamified progress system.

## 9. Signature element, hero thesis, reference lock.
Signature: a small inline-SVG wren delivers one kind, context-aware line and one restrained connection settle; it is quiet while an action is pending and sits still while the feed is paused. It never replaces a status label or announces its own motion. Hero thesis: “Welcome back. Here is what needs you, and who owns it.” Reference lock: Apple Home’s accessory-to-owner handoff and Homarr’s integration feeding multiple surfaces; borrow mechanics, not visual language.

## 10. Risks and UNKNOWNs.
The Connect API, safe-test semantics, actual service embed protocol/isolation, real action authorization, and disconnect history are UNKNOWN. All values are synthetic fixture data and every screen carries a visible MOCKUP label. Live freshness and drift are simulated, labeled “Simulated feed,” and never presented as real observations. Implementation must verify actual contrast pairs, mobile safe areas, keyboard focus, and 200% reflow.

## 11. How it differs from C, and what it keeps
C’s service cabinet pairs a fixed owner bay with a docked app and shared fact card. This concept keeps C’s persistent Home / Connect / Memory / Settings shell, explicit ownership, honest fixture states, and adjacent owner app plus shared facts. Its delta is an attention-first Home welcome that leads into full service workspaces, with one warm wren detail and no cabinet, bay, shelf, or door furniture metaphor organizing the experience.

## 12. Desktop and mobile layouts; live behavior and checker controls.
**Desktop, 1440px:** a persistent left navigation rail sits beside a centered content area up to 1080px. At first paint, Home selects Front Door and shows “Welcome back,” a needs-you summary, service list, service workspace, and Agent facts entry. The workspace has the framed owner app and shared facts side by side. The service list selection is visibly synchronized with the open workspace. Home also has a freshness line labeled “Simulated feed,” `#live-toggle` (ON by default), and the first-screen controls `#add-service`, `#disconnect` for selected Front Door, and `#simulate-change`. Memory uses the two-column local-pending / last-successful-sync view. Agent facts uses aligned columns. Settings presents the five named groups and reset control. Connect uses a connected six-step progress rail and one focused step panel.

**Mobile, 390px:** compact top identity and a fixed bottom bar for Home, Connect, Memory, Settings, with `env(safe-area-inset-bottom)`. Home reads greeting/attention, selected service summary, freshness controls and actions, service list, then owner app and facts. The selected service also has a full-width workspace screen with explicit Back; its owner app is followed by its facts and actions. Agent facts is a full-screen stacked list with permission triple last. Memory reads local pending list then last-sync detail. Settings is a single-column grouped screen. Connect is a sequential full-screen step flow with one primary step action, all step controls real `<button>`s, and clear labels. All controls have at least 44px targets; there is no sideways scroll. A skip-to-main link is first in focus order. Disconnect opens a native confirmation dialog, initially focuses Cancel, traps focus, closes on Escape, names the selected service, and returns focus to `#disconnect`.

**Reactive policy, shared in every view:** the visible feed is labeled simulated and ticks every 5 seconds. While ON, age labels recompute from fixture `checkedAt` values; every 12 ticks, the connected live service with the oldest checked timestamp (Front Door initially, then Media Shelf) changes to `stale`, keeps its fixture reason/value, and updates Home, workspace and Agent facts from the shared store with one concise polite announcement. Routine ticks and timestamp changes are not announced. After 150 seconds without a user-relevant announcement, a later meaningful state change may be announced. `#live-toggle` pauses both age recomputation and drift; its freshness line becomes visibly muted with the words “Feed paused.” `#simulate-change` remains available while paused because it is an explicit human action, not a feed event. Resuming reports the elapsed pause gap (“Paused 40s — freshness may have moved”) and recomputes age immediately; no claim is made that state stayed current.

Actions give immediate, explicit optimistic feedback before settling visibly in the shared store: lock review shows the pending Home handoff and disables its action; Publish and Disconnect show named pending states and disable duplicate submission, then settle to the service added/removed result. Failed test retains the entered reference and offers retry. Use Duolingo’s 180ms press and 320ms unlock easing only for publish/connected and a fact settling; no ambient motion. Reduced motion strips transforms and uses a static state change or brief opacity/color crossfade, while labels and status remain legible. Respect `prefers-reduced-motion`; data feed behavior remains independent of animation preference.

## Critique fixes
- Bound the assigned Duolingo system to explicit tokens, contrast rules, typography, shape, and motion rather than substituting an unnamed neutral style.
- Designed Memory, Agent facts, and Settings as complete destinations in both desktop and mobile reading orders; selected Front Door at first paint so `#disconnect` is immediately available.
- Defined live drift, pause/resume semantics, shared optimistic/pending/settled updates, and reduced-motion behavior.
- Let the wren support one connected moment without carrying status; removed conflicting cabinet/shelf/front-door shell metaphors from the distinction from C.
- Made every remaining fixture service reachable through Discover, added the resettable zero-service/provider state, and separated Connect test retry from human-only owner-app retry handoffs.
