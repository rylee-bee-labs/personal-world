# v4220 — Service folio

**MOCKUP direction; no prototype or reading is approved.** Worlds is the frame around independent services, not their replacement. Every view carries a visible `MOCKUP` label.

## 1. Metaphor in one line, and the main gesture.
Worlds is a service folio: each service keeps its own named page, while a portable fact slip carries its source and freshness wherever that fact is shown. The main gesture is to follow a fact from its owner’s app through its reading context and into Home or Agent facts.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
On first load, select Home and show two connected fixture services: Media Shelf (`healthy`) and Front Door (`needs_attention`). Connect begins with a six-step `#add-service` flow: discover; enter credential reference only; run safe test; inspect preview; choose facts to publish; publish. Use fixture IDs, names, states, facts, reasons, owner names and fallback links verbatim. Notes Sync (`unavailable`) is the third service. Its preview preserves `sync.provider-reachable` (`unavailable`), `sync.local-pending` (3 notes, `live`), and `sync.last-synced` (`stale`) as separate records. Publish adds Notes Sync and shows: “Notes Sync is in. Its provider is not answering yet; your 3 local notes are safe.” Its slip changes from “checking” to “checked just now.” `garden-camera` (`unknown`) is available in Discover as a fixture-backed service, and `local-weather` (`not_configured`, zero facts) is shown as an unconfigured Discover option; they are not extra connected defaults.

Each service owns its app, data, and actions. Worlds composes only selected facts into Home and the labelled Agent facts section in Memory. The same in-memory records drive all views. `#simulate-change` applies the fixture `lock-back-door` example to `frontdoor.back-door`: for about 600 ms its slip reads “Locking…” with `aria-busy="true"`, the control disables, and Home’s attention count remains visibly pending; it settles to `locked`, Front Door becomes `healthy`, and Home attention count becomes 0 in one store update that also refreshes Agent facts. Show the existing permission reason once beneath the settled value: “Locking the door changes the external system and is the person's decision.” This is a mock review/handoff only; Worlds does not lock the door.

## 3. Navigation between Worlds and a service (phone and desktop).
Home is the first paint after load. Its first screen shows the currently selected service summary and a visible `#disconnect` control for Front Door, satisfying the first-screen checker requirement; Connect repeats the same control beside the selected service. Persistent shell destinations are Home, Connect, Memory, Settings. Desktop uses a left destination rail; the main area is an asymmetric editorial spread, not a service index beside a docked app and fact card. Connect has a readable service index and selected detail. Memory contains both the local records and a labelled “Agent facts” section, so the three-view update is reachable without adding a fifth nav item.

At 390px, use a persistent four-item bottom bar and one-column routes. Home opens a selected service page. Connect opens the index; choosing a service replaces it with detail and an explicit Back button. Memory and Settings are single-column screens. In service detail, the narrow provenance margin is placed first in semantic/source order and collapses above the wide reading flow; label/value and owner app follow. No sideways scrolling. At desktop and mobile preserve keyboard access, visible focus, 44px hit areas, skip-to-main, landmarks, and reflow at 200% zoom. The service index and detail retain selected state when navigating between shell destinations.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
Place the service app inside the reading column at the point where its shared fact is discussed; its frame edge carries the owner name as a running head. Keep Worlds navigation, Back, service state, provenance margin and fact controls outside the app. Show the fixture fallback at the frame edge: “Open Media app” (`app://media`), “Open Home app” (`app://home`), or “Open Memory app” (`app://memory`). For Garden Camera use “Open Home cameras” (`app://home/cameras`); for Nightly Backup use “Open Backup settings” (`app://settings/backups`). If embedding fails, state that plainly and leave the owner link and facts available. The mock frame receives no Worlds credential; actual browser isolation, sandbox flags and app messaging are UNKNOWN. Approval handoff goes to Project Home; other service actions go to their owning app.

On `frontdoor.back-door`, provide a 44px “Review in Project Home” handoff control with an external-link cue. It opens a mock Project Home surface naming “Front Door: back door unlocked for 47 minutes” and says: “Nothing was decided in Worlds. Locking the door changes the external system and is the person's decision.” After the mock handoff, say “Recorded here as reviewed. The door is still unlocked until Project Home changes it.” Do not change the fact through this handoff; only `#simulate-change` applies the fixture’s cross-view example.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
A fact slip is the same portable record on Home, in the service reading flow, and in Memory’s Agent facts section. Its margin lists source, checked/observed time, freshness word, Agent can see, Human can see, and who can act; the reading column carries label/value. No view rebuilds the slip with different provenance. Every `none` is a named disabled, focusable control with its fixture reason. For `frontdoor.back-door`, Agent can read and Human can act, with the exact permission reason. For `frontdoor.guest-code-used`, Agent’s disabled permission explains: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.” For `camera.human-detected-today`, Agent’s disabled permission says: “The agent may not assert a detection while the source is unknown.” Facts retain independent states; provider failure never erases locally available data.

Notes Sync includes its fixture retry control, “Check provider now” (human-only, 2 attempts, last error “provider timed out”). Activation shows “Checking the provider…” for about 600 ms, then settles to `unavailable` with “provider timed out”; `sync.local-pending` stays `live` at 3 notes. This is a mock action; no provider call is made. Do not expose an Agent retry control.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
First-run zero services shows a useful local Worlds/Memory baseline, Connect invitation and `#add-service`; zero providers shows no invented readings. Memory’s local section shows fixture-backed local facts: `media.items` (1284 items), `frontdoor.unlocked-for` (47 minutes), and `sync.local-pending` (3 notes, `live`), each marked as local observations, not provider readings. Local Weather is shown as `not_configured` with its exact empty reason: “No provider configured, so there are no facts to show. The concept must render the empty state honestly rather than a placeholder value.” Quiet is Media Shelf’s `healthy` state. Front Door remains `needs_attention` with fixture reason and a kind line: “Back door has been unlocked for 47 minutes — longer than usual.” Nightly Backup remains `stale`.

Garden Camera gives the real `unknown` state: show `unknown` and its exact reason, “The device stopped answering at the fixture's baseline; no source has answered since.” For Last frame show “No frame available” (not an image); never imply a current observation. `camera.human-detected-today` uses its named disabled permission control and exact reason from §5. A failed safe-test state gives a specific failure and a retry/recovery button; an unavailable embedding state preserves the owner link and facts. Disconnect opens a modal confirmation naming the service and consequence, initially focuses Cancel, and includes a button labelled “Disconnect”; after removal, state exactly what service/app/facts are gone and that other destinations remain usable. Settings keeps a plain disconnected-services list with the same removal summary.

The mock feed is ON by default; `#live-toggle` is visible on Home and Settings. Tick every 3 seconds against a mock clock. Recompute “checked Ns ago” from `checkedAt` each tick; never trust or store fixture `ageSeconds`. On pause, replace every live age string in every view with “paused at [time]”; a frozen value never continues to say “ago.” Resume the mock clock and show “Live updates resumed.” At tick 6 (about 18 seconds after start), simulate a provider check drop-off for Media Shelf: freshness source becomes `none`, freshness word becomes `stale`, and copy reads “Media Shelf has not answered since 14:24:26. The last answer is still shown.” Keep its last-known values visible and label them stale; update Home, service detail and Agent facts atomically. On the next tick restore the fixture freshness source `local` and state `live`, then resume computed age strings. This is a mock freshness overlay; immutable fixture values and baseline states are never rewritten. `#simulate-change` and retry use immediate optimistic text and a visible 600 ms settle. Use one 150–200 ms opacity/transform cross-fade on the changing value line only; remove it entirely under `prefers-reduced-motion`, while data changes continue. Routine age updates are not announced; announce only meaningful state changes, batched politely.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr’s integration reused across views, Dashy’s in-place app opening, Home Assistant cards’ explicit stale/unknown words, and MCP ext-apps’ contained UI boundary. The folio puts provenance in a narrow margin and threads the owning app through the fact’s reading flow. These are pattern references, not claims about current product behavior; the research note describes them as memory-based rather than live-verified.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `skill-minimalist-skill.md` and `ds-pinterest.md`. Name these tokens and use only these source values: canvas `#F7F6F3`; surface `#FFFFFF` and `#F9F9F8`; hairline `#EAEAEA`; primary text plum black `#211922`; secondary olive `#62625b`; warm silver `#91918c`; sand `#e5e5e0`; warm light `#e0e0d9`; status pale red `#FDEBEC`/text `#9F2F2D`; pale blue `#E1F3FE`/text `#1F6C9F`; pale green `#EDF3EC`/text `#346538`; pale yellow `#FBF3DB`/text `#956400`; action accent Pinterest Red `#e60023` with dark plum text only where contrast passes. Keep red as the singular accent for primary actions; status pastels are semantic status treatment, always paired with explicit words. If either pair misses 4.5:1 normal-text or 3:1 large/control contrast, use a compliant neutral treatment and explicit state word; do not invent colors. Focus uses the project accessibility contract’s 2px teal `#72b1b1` ring at ≥3:1.

Use the system-native sans stack available locally, with no downloaded fonts or external images; do not use the banned Inter/Roboto/Open Sans or claim Pinterest’s proprietary font. Warmth moments: the connected line above; the kind Front Door sentence in §6; and a tiny inline SVG bookmark beside the service title, paired with a visible text label naming the current service (SVG itself `aria-hidden`). The bookmark is the only decorative flourish. The connected state gets a single 200 ms settle; all nonessential motion disappears under reduced motion. Apply the craft guides’ single signature, calm hierarchy, honest state coverage, 4.5:1 body/3:1 large/control contrast, keyboard-visible focus, reduced motion and specific useful feedback.

## 9. Signature element, hero thesis, reference lock.
Signature: the portable fact slip, identical on Home, beside its owner app in the reading flow, and in Agent facts, with source and freshness attached. The slip is the invariant record; the app stays present in its service reading context. Hero thesis: “A service keeps its own page. A fact keeps its source.” Reference lock: a naturalist’s field-guide specimen label for marginal provenance and a library catalogue card for the repeatable source-stamped slip; mechanics only, no copied skin or palette.

## 10. Risks and UNKNOWNs.
Connect protocol, actual credential-reference handling, browser-enforced embedding isolation, service messaging, and disconnect history are UNKNOWN. The live feed is a synthetic mock, not a real reading. “Paused at” is a mock clock time. The stationery metaphor must not imply facts are manually authored or detached from owners. Contrast values require implementation checking.

## 11. How it differs from C, and what it keeps
C pairs an owner bay’s docked app beside a shared fact card. The folio replaces that location-based pairing with a single asymmetric reading spread: provenance alone occupies the narrow margin, while value, owner app and action are threaded through the wide reading column in the order the fact is understood. The app cannot be removed from the folio without losing the service context. This is distinct from round-2’s “editorial ledger of facts,” a list that can stand without an owner app in frame; here the record is inseparable from the owning app in its reading flow. What the folio optimises is a portable slip identical on Home, the service page and Agent facts; C’s bay is a location, this slip is a reusable record. It keeps C’s real Home / Connect / Memory / Settings shell, independent service ownership, honest states, owner fallback, shared human/agent facts and governed handoff.

## 12. Desktop and mobile layouts
At 1440px, keep Home / Connect / Memory / Settings in a persistent left rail. The service page is a single asymmetric editorial spread: a narrow provenance-only left margin (source, checked time, freshness, visibility/action permissions) and a wide right reading column (fact label/value, owner app frame inserted into the reading flow, then action). The selected service’s identical fact slip appears on Home and Agent facts with the same source line. Home’s first screen shows selected Front Door and `#disconnect`; Connect repeats it. Keep `#add-service`, `#simulate-change`, and `#live-toggle` plainly visible on Home; feed control also appears in Settings. Settings includes per-service published-fact toggles (same selection as Connect step 5), credential-reference rows showing reference name only and “Worlds stores a credential reference, never the secret,” feed interval/state, a motion and reduced-motion acknowledgement, and disconnected-service history. Memory shows the three local facts, the explicit “nothing here is a provider reading” line, zero-provider Local Weather state, and the Agent facts section with identical slips and permissions.

At 390px, use the persistent four-item bottom bar. Each route is single-column with the same content and controls; service detail is separate from index with explicit Back. Provenance collapses above the reading column in semantic order, followed by label/value, owner-named app frame/fallback, and actions. The same Home/Connect/Memory/Settings screens, actions and live changes remain available without hover or motion. Hit areas stay at least 44px, text reflows at 200% zoom, and there is no horizontal page scrolling.
