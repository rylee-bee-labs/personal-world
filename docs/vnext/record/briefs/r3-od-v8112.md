## DESIGN.md

# v8112 — Clay tray (MOCKUP)

Status: MOCKUP. Synthetic fixture data only (`docs/vnext/fixture/fixture.json`); nothing here is a real reading. A visible "MOCKUP" label sits in the shell header at every width. Round 3, revised after cross-critique.

## 1. Metaphor in one line, and the main gesture.
Worlds is a tray of soft clay pebbles, one per service. The tray is sorted by what the facts say: each pebble carries one **dimple per fact**, and the pebble moves between three wells ("Needs you", "Settled", "Not answering") when its facts change state. Main gesture: **press a pebble (or one of its dimples) to settle it, then read its app and facts together; watch the tray regroup when a fact changes.** The face is an accent; the state word is always the truth.

**Mechanism that is false of C:** C's bays sit in a fixed register that never moves; in v8112 the arrangement itself is the status, because pebbles travel between wells and their dimples change shape as facts change.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
First screen has exactly `media-shelf` (Healthy, in "Settled") and `front-door` (Needs a human, in "Needs you"), with Front Door selected because it needs the person.

**Connect.** `#add-service` opens Connect. Step 1 Discover lists the fixture's not-yet-connected services, each with owner and state word: `notes-sync` (Memory, Unavailable; preselected as the default path), `studio-printer` (Studio, Unavailable), `garden-camera` (Home, Unknown), `local-weather` (Settings, Not configured), `nightly-backup` (Settings, Stale). Any can be connected; the six steps are the same, and the preview shows exactly that service's fixture facts. Steps:
1. Discover (shows owner).
2. Credential reference (reference only). Label "Credential reference", helper text persists. Validate on blur. A pasted secret is refused with "Worlds stores a credential reference, never the secret". Dirty/valid, submitted-pending (fields lock) and invalid states exist. The reference stays in the field across any later failure.
3. Safe test (idle/running/failed/passed). For `notes-sync` the first run fails (see §6 error copy) and offers "Check provider now" (the fixture retry label) or "Skip and publish local facts only". "Check provider now" passes on the second run, after which Preview shows provider-reachable as unavailable anyway, because the fixture says so.
4. Preview of `sync.provider-reachable` (unavailable), `sync.local-pending` (3 notes, live), `sync.last-synced` (stale), each with state word and source.
5. Choose what to publish: one checkbox per fact id plus a sentence on what is shared ("Shared with Home, this tray and the agent facts view. Nothing leaves this device in this mockup.").
6. Publish. The pebble drops onto the tray, settles into its well, the face blinks once, and the words read "Notes Sync is connected. Its provider is still unavailable; your 3 local notes are safe." No provider call occurs. (Other services get the equivalent sentence built from their own fixture state, e.g. Local Weather: "Local Weather is connected. No provider is set up yet, so it holds no readings.")

**One store.** One in-memory store keyed by fact id feeds Home, the service surface and the Agent facts view.

**Two separate things, never confused.**
- Human action (§5): "Ask Home to lock" on the back door is a real affordance that hands off to Project Home. It changes no fact by itself.
- `#simulate-change` is labelled "Fixture simulation: pretend Home confirmed the lock" and lives in the right rail (desktop) / Settings (mobile) under a "Fixture controls" heading with the MOCKUP tag. It applies `lock-back-door` from `crossViewExample`: `frontdoor.back-door` becomes `locked`, Front Door becomes Healthy and its pebble travels from "Needs you" to "Settled", the attention count goes to 0, and Home, the service surface and the Agent facts view all change in the same update. If a hand-off request is pending, it resolves as "Home confirmed" in the activity log. Worlds locks nothing.

`#disconnect` is on the first screen, in the selected service's header; it opens a confirm naming the service with a button labelled "Disconnect" (and "Keep it").

## 3. Navigation between Worlds and a service (phone and desktop).
Four persistent destinations, each a real screen:
- **Home**: Today sentence, Needs you, tray, selected service.
- **Connect**: the six steps above, plus a list of connected services.
- **Memory**: the hand-off and event log Worlds keeps in this mockup (connects, hand-offs, disconnects, each with time and who acted). Retention is UNKNOWN and said so on screen.
- **Settings**: see §6b.

Desktop: left rail. Phone: bottom tab bar (four 44px+ targets). A service opens in place; phone gets a full screen with Back, focus moves to its heading and returns to the invoking pebble on Back. Source order: nav, main, facts.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
The owning app sits in a clay-rimmed inset labelled with owner and state. Fallback is always visible under it with the fixture labels: Media Shelf "Open Media app" (`app://media`), Front Door "Open Home app" (`app://home`), Notes Sync "Open Memory app" (`app://memory`), Studio Printer "Open Studio printers" (`app://studio/printers`), Garden Camera "Open Home cameras" (`app://home/cameras`), Nightly Backup "Open Backup settings" (`app://settings/backups`), Local Weather "Open provider settings" (`app://settings/providers`). The frame is meant to receive no Worlds credential; browser-enforced sandbox flags and messaging are UNKNOWN. If embedding fails, the shell, fact card and fallback link stay, with the three-question copy in §6c and "Try again". Approvals hand off to Project Home; other actions to the owning app. For `local-weather` the frame shows the owner's setup prompt instead of an app, and its only action is the fallback "Open provider settings".

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
Agent facts rows show: fact, value, source (local/external/none), checked time and freshness word, "Agent can" and "Human can", and for any `none` a named disabled-but-focusable control with its fixture reason verbatim. Value for an absent fact is "Unknown", "Unavailable" or "Not configured", never blank.

- `frontdoor.back-door`: agent read; human act, with the reason "Locking the door changes the external system and is the person's decision." The act has a named control: **"Ask Home to lock"**. Pressing it shows in place: *Requested → Handed to Project Home → Waiting for Home to confirm* (the "Done" step arrives only when Home answers; in the mockup that is `#simulate-change`). It can also end *Failed: Home did not answer. Your request is kept. Ask again* (shown if the hand-off is pressed while the live feed is paused: "the mock host is not listening"). The control never says "Lock"; it asks.
- `frontdoor.unlocked-for`: both read.
- `frontdoor.guest-code-used`: agent none, rendered as a disabled, focusable control "Agent can't see who" with "Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who."; human read.
- `camera.human-detected-today` (Garden Camera, source `none`, value Unknown): agent none, disabled focusable control "Agent can't assert a detection" with "The agent may not assert a detection while the source is unknown."; human read. This is the unknown-source permission case.
- Studio Printer: `printer.status` is `unavailable`; the retry "Retry last job" is human-allowed and hands off to Studio ("Handed to Studio… waiting for it to confirm"); attempts shown as 1.
- Notes Sync: provider-unavailable and local-live facts stay separate rows.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
Each state is bound to a fixture service with its verbatim copy.

- **Zero services** (after disconnecting everything): an empty tray with one sleeping pebble outline, "Nothing plugged in yet. Connect your first service." and a button to `#add-service`. Worlds, Memory and Settings still work.
- **Zero providers** is a different situation: `local-weather`, "Not configured", blank face, an empty fact list, and the fixture `emptyReason` ("No provider configured, so there are no facts to show.") plus the summary "No weather provider has ever been set up…". Its dimple row is empty and says "0 facts". CTA: "Open provider settings", and a link to Connect. No reading is invented.
- **Quiet**: `media-shelf`, "Healthy", smiling face, "Library reachable and indexing is current."
- **Needs-you**: `front-door`, "Needs a human", `attentionReason` "A decision is required; the local app will not act on its own." with the summary; raised-hand face; in the "Needs you" well and listed first on Home.
- **Stale**: `nightly-backup`, "Stale", sleepy face, "Last successful run is older than the configured daily window."; its facts show a "Stale" word. The live feed also ages `media-shelf`: from tick 8 its check stops refreshing, and when age passes the Settings threshold (default 2 minutes) it becomes "Stale" ("Checked 2m ago") and its pebble travels to "Not answering".
- **Unknown**: `garden-camera`, "Unknown", puzzled face, `unknownReason` "The device stopped answering at the fixture's baseline; no source has answered since." Its three facts read "Unknown" with source `none` and no checked time ("No time recorded").
- **Unavailable**: `studio-printer`, "Unavailable", "job rejected: no media loaded" with error code E-MEDIA-02, "Retry last job" with running ("Handed to Studio…"), failed (the same error again, attempts 2) and done states shown in place.
- **Disconnected**: "Front Door is disconnected. Its bay, app frame and 3 facts are gone from Worlds; the rest still works." Retention of history is UNKNOWN.
- **Loading**: a static skeleton; a 15s "taking longer than expected" line. Long copy wraps. Edge: a 200-char service name and a missing summary still lay out.

### 6a. Live feed
ON by default, ticks every 3s, recomputes "checked Ns ago" from `checkedAt` in every view, and `#live-toggle` pauses/resumes with a visible "Live" / "Paused" word. Reduced motion removes animation, never data updates. Actions give instant optimistic feedback phrased as a hand-off ("Sent to Home… waiting for Home to confirm"), never as Worlds acting, then settle.

### 6b. Settings (a real screen, one row per decision)
Each row: label, current value, helper sentence, state, and who owns it.
- **Live feed** (switch, default On; shows "Live"/"Paused"). Owner: Worlds. Same state as `#live-toggle`.
- **Treat as stale after** (2 minutes default; 1, 2, 5). Owner: Worlds. Changing it re-words every freshness at once.
- **Motion** (follows device; read-only note "Reduced motion is on: nothing animates, data still updates" or "Motion is on"). Owner: your device.
- **Credential references** (list: name, service, "reference only, no secret stored", Remove). Empty: "No references yet. Connecting a service adds one." Remove asks first; owner: Worlds.
- **Providers** (per service: Local Weather "Not configured" with "Open provider settings" hand-off; Notes Sync "Unavailable" with "Check provider now"). Owner: the owning app; Worlds only links.
- **Fixture controls** (mobile only; desktop has them in the right rail): `#simulate-change`, `#live-toggle`.

### 6c. Errors in three-question form (what happened, why, what you can do)
- Safe test failed (Notes Sync): "The test did not finish. The provider timed out (it has not answered 2 checks). Your credential reference is kept. Check provider now, or skip and publish local facts only." Buttons: "Check provider now", "Skip and publish local facts only".
- Service dropped off (Notes Sync after publish or Studio Printer): "Notes Sync stopped answering. The provider timed out, so its sync status is unavailable; your 3 local notes are safe. Check provider now, or open Memory." The pebble moves to "Not answering".
- Embed failed: "The Memory app could not open here. It did not load inside Worlds. Try again, or open it in Memory." Fact card and fallback link stay.
- Hand-off failed: "Home did not answer. Your request to lock the back door was not delivered. It is kept; Ask again, or open Home."

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr's one integration feeding many surfaces, Dashy's open-in-place, HA's literal state words, ext-apps' contained UI behind a host boundary. Different: no dashboard grid or topology; a flat tray of wells with one selection and a fixed docked pair (app + facts).

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Starting point: `skill-stitch-skill.md` (stitch-design-taste) + `ds-claymorphism.md`. From Stitch: a DESIGN.md of atmosphere, roles and banned list, "Daily App Balanced" density (5), one accent, no Inter, no emoji, no pure black, no neon glow, no filler copy, skeletal loaders, composed empty states, 44px targets, `clamp()` type, `100dvh`. From Clay: soft puffy radii (20/28px), 4/8/12/16/24/32 spacing, Poppins display / Montserrat body / JetBrains Mono for ids, Text `#1C398E`, Surface `#FFFFFF`, Primary `#3B82F6`, semantic success `#16A34A`, warning `#D97706`, danger `#DC2626`. Fonts load as local stacks only (no CDN); fallback system sans.

**Colour reconciliations.**
(a) Primary `#3B82F6` is 3.7:1 on white, so it is a non-text marker (focus ring, selection rim, progress) and never text; CTA is `#1C398E` fill with white label (about 11:1). Semantic colours are for shape, border and face fill only; status words are set in Text `#1C398E`.
(b) Stitch bans serifs in software and the 3-equal-card row; Clay's puffy depth is limited to pebbles and the frame rim, using one soft inset shadow. The canvas tint is derived, not new: Primary `#3B82F6` at 8% over Surface `#FFFFFF`. No new hex values are introduced.
(c) One accent, as the skill says: Primary is the single accent. The earlier "two accent uses per screen" rule is dropped. Status colours are the Clay semantic tokens and always sit with a word and a face.

**Motion reconciliations (the skill asks for more motion than the craft rules allow).**
(a) The skill mandates "Perpetual Micro-Interactions: every active component should have an infinite loop state". **Overridden.** `animation-discipline.md` wins: motion only for a state change or reorientation, 150-250ms, transform and opacity only, off under reduced motion. Reason: a looping face or pulse would imply liveness the data does not have; the only liveness signal is the "Live" word and the 3s tick.
(b) The skill mandates "Staggered Orchestration: never mount lists instantly". **Narrowed.** Pebbles stagger in once on first mount (40ms steps, at most four, fade and 8px rise) because that is orientation; they do not stagger on re-render or tick. Under reduced motion, everything mounts at once.
(c) Allowed motion list: pebble settle on select; pebble travel between wells (FLIP, 200ms); dimple changing shape; face swap with a 150ms fade; connect-published drop; bottom-sheet slide on phone. Skill's "-1px translate on active" for buttons is kept (pressing is a state change). Craft rules also applied: anti-ai-slop, color, typography, laws-of-ux, state-coverage (all five states per surface), accessibility-baseline. Status words and shapes (face + word + text) are never colour-only.

## 9. Signature element, hero thesis, reference lock.
Signature: **the pebble's face and dimples**, an inline-SVG face per state (smile, raised hand, sleepy, puzzled, flat-mouthed for Unavailable, blank for Not configured) and one dimple per fact (pressed-in = live, half-filled = stale, dashed = unavailable, hollow with "?" = unknown). Both change with a small settle when a fact changes, always paired with words and a count ("3 facts: 2 live, 1 stale"). Hero thesis: "Every service gets a place, a face, and an honest word." Reference lock: Apple Home's accessory tiles that open to detail (mechanic only), and Duolingo-style small character feedback (tone only, no gamification). No palettes borrowed.

## 10. Risks and UNKNOWNs.
Embed support and browser-enforced isolation, Connect API, credential storage, hand-off protocol with Project Home and disconnect history are UNKNOWN. Faces could read as decoration or imply capability: the word always leads. Clay softness could blur hierarchy: borders are 2px `#1C398E` at low alpha on controls, with 3:1 checked on implemented pairs. Pebbles moving between wells could disorient: motion is brief, focus stays on the pressed pebble, and a polite live-region says "Front Door moved to Settled". Synthetic data must stay labelled MOCKUP.

## 11. How it differs from C, and what it keeps.
Keeps C's real shell (Home / Connect / Memory / Settings), owner-labelled services, the docked app-plus-fact-card, owner fallback links, fixture copy verbatim, the six-step Connect, and its honest state language. Differs in interaction, not just look: C is a fixed register with a static bezel; v8112's tray reorders itself into wells by state, each pebble carries a dimple per fact that can be pressed to jump to that fact, and a human action ("Ask Home to lock") runs a visible request-hand-off-answer path that `#simulate-change` completes. Also different: warm micro-copy and a "connected" moment, a mobile-native pattern rather than a shrunken register, and a failing-test recovery path in Connect. C is deliberately static; v8112 is reactive.

## 12. Desktop and mobile layouts.
**Desktop (1440):** three columns on a CSS grid. Left rail (240px): wordmark, MOCKUP label, four destinations, live toggle `#live-toggle` with the word "Live"/"Paused". Centre (flex): top "Today" sentence ("1 thing needs you."), the tray as three wells side by side ("Needs you", "Settled", "Not answering"; an empty well collapses to one quiet line such as "Nothing needs you" ) holding the pebbles, plus a dashed "Add a service" `#add-service` pebble below the wells; then the selected service's header (name, state word, freshness, `#disconnect` visible), with the app frame left and the fact card right, side by side. Right (320px): "Needs you" list, the live activity log, and "Fixture controls" with `#simulate-change`. Agent facts is a tab beside the fact card (and its own table on wide screens).
**Mobile (390):** one column, no sideways scroll, 44px targets, bottom tab bar (Home, Connect, Memory, Settings). Reading order differs from desktop: Today sentence, then Needs you (Front Door first), then the wells as stacked sections of full-width pebble rows, with the selected service's summary card showing `#disconnect` on the first screen. Opening a service pushes a screen with Back and a three-segment control: Facts (first), App (frame, fallback link), Agent. `#add-service` is a primary button in Home and in the tab bar's Connect, and Connect is full-screen steps with a sticky Back/Next. `#simulate-change` and `#live-toggle` sit in Settings (under "Fixture controls") and a compact Live chip in the header (also a `#live-toggle` equivalent; only one element carries the id). Confirmations use a bottom sheet. **Tablet (768, bonus):** icon rail replaces the bottom bar, wells stack, the detail stacks app over facts.
