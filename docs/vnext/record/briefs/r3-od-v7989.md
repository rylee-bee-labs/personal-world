## DESIGN.md

# Worlds vNext — v7989: The Service Cabinet

**MOCKUP** · Design decisions for a warm, working shell where a service’s register row carries its state-driving fact, and opening it reveals that fact’s source.

## 1. Metaphor in one line, and the main gesture

Worlds is a small, welcoming service cabinet: each service has a named row in a fixed register, and its most useful shared fact leads into the service’s own workspace. The main gesture is **follow one fact from the register into its provenance**. A tiny inline-SVG source mark (local, external, or unanswered) and kind helper copy add warmth; neither carries status alone. No physical cabinet bays, map, routes, or unfolding furniture.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow

The first render contains exactly `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`). The full fixture roster and role are fixed:

| Fixture service | Initial state | Required surface |
|---|---|---|
| `media-shelf` — Media Shelf | `healthy` | Quiet state; summary “Library reachable and indexing is current.” |
| `front-door` — Front Door | `needs_attention` | Human decision and `lock-back-door` cross-view example; owner Home (`app://home`). |
| `nightly-backup` — Nightly Backup | `stale` | Stale label and its daily-window summary; 8+ hour freshness gap. |
| `garden-camera` — Garden Camera | `unknown` | `unknownReason` in words; all three null facts say Unknown, never blank. |
| `studio-printer` — Studio Printer | `unavailable` | Human-only retry handoff; show last error and `attempts: 1`. |
| `notes-sync` — Notes Sync | `unavailable` | Connect’s third service; provider failure does not erase local notes. |
| `local-weather` — Local Weather | `not_configured` | Empty provider state using `emptyReason`; zero placeholder readings. |

`#add-service` starts Notes Sync through Discover → Credential reference → Safe test → Preview → Choose facts to publish → Publish. The credential field accepts a reference only, never a secret; reject a secret-shaped value with “Worlds stores a credential reference, never the secret.” Preview exactly `sync.provider-reachable` (`unavailable`), `sync.local-pending` (3 notes, `live`), and `sync.last-synced` (`stale`). The provider can be unavailable while local notes remain live. The published register row appears optimistically as “Connecting…” with `unavailable`, then settles to the fixture state on the next feed tick. This is mock UI; no provider call occurs.

Every register row carries its state-driving fact inline where present; selecting it opens the service transcript with the same fact’s provenance. Services own their data and actions; Worlds shows published fixture facts from one shared in-memory store keyed by fact ID. The `#disconnect` control is visible on the selected service’s first screen. A confirmation dialog names the selected service, explains that its current app view and facts disappear from the register, and has the exact confirm button label **Disconnect**. Confirm collapses the row immediately, reflows the remaining register, and leaves a persistent “Disconnected: [service]. Its current service view and facts are no longer in Worlds.” notice. History retention is UNKNOWN.

## 3. Navigation between Worlds and a service (phone and desktop)

Persistent destinations are Home, Connect, Memory, Settings. Desktop (1440px) has a compact top bar with those destinations, a visible MOCKUP marker, and the single `#live-toggle`. The constrained work canvas places the fixed-order register in the main column and selected service workspace to its right; its shared-fact provenance is a sticky right rail. At 768px, show the register as a horizontal two-up card row above a full-width service detail; provenance becomes an inline section below facts, not a side rail.

At 390px, use a distinct one-column Connect reading flow and persistent four-item bottom navigation. The single `#live-toggle` sits above the register on Connect (desktop top-bar instance and mobile Connect instance are the same control/state). Service detail replaces the register and includes a 50%-radius circular Back button with visible “Back to services” label. Service-screen first-screen budget: above the fold show only the service heading/name, explicit state word, Back control, and `#disconnect`; then a collapsed preview summary. The owner frame starts at or below the fold; facts, `#simulate-change`, and `#add-service` follow below it. On entry, focus the service heading; when Back is activated, focus returns to the selected register row.

DOM/source reading order is: skip link, shell navigation, main (heading and service actions → collapsed preview summary → owner frame → shared facts → remaining actions), then complementary provenance details. Mobile safe-area insets apply; text wraps; no sideways scroll at 390px or 200% zoom. Every target is at least 44×44px. Home and Memory use the same fact rows and store, never separately computed copies.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it)

The selected owner app sits in a clearly titled, softly rounded inset frame with owner and state named at its edge. Keep these fixture fallback labels and links verbatim: Media Shelf — “Open Media app” (`app://media`); Front Door — “Open Home app” (`app://home`); Notes Sync — “Open Memory app” (`app://memory`); Studio Printer — “Open Studio printers” (`app://studio/printers`); Garden Camera — “Open Home cameras” (`app://home/cameras`); Nightly Backup — “Open Backup settings” (`app://settings/backups`); Local Weather — “Open provider settings” (`app://settings/providers`). The live viewport uses the selected fixture owner fallback and displays its exact fixture link label as a real link. If embedding fails, state what failed and retain the owner link and shared facts. Keep Worlds navigation, service state, and provenance outside the frame. Worlds sends no credential value into the frame. Actual browser isolation, sandbox flags, and app messaging are UNKNOWN. Approvals hand off to Project Home; other actions go to their owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts)

Home, the register’s driving fact, selected service transcript, and Memory’s Agent facts view subscribe to the same fixture-keyed state. Each fact presents value (or explicit Unknown/Unavailable), source, observed/checked time and recomputed age, freshness word, Agent visibility, Human visibility, and who may act. Add a small source mark: filled dot for local, outlined dot for external, and a short hairline plus explanatory words for no source. It is decorative and `aria-hidden`; text carries the distinction.

Keep permissions independent: `frontdoor.back-door` is agent `read`, human `act`, with fixture reason “Locking the door changes the external system and is the person's decision.” `frontdoor.unlocked-for` is `read` for both. `frontdoor.guest-code-used` is human `read`, agent `none`, rendered as a named disabled control that stays keyboard-focusable so its exact reason is reachable: “Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who.”

`#simulate-change` applies only the fixture `lock-back-door` example: `frontdoor.back-door` becomes “locked,” Front Door becomes `healthy`, and Home attention count becomes 0. The fact, register row, Home attention summary, and Agent facts update in the same state commit. The control first shows immediate “Review recorded” feedback; the committed values then settle together. This is a mock review/handoff, not a Worlds decision or real door action. `#retry-last-job` for Studio Printer is labelled from fixture “Retry last job,” names human-only permission, and links to `app://studio/printers`; activation shows “Handing off…” then “Review opened in Studio printers.” It records mock review only; it never changes `printer.status`, its error code, or `attempts`. Notes Sync’s fixture retry (“Check provider now”) likewise hands off to `app://memory`; neither retry is agent-permitted or an in-Worlds mutation.

## 6. States and reactivity

First run with zero services shows “Connect a service,” explains that local Memory works without a provider, and offers no readings. `local-weather` demonstrates the exact zero-provider empty reason: “No provider configured, so there are no facts to show.” Quiet uses Media Shelf’s exact healthy summary. Needs-you uses Front Door’s exact summary and attention reason: “A decision is required; the local app will not act on its own.” with a calm Home handoff. Studio Printer has an explicit unavailable/error panel with exact `lastError` (“job rejected: no media loaded”), `attempts: 1`, and owner recovery. Garden Camera says its exact unknown reason: “The device stopped answering at the fixture's baseline; no source has answered since.” Keep its three null facts explicitly Unknown. Nightly Backup says Stale in text and surfaces the fixture’s last successful run beyond its configured daily window. Notes Sync keeps provider unavailable, 3 local pending notes live, last sync stale. Test failure identifies the failed check, what still works, and recovery; preserve credential reference and form input. Empty preview and long-copy states retain controls. Disconnected names the removed service and what remains.

**Reactivity contract:** At startup set `now₀` to the fixture `generatedAt` (`2026-10-13T14:24:26Z`); a wall-clock offset from that point advances `now` without changing fixture timestamps. A feed tick runs every 2 seconds. Every view recomputes `ageSeconds = max(0, now - checkedAt)` from the original ISO timestamp. Keep dynamic data in a volatile overlay `{ [serviceId]: { observedAgeSeconds, forcedState } }`; do not mutate fixture objects. A fact/service with fixture `live` freshness becomes overlay `stale` only after 900 seconds. Notes Sync begins fixture-stale and remains so; the rotating candidate cycle is exactly Media Shelf → Front Door → Studio Printer, one candidate at a time, for 5 ticks (10 seconds), then clears to its fixture freshness and advances to the next candidate. Candidate starts are separated by 30 ticks (60 seconds); no other forced state is possible. Feed pause clears any forced state and freezes age; resume starts a fresh `now₀` offset from current wall time, clears overlays, and continues age from fixture `checkedAt`. The feed never changes service states to `unavailable`, `unknown`, or `needs_attention`; those are authored fixture/action states. Persistent copy beside the toggle reads: “Simulated clock; these are MOCKUP readings, not a live check.” Feed is ON by default; `#live-toggle` actually pauses/resumes it. Settings contains exactly these rows: Live feed (On; same control/state as `#live-toggle`, fixture-independent local display preference); Pause with tab when hidden (On; local display preference); Motion (Full/Reduced, initialized from `prefers-reduced-motion`, with OS reduction taking precedence); Text size (Standard/Large, one root font-size step, local display preference); Comfort spacing (Standard/Roomier, one 8px spacing step, local display preference); About this MOCKUP (the fixture `syntheticNote`, fixture-backed disclosure). No preference changes fixture values. There is no unread/dismiss-all state in this fixture, so no Mark all read or Dismiss all row. Reduced motion affects visual movement only; data keeps updating.

Actions give immediate optimistic feedback and settle visibly: Publish inserts “Connecting…” then fixture state next tick; Disconnect removes the row now and preserves its notice; retry changes the control to “Handing off…” then to a named mock-review line; simulate-change commits its linked values atomically and updates visible labels in place. Rare Connect confirmation/first-run invitation may use one 180ms opacity confirmation plus 8px entry translation; no label-only keyframe. Frequent navigation, Back, feed toggle, and keyboard-initiated actions have 0ms movement (opacity only where confirmation helps). Use CSS transitions, never keyframes, for interruptible UI; exact property only, no `transition: all`; custom easing `cubic-bezier(0.23, 1, 0.32, 1)`. Pressable controls use Emil’s `scale(0.97)` `:active` feedback. Under reduced motion, remove translation and scaling, retain opacity/color feedback, and keep feed ticks. No shimmer or looping movement.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different

Borrow Homarr’s one integration feeding UI and assistant, Dashy’s in-place app opening, Home Assistant cards’ shared subscriptions, and MCP ext-apps’ contained UI boundary. Worlds keeps owner and permission/freshness context attached to each fact. The structural difference is a **fact-first register with a transcript**: the row carries the fact that explains its service state; opening it answers where that same fact came from and who may use it. There are no paired docked columns repeating the same payload and no provider catalog. The owner app remains a service view, not a replacement for the shell.

## 8. OpenDesign starting point and applied guide rules

Starting point: `skill-emil-design-eng.md` and `ds-airbnb.md`; use measured hospitality rhythm, button feedback, and the Airbnb type/color restraint without travel imagery or inaccessible bright surfaces. Named tokens and uses:

| Token | Value | Use |
|---|---|---|
| Ink Black | `#222222` | Primary text, headings, icons. |
| Warm Canvas (explicit Airbnb white-canvas override) | `#f4f1ec` | Low-glare page background for night reading. |
| Warm Surface (explicit Soft Cloud override) | `#faf8f5` | Cards and owner-frame surround; never pure white as a large surface. |
| Hairline Gray | `#dddddd` | 1px separators and card borders. |
| Ash Gray | `#6a6a6a` | Secondary text only after contrast check on Warm Canvas. |
| Rausch | `#ff385c` | Single primary Connect action per screen only; white label only if measured ≥4.5:1, otherwise Ink Black label or neutral fill with coral edge. |
| Error Red | `#c13515` | Error text/icon with explicit “Unavailable” or error words. |
| Focus teal | `#72b1b1` | 2px visible keyboard focus; provide a darker measured fallback if below 3:1 on a surface. |
| Spacing | 8px base; 8/16/24/32px | Common increments; 24px group separation. |
| Type | 14/16/21/28px; weights 500/600/700 | Airbnb roles; no 400. System fallback stack `Circular, -apple-system, system-ui, Roboto, Helvetica Neue, sans-serif`; no downloaded font. |

Canvas and surface overrides are deliberate: replace Airbnb’s `#ffffff`/`#f7f7f7` with named warm neutrals for a dim-room appliance; keep its Ink, Hairline, single Rausch, 50%-circle, 8px base, and 500 body weight. Rausch fill with white is not assumed to pass: measured white-on-`#ff385c` is about 3.7:1 and fails normal text, so primary Connect uses Ink Black label; fill is demoted to a non-text edge if component contrast fails. No gradients, photography, 3D icons, external assets, or remote fonts. State text and shape stay neutral; no status hue coding. Body copy max width 65ch, line-height 1.5, UI labels letter spacing 0.02em; do not uppercase headings.

| Rulebook and rule applied | Concrete decision |
|---|---|
| Emil — frequency table | Rare connect/first-run feedback may move for 180ms; Back, tabs, feed toggle, and keyboard actions do not move. |
| Emil — transitions/press | CSS property transitions for repeatable actions; no keyframes; pressables scale to 0.97; hover styling only under `(hover: hover) and (pointer: fine)`. |
| Emil — reduced motion | Strip translate/scale/rotation; retain opacity/color; the simulated data feed continues. |
| `anti-ai-slop.md` | One memorable visual move (fact-first row with source mark); no dashboard-template icon tiles, gradients, or invented content. |
| `color.md` | One accent, Rausch, limited to the primary action; warm neutrals dominate; status never color-only. |
| `typography.md` | Seven sizes maximum, 50–75 character body measure, 1.5 body leading, 0.02em UI label tracking. |
| `laws-of-ux.md` | Hick’s Law: show the two connected services first and progressively disclose the other fixture states in Connect; one clear primary action per surface. |
| `state-coverage.md` | First-use empty, error, retry, loading/test, and edge states name what failed, what still works, and recovery. |
| `accessibility-baseline.md` | Native buttons/links, skip link, explicit labels, keyboard-visible focus, 44px targets, WCAG 2.2 AA contrast, 200% reflow. |
| `animation-discipline.md` | Optimistic data commit precedes motion; state confirmation 150–180ms, no looping ambient animation, reduce axis motion. |

Contrast acceptance is explicit: normal text ≥4.5:1, large text ≥3:1, controls/markers and focus ≥3:1. Ink Black on Warm Canvas and Error Red on Warm Canvas are the text pairs. Before build, calculate exact ratios for all rendered pairs; if any fails, adjust fill first, then text, then non-text marker, and never use color alone for state. Disabled `none` control remains named and focusable per fixture rule. This DESIGN specifies candidate tokens; implementation’s measured rendered pairs are still required.

## 9. Signature element, hero thesis, reference lock

Signature element: the **fact-first register row that opens as its own provenance transcript**, with a tiny source mark and kind sentence (“No source has answered since 11:02 — we’re not guessing.”) for `none`. The mark remains decorative; the value, source, and state words carry meaning. Hero thesis: “Every service keeps its own door; every shared fact keeps its source.” Reference lock: Airbnb’s calm listing/detail hierarchy (whitespace, small-radius framing, not travel imagery or booking UI) and Apple Home’s accessory-to-home state handoff (mechanic, not palette).

## 11. How it differs from C, and what it keeps

Unlike C’s selected-bay composition, where the inset app and shared fact card sit docked side by side, v7989 makes the **fact the register artifact and the service screen its transcript**: a row leads with the value that explains the service, then detail traces source, freshness, visibility, and action permission. The inline source mark and plain kind sentence give the cabinet a small human touch instead of physical bay dressing. It keeps C’s persistent Home / Connect / Memory / Settings shell, clear ownership, in-place owner app and shared facts, honest fixture states, and non-authoritative Worlds boundary.

## 12. Desktop and mobile layouts

**Desktop, 1440px:** persistent top shell navigation; compact MOCKUP marker and `#live-toggle` in the top bar. Main canvas is constrained to 1280px: service register (about 280px), service transcript (about 600px), and sticky right provenance rail (about 320px). The first view includes service name/state, driving fact, owner frame preview, provenance, `#disconnect`, `#simulate-change`, and `#add-service`; no hidden menu. At 768px use the two-up register row above full-width detail, with provenance inline below the facts.

**Mobile, 390px:** bottom navigation for Home, Connect, Memory, Settings. On Connect, place the live toggle and honest simulated-clock line above the register. Register and detail are separate one-column screens; detail has Back and `#disconnect` by the heading. First-screen order/budget: Back → service heading and state → `#disconnect` → collapsed owner-preview summary; owner frame begins at or below fold, then shared facts/provenance, `#simulate-change`, and `#add-service` below. This is a mobile reading sequence, not a reduced desktop grid. Use safe-area insets, wrapping labels, 44px targets, and no horizontal scrolling. At both widths the MOCKUP label persists. The mobile bottom navigation stays available while scrolling.
