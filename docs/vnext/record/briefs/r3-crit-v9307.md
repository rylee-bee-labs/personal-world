## DESIGN.md for v9307

# v9307 — "The Sleeve"

Status: MOCKUP. Synthetic fixture only (`../../fixture/fixture.json`); nothing here is a real reading, and nothing here is approved. Follows `../../concept-brief-v2.md` plus the real-rounds additions in `../../concept-brief-v3.md`. Starting direction: `../../reference/direction-C-DESIGN.md`.

## 1. Metaphor in one line, and the main gesture.
Worlds is a **player for the services in your home**: each service is a **sleeve** you pull out, its own app lives inside the sleeve, and the **liner notes** beside it say where each fact came from and who may act on it. The main gesture is **pull out a sleeve and read its liner notes while its app is open**. The shell itself is a calm, real product: a persistent left rail, a Home board, and one **live strip** along the bottom that keeps honest time.

## 2. Integration model: how a service plugs in, where it lives in the shell, how its facts flow.
First render has `media-shelf` (Media Shelf, `healthy`) and `front-door` (Front Door, `needs_attention`); `#add-service` starts the third-service Connect flow for `notes-sync` (Notes Sync, `unavailable`) as an explicit mode, never on the live board: **Discover** (shows Notes Sync and its Memory owner) → **Credential reference** (labelled; accepts a reference only and rejects a secret with "Worlds stores a credential reference, never the secret.") → **Safe test** (run / running / passed / failed + recovery) → **Preview** (`sync.provider-reachable` `unavailable`, `sync.local-pending` 3 notes `live`, `sync.last-synced` `stale`) → **Choose what to publish** (a checkbox per fact) → **Publish** creates the Notes Sync sleeve. Each step is a real `<button>` with a clear label; this is mock UI, no provider call occurs.

Sleeves are independent owners, not locations: nothing routes or unfolds. Facts live once in one in-memory store and are read by Home, the service's own sleeve, and the Memory view, so one change updates all three without a reload. **`#simulate-change`** applies `lock-back-door` from `crossViewExample` in one state update: `frontdoor.back-door` becomes `locked`, Front Door becomes `healthy`, Home's needs-you count becomes 0, and the Memory row changes at the same instant. Words only — Worlds locks nothing; the mock action hands off to Project Home for review.

## 3. Navigation between Worlds and a service (phone and desktop).
Desktop keeps Home / Connect / Memory / Settings in a persistent left rail; the main area is the Home board beside the **docked sleeve** for the currently selected service. Opening a sleeve never leaves the shell: rail and live strip stay live around it. At 390px the rail becomes a bottom nav bar, Home becomes one column, and a sleeve opens as a full-screen route with an explicit Back; focus moves to the sleeve heading and returns to the invoking tile. Source order is nav → header → selected sleeve → tiles → strip. Everything is keyboard-reachable with a visible focus ring and 44px targets.

## 4. The embedded-app frame (sandbox, fallback, what the shell keeps around it).
Inside each sleeve sits a framed inset screen for the owning app — drawn statically, no iframe. The frame edge permanently shows owner, state and the fallback: Media Shelf — "Open Media app" (`app://media`); Front Door — "Open Home app" (`app://home`); Notes Sync — "Open Memory app" (`app://memory`). Fixture links use `app://` only. The frame receives no Worlds credential by design; whether the browser enforces that boundary, the sandbox flags and app messaging are **UNKNOWN**. If embedding is unavailable, the sleeve keeps the owner, state, liner notes and fallback and explains the failure. Approvals hand off to Project Home; other actions hand off to the owning app.

## 5. The agent/human shared-facts model (source, freshness, who sees, who acts).
The liner notes and the Memory view read the same records as Home. Each row separates **source** (local / external / none), **checked** age recomputed from `checkedAt`, **freshness**, **Agent can see**, **Human can see**, **Who can act**. `frontdoor.back-door`: agent `read`, human `act`, reasoned "Locking the door changes the external system and is the person's decision." `frontdoor.guest-code-used`: human `read`; agent `none` rendered as a named, disabled, focusable control with its exact reason — "Identifying a person is human-only in this fixture; the agent sees that a guest code was used, not who." `frontdoor.unlocked-for`: both `read`. `sync.provider-reachable` can be `unavailable` while local `sync.local-pending` stays `live`; both records persist and provider failure is never collapsed into local-data failure. Notes Sync retry is an owner-app handoff, never an approval.

## 6. States: empty/first run (zero services, zero providers), quiet, needs-you, stale, unknown, disconnected.
First run shows a vacant board, the wren, `#add-service`, and the local Memory baseline working — zero providers means no invented readings. Quiet is Media Shelf `healthy`. Needs-you is Front Door `needs_attention` with its fixture reason, promoted as the one strong tile. Stale is Nightly Backup: "Last good backup 4 days ago. Nothing's lost — Worlds just stopped checking." Unknown is Garden Camera (`source: none`) with its reason, said in words, never blank. Not configured is Local Weather: zero facts, honest empty copy. Disconnect leaves a tombstone naming the service and its owner; the other sleeves and the whole shell stay usable; retention is **UNKNOWN**. Loading (skeleton 300 ms–2 s, "taking longer than expected" at 15 s), error (what happened, why, recovery, input preserved) and long-copy edge states are drawn per `../../od-pack/state-coverage.md`.

## 7. Borrowed from Homarr / Dashy / HA cards / MCP ext-apps, and what is deliberately different.
Borrow Homarr's one integration feeding several surfaces, HA cards' literal state words and explicit `unavailable`/`unknown`, MCP ext-apps' contained UI and host-mediated permission boundary, Dashy's per-item checked-at. Deliberately different: there is no map, no route tracing, no unfolding place and no cross-service topology. The board is a fixed, gapless bento; the reactive spine is the live strip, not the layout. Colour comes from the owning app inside a sleeve, never from the shell.

## 8. Your OpenDesign starting point (skill + design system) and how you used it; which guide rules you applied.
Skill `../../od-pack/skill-gpt-tasteskill.md` is a marketing/GSAP skill, so I take only its **anti-default discipline**: a wide editorial Home heading that stays within two lines, no cheap meta-labels ("SECTION 01"), no emoji, a gapless dense board, varied composition, restrained hover physics. I drop its AIDA landing skeleton, its React/Tailwind/GSAP/CDN assumptions and its stock-image CDNs, which the stack rule forbids. Design system `../../od-pack/ds-spotify.md` shapes the shell: content-first darkness (`#121212`/`#181818`/`#1f1f1f`) so the owning app is the only colour; pill/circle geometry; uppercase, wide-tracked labels (1.4–2px) as the label voice; compact 10–24px type; heavy elevation shadows; sidebar → bottom bar collapse; accent green `#1ed760` used functionally only (the `#live-toggle` play state plus one primary CTA, ≤2 visible accent uses a screen per `../../od-pack/color.md`). Body text is silver `#b3b3b3` (≈8.9:1 on `#121212`) with white for emphasis; states use the semantic red `#f3727f` (unavailable), orange `#ffa42b` (needs-you), muted grey (unknown / not configured). Warmth is laced in as kinder micro-copy and **one** inline-SVG wren, never as texture or decoration. Applied: `anti-ai-slop` (no indigo, no emoji, no filler, no invented metrics, ≤12 raw hex outside `:root`, ≤2 accent uses), `color` (4.5:1 / 3:1 gates, dark not pure black), `typography` (6-size cap, ALL-CAPS tracking ≥0.06em), `laws-of-ux` (≤5 primary choices, one von-Restorff needs-you tile, grouping rhythm, familiar nav placement), `state-coverage`, `accessibility-baseline` (WCAG 2.2 AA, 44px targets, `:focus-visible`, native controls, landmarks), `animation-discipline` (150 ms state-confirm, ≤500 ms non-navigation, motion confirms rather than performs, `prefers-reduced-motion` strips transforms).

## 9. Signature element, hero thesis, reference lock.
Signature: the persistent **live strip** — the one Worlds-owned surface that keeps honest time for the selected service and is the only place the motion budget is spent — bound to the sleeve-plus-liner-notes dock. Hero thesis: "Worlds doesn't hold your services; it holds their labels — the sleeve shows whose it is, the strip shows how fresh it is, the liner notes show who may act." Reference lock: Spotify's web player for shell mechanics (library board, now-playing strip, pill/circle geometry, uppercase label voice, content-first darkness) and Things 3 for calm, one-job surfaces and warm micro-copy. Mechanics only; no palette is copied.

## 10. Risks and UNKNOWNs.
Real embed support, browser-enforced isolation, sandbox flags and app messaging are **UNKNOWN**; the Connect API, the provider protocol and disconnect history retention are **UNKNOWN** (mock only). The dark system risks feeling cold — warmth depends on copy and on the owning app's colour, both limited by the fixture. The wren could read as noise, so it is omitted under reduced motion and is never the sole signal of a state. Contrast must be measured on implemented pairs before review. The fixture is synthetic and stays labelled MOCKUP, never a real reading.

## 11. How it differs from C, and what it keeps.
**Differs.** C is a cabinet of fixed static bays with a static signature; v9307 is a player: a gapless bento Home, a **reactive live strip** (pause/resume) as the signature, and a sleeve whose colour comes from the owning app. C's register is equal-order and achromatic; v9307 promotes exactly one needs-you tile and warms the shell with micro-copy and the wren. C uses the design-taste skill with `ds-skeumorphism`; v9307 uses the gpt-taste skill with `ds-spotify`. On phone, C trades a one-column register for one-column detail + Back; v9307 adds a bottom nav bar and a slim live strip above it. **Keeps.** The real shell (Home / Connect / Memory / Settings), services as clearly owned labelled places, the owning app docked beside the shared fact card, the same fixture data and state words verbatim, the same Connect lifecycle shape, honest states, calm structure, the accessibility floors, the visible MOCKUP label, and the rule that a governed action hands off rather than deciding.

## 12. Desktop and mobile layouts.
**Desktop @1440.** Three zones: left rail (14px nav, active 700 white, inactive 400 `#b3b3b3`); two-pane main — left a five-column gapless bento board of service tiles, right the docked sleeve, whose header carries owner, state and **`#disconnect`** and whose body is the embedded frame beside the liner-notes card; full-width **live strip** along the bottom showing the selected service, its ticking freshness, **`#live-toggle`**, **`#simulate-change`** and the wren. **`#add-service`** sits in the Home header. Tab order is rail → board → sleeve → strip. **Tablet @768 (bonus):** rail becomes a top bar, board is two columns, strip stays pinned. **Mobile @390.** Bottom nav bar (Home / Connect / Memory / Settings) with the slim live strip above it (`#live-toggle`, `#simulate-change`); Home is a single column — a two-line editorial header, `#add-service`, then the currently selected service pinned as the first card with **`#disconnect`** visible inline (so no drawer is opened to reach it), then the remaining rows; tapping a row opens the sleeve as a full-screen route with a sticky Back + owner + `#disconnect` header, embedded frame, liner notes and owner fallback. No sideways scroll; 44px targets; the live feed is ON by default and every view updates in place.
