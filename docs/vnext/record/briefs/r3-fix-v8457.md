## Your DESIGN.md

# v8457 — The Counter (MOCKUP)

Status: MOCKUP. Synthetic fixture data only (`docs/vnext/fixture/fixture.json`); nothing here is a real reading. A visible "MOCKUP" label sits in the top bar on both layouts.

## 1. Metaphor in one line, and the main gesture
Worlds is a friendly service counter: every service hands its facts across it, and the counter shows plainly where each came from, how fresh it is, who can see it and who can act. Main gesture: **pick a service slip, then read its fact journey** (source → Worlds → agent / you). A small inline-SVG snail courier, **Dot**, carries the facts: slow on purpose, which is the calm.

## 2. Integration model
Start: exactly `media-shelf` (Healthy) and `front-door` (Needs a human). `#add-service` opens Connect for `notes-sync`: (1) discover, (2) credential *reference* (a reference only; a pasted secret is refused with "Worlds stores a credential reference, never the secret"; validates on blur, with dirty and submitted-pending states), (3) safe test (run / running / passed / failed, with recovery), (4) preview of `sync.provider-reachable` (unavailable), `sync.local-pending` (3 notes, live), `sync.last-synced` (stale), (5) choose which facts to publish, one checkbox each, (6) publish. Dot delivers a parcel and a "Connected" stamp lands. All in-memory; no provider call. One store keyed by fact id feeds Home, the service surface and the agent-facts view. `#simulate-change` applies `lock-back-door` (`crossViewExample`): `frontdoor.back-door` → locked, Front Door → Healthy, attention count 0, on all three at once. Worlds locks nothing; it records a mock handoff.

## 3. Navigation between Worlds and a service
Four destinations everywhere: Home, Connect, Memory (holds the aggregate Agent facts view), Settings. Desktop: left rail. Mobile: bottom tab bar; a service opens as a pushed full screen with a Back button and in-page tabs *App / Facts / Agent view*. Focus moves to the new heading and returns to the invoking slip on Back.

## 4. The embedded-app frame
A bordered frame (iframe/ext-app style, drawn) holds the owning app, headed by owner name and state word. The fallback link is always at the frame edge, verbatim from the fixture: "Open Media app" (`app://media`), "Open Home app" (`app://home`), "Open Memory app" (`app://memory`). The frame gets no Worlds credential by intent; real browser enforcement and sandbox flags are UNKNOWN. If embedding fails, the shell, facts and fallback stay, with a plain cause and recovery. Approvals hand off to Project Home; other actions to the owner.

## 5. The agent/human shared-facts model
Each fact row: source (local / external / none), checked time, freshness word, **Agent can** and **Human can** shown separately, plus the reason where one is given. `frontdoor.back-door`: agent read, human act ("Locking the door changes the external system and is the person's decision."). `frontdoor.guest-code-used`: agent none, a named, focusable, disabled control showing the fixture reason verbatim. `sync.provider-reachable` stays unavailable while `sync.local-pending` stays live; they are never merged.

## 6. States
First run (zero services): Dot asleep beside an empty counter, a value sentence and `#add-service`. Quiet: Media Shelf, Healthy. Needs-you: Front Door with its fixture reason. Stale: the live feed can age a service into Stale (labelled "simulated"), and Notes Sync's last sync is Stale. Unknown: said in words, never blank. Error: a failed safe test keeps the typed reference and offers retry, with "last tried Xs ago" and a limit of three tries. Disconnected: `#disconnect` is visible on the first screen for the selected service and opens a confirm dialog with a "Disconnect" button; afterwards Worlds says what is gone ("Front Door's 3 facts and its app frame are removed from Worlds; the app itself is untouched"). Whether history is retained is UNKNOWN. Loading, empty preview and long-copy states each carry recovery copy.

## 7. Borrowed, and what is different
Homarr: one integration feeds the UI and the agent. Dashy: apps open in place. HA cards: literal state words. MCP ext-apps: a contained UI under a host boundary. Different: the fact journey is a list-shaped receipt (the Wise transfer breakdown), not a map, route or topology.

## 8. OpenDesign starting point
Skill `frontend-design` (commit to one direction; real states; self-review at both widths; a memorable quality) and design system `ds-wise`. Used from Wise: off-white canvas, near-black `#0e0f0c`, lime `#9fe870` with `#163300` text for primary pill buttons only (never a large surface), mint `#e2f6d5` for the selected slip, ring shadows `0 0 0 1px rgba(14,15,12,.12)`, 16/30px radii, 8px spacing, heavy display type with tight leading and weight 600 body. Wise Sans and Inter are not available (no external fonts), so I use a heavy system stack, an UNKNOWN for fidelity. Wise's red `#d03238` and yellow `#ffd11a` come with a text label and icon shape, never colour alone. I keep the scale-on-hover behaviour on buttons only, off under reduced motion. Craft rules applied: state-coverage (all five states), accessibility-baseline, animation-discipline, anti-ai-slop (no emoji icons, gradients or invented metrics).

## 9. Signature, hero thesis, reference lock
Signature: the **fact journey receipt** with Dot, which shows source → Worlds → agent / you and settles with a small tick on each change. Thesis: "Every fact says where it came from and who can act on it." Reference lock: Wise's transfer breakdown (mechanics only, not its palette beyond the design system) and Apple Home's accessory states.

## 10. Risks and UNKNOWNs
Embed support and isolation, the Connect API, disconnect history, and font fidelity are UNKNOWN. Whimsy may crowd the calm, so Dot appears only at first run, connect, and state changes. The lime-on-mint contrast is to be measured on the built pairs.

## 11. How it differs from C, and what it keeps
Keeps C's persistent app shell, labelled and owned services, the owning app beside the shared facts, honest states, and the verbatim fixture reasons and fallbacks. Differs: C is a flat, static bezelled cabinet of fixed bays. v8457 drops the cabinet and the bezel and makes a counter with a receipt-style fact journey. It adds warmth through Dot, kind copy and a connect moment, and the live feed makes it reactive: the "checked 2s ago" ticker, simulated staleness and optimistic actions that settle visibly. The skin is Wise (lime, heavy type), not C's skeuomorphism. The feed is on by default, and `#live-toggle` pauses and resumes it, with reduced motion removing animation but not data.

## 12. Desktop and mobile layouts
**Desktop, 1440px:** top bar (MOCKUP label, `#live-toggle` "Live · checked 2s ago", `#simulate-change`, `#add-service`), 232px rail, 360px column of service slips (Front Door is selected on load, and each slip shows state word and freshness), and a detail pane with the service header (state word, **`#disconnect` visible**), the app frame with its fallback link, then the fact journey rows and an "Agent sees" strip under it, so `#simulate-change` visibly changes the slip, the pane and the agent strip together. Tablet at about 768px: the rail collapses to icons and the slips become a top row.
**Mobile, 390px:** a single column with a bottom tab bar and 44px targets. Reading order: the counter's one-line status and live toggle; the selected service card (Front Door first, with state, reason and **`#disconnect` on the first screen**); the other slips; then a floating `#add-service` above the tab bar. Opening a service pushes a screen with Back and tabs (App / Facts / Agent view), and the frame stacks above the facts with the fallback link beneath. Connect is a full-screen stepper with a sticky Back/Next bar. There is no horizontal scroll, and rows wrap, never truncate.

## CRITIQUE.md (another engine)

# Critique — v8457 "The Counter" DESIGN.md

Reviewed: the DESIGN.md pasted as the concept's round-3 design, against
[concept-brief-v3.md](../../concept-brief-v3.md), [concept-brief-v2.md](../../concept-brief-v2.md)
(still in force), [direction-C-DESIGN.md](../../reference/direction-C-DESIGN.md) and
[fixture.json](../../fixture/fixture.json). Five gaps, most important first. This
is a design review, not a build review: it judges the pinned decisions, and the
document's own deferrals ("to be measured on the built pairs", UNKNOWN) count as
missing decisions, because the brief requires them pinned *before* code.

---

## 1. Settings is promised as one of four destinations and is never designed

**Missing / wrong.** §3 commits the shell to "Four destinations everywhere: Home,
Connect, Memory …, Settings." Settings then appears nowhere else in the
document: not in the state list (§6), not in the desktop layout (§12), not in the
mobile reading order (§12), not in the Connect flow (§2). The brief makes it a
named deliverable — "Real navigation, a settings screen, a first-run / empty
state, an error state" (v3, *What "the real rounds" add* 1) — and Rylee's decision
in force is a "more real application". The concept is one quarter short of its
own navigation.

This is not cosmetic, because Settings is the only place the shell's own governed
concerns can live:

- **Credential references.** §2 lets her paste a reference in Connect but says
  nothing about seeing, replacing or revoking it afterwards. "Worlds stores a
  credential reference, never the secret" is a claim about the product, so the
  list of stored references has to exist somewhere she can reach.
- **Disconnect and its history.** §6 says "Whether history is retained is
  UNKNOWN" — a Settings decision, not a modal's.
- **Providers.** The fixture's `local-weather` is `not_configured` with fallback
  "Open provider settings" (`app://settings/providers`); v2 integration req 2
  requires the fixture's words used verbatim, and there is no Worlds screen that
  answers them.
- **Comfort.** The live feed, `prefers-reduced-motion`, and mock/real honesty
  labels are all Settings-shaped and all currently implicit.

**Why it matters.** An empty rail item behind a persistent tab is the fastest way
for "a real application" to read as a mockup, and it leaves the credential-
reference promise unmanageable in daily use. It is also the difference between a
demo and something she would open on a Tuesday.

**Fix.** Pin Settings as a real screen at the same depth as §2/§12: sections for
Connected services (state word, freshness, per-service `#disconnect`), Credential
references (list, replace, remove — reference only, never a secret), Providers
(including the `local-weather` `not_configured` empty state, verbatim), Live feed
(on/off, cadence, reduced-motion), and About (MOCKUP label, the UNKNOWNs). Give it
its desktop pane and its 390 reading order, and its own loading / empty / error /
edge content. If Connect's review step is meant to deep-link here, say so.

---

## 2. The live feed is named but not modelled, and its first value is invented

**Missing / wrong.** Reactivity is the explicit decision in force ("make sure they
have both desktop and mobile and are reactive"). The design answers with
attributes, not a mechanism: §12 puts "`#live-toggle` 'Live · checked 2s ago'" in
the top bar, §6 says "the live feed can age a service into Stale (labelled
'simulated')", §11 lists "the 'checked 2s ago' ticker, simulated staleness and
optimistic actions that settle visibly". There is no tick interval, no time base,
no rule for *which* service ages, and no statement that a tick propagates to the
slip freshness, the fact rows and the agent-facts view.

Two concrete defects fall out:

- **The opening value is fabricated.** The fixture pins the baseline: `generatedAt`
  `2026-10-13T14:24:26Z`, Front Door `checkedAt` `14:24:02Z` (24 s), Media Shelf
  `14:23:58Z` (28 s), and `_meta.provenanceFields.ageSeconds` says "A viewer should
  recompute age from `checkedAt` rather than trusting this number." "checked 2s
  ago" is therefore not derivable from anything — it is an invented metric, which
  is on the exclude list (v2 *Prompt guidance applied*) and which §8 nonetheless
  claims to avoid ("anti-ai-slop (no emoji icons, gradients or invented metrics)").
  A freshness readout that starts by lying about its own source undercuts the
  thesis "Every fact says where it came from" (§9) and the floor "nothing
  presented as a real reading".
- **The staleness rule contradicts the pinned start state.** The feed may "age a
  service into Stale"; but the start is exactly `media-shelf` (Healthy) and
  `front-door` (`needs_attention`, freshness `live`). Ageing Media Shelf destroys
  the "quiet" state; ageing Front Door overwrites the fixture's `needs_attention`.
  Neither is allowed to happen by accident, and the design does not say what is.

**Why it matters.** v3 *What "the real rounds" add* 4 asks the feed to change
freshness, occasionally move a service to stale, "and update every view that
shows it without a reload". As written, the only specified reactive surface is a
badge in the top bar; the cross-view update (v2 req 4) is carried entirely by
`#simulate-change`, so the live feed is decoration with a fabrication in it. Under
`#simulate-change` the same gap shows up as silence: nothing says the ticker,
the slips and the agent strip re-render together.

**Fix.** Pin the feed as four decisions: (a) a mock clock anchored at the
fixture's `generatedAt`, so first paint reads the fixture's real age ("checked
24s ago"), never a fabricated 2 s; (b) the cadence ("tick every ~5 s; freshness
recomputed from `checkedAt`"); (c) a staleness rule that respects the fixture —
only facts whose fixture state is `live` may age, a service's state word changes
only where its own fixture data supports it, and `needs_attention`, `unavailable`
and `unknown` are never overwritten; (d) explicit propagation: every tick and
`#simulate-change` re-render the slip, the detail pane, the fact rows and the
agent-facts view together. Say what pause does (age freezes, data stays) and keep
"simulated" on every feed-driven change.

## 3. 390 is the desktop inventory reordered: `#simulate-change` is dropped and three navigation layers collide at the bottom

**Missing / wrong.** Two first-class layouts are required — "both designed on
purpose. Two first-class layouts, not one stretched … it is not a squeezed
desktop. No sideways scroll at 390px; 44px targets" (v3, 3). §12's mobile reading
order is "the counter's one-line status and live toggle; the selected service
card …; the other slips; then a floating `#add-service` above the tab bar."

- `#simulate-change` — a checker-contract control and the app's only cross-view
  demonstration — is absent from the 390 layout entirely.
- The bottom of the screen is claimed by three different things with no stated
  relationship: the "bottom tab bar" (§3), the floating `#add-service` "above the
  tab bar" (§12), and Connect's "sticky Back/Next bar" (§12). §3 says a service
  "opens as a pushed full screen", but never says whether the tab bar persists
  under that push or under Connect. At 390 with 44px targets this is exactly where
  targets overlap, text truncates and the layout scrolls sideways.

**Why it matters.** This is the layout the concept treats as its second half, and
as pinned it is the desktop set with `#simulate-change` removed and the controls
restacked — the "squeezed desktop" the brief rules out. It also risks the two
hard floors (44px, no sideways scroll) and hides a required control from the
checker.

**Fix.** Give mobile its own control map rather than the desktop reading order:
put `#live-toggle` and `#simulate-change` in the selected service card's status
row (or a labelled counter header) and say so; state the tab-bar contract per
mode (e.g. tab bar hidden while a service screen or Connect is pushed, Back
returns to the invoking slip); allow one 44px-safe bottom strip at a time and
name which; state the safe-area inset for the floating `#add-service`.

## 4. Warmth is budgeted, not laced in — the daily surface is left cold

**Missing / wrong.** The brief asks for warmth "laced in, not a theme park. Small,
specific, delightful moments: kind micro-copy, a tiny illustration or character
accent drawn in inline SVG, a gentle motion on a state change, a satisfying
'connected' moment" (v3, 2). The design names the ingredients but pins almost
none of them, and then confines them: §10 — "Whimsy may crowd the calm, so Dot
appears only at first run, connect, and state changes."

- No verbatim warmth in the working surfaces. There is the credential refusal
  (§2) and the disconnect copy (§6); the first-run "value sentence" (§6) is never
  written, and stale / unknown / retry / empty have no pinned kind line.
- No motion is specified for the moments that carry it: the state-change tick
  (§9), the "parcel and … 'Connected' stamp" (§2). The brief asks for motion
  "and calm under reduced motion"; `animation-discipline.md` wants motion to
  *confirm* a change that already happened, ≤200 ms for frequent micro-feedback,
  with a static substitute under reduced motion.
- Dot "carries the facts: slow on purpose, which is the calm" (§1) while the feed
  is the fast, reactive surface. Who moves is never resolved; a slow courier
  animating a 5-second tick is a contradiction, not a charming one.

**Why it matters.** Confining Dot to three events means the everyday screen — the
one the product is for — carries no warmth at all; the "lacing" becomes
onboarding garnish, which is the theme-park failure the brief names. It also
removes the concept's main claim to differ from C (§11), which rests on "warmth
through Dot, kind copy and a connect moment".

**Fix.** Pin warmth where it is used daily: three to five verbatim lines
(first-run value sentence; stale "nothing has changed since …"; disconnect "the
app itself is untouched"; retry "the reference is still here"); one motion spec
(duration, easing, and the reduced-motion substitute — opacity or the word, never
transform, with data still updating); and one sentence fixing Dot's relationship
to the feed (Dot idles and reacts to state changes; the tick is not Dot's journey)
or drop the "slow on purpose" framing.

## 5. The direction is named, not committed: the design system's identity is left UNKNOWN, and the concept keeps C's hero beside its new one

**Missing / wrong.** v3 requires the DESIGN.md to say how it differs from C and to
"take into account prompt guidance and the opendesign options to make unique
things". §8 uses `ds-wise`'s colour, radii and ring shadows, then leaves the thing
that design system *is* undecided: "Wise Sans and Inter are not available (no
external fonts), so I use a heavy system stack, an UNKNOWN for fidelity." `ds-wise`
is typography-first (weight 900, 0.85 leading, `calt` on all text, Inter 600
body); `skill-frontend-design.md` §2 says "Commit to one specific aesthetic
direction" and §5 says avoid a default system stack as the main visual idea
"unless the direction is intentionally utilitarian". Neither is claimed. §10 then
defers the signature pair to the build: "The lime-on-mint contrast is to be
measured on the built pairs" — but the guide requires decisions pinned in
DESIGN.md before code, and this is the pair the selected state is made of (mint
`#e2f6d5` slip on the off-white canvas, and any lime adjacent to it).

The same non-commitment appears in the hero. §9 names the signature as "the fact
journey receipt with Dot", but §11 keeps C's signature pairing ("the owning app
beside the shared facts") and §12 keeps its layout. The concept therefore carries
C's hero *and* a second hero, where the brief asks for ONE signature element.

And the stated difference from C is not yet a difference: §11 keeps C's
"persistent app shell, labelled and owned services, the owning app beside the
shared facts, honest states" — that is C's structure — and adds a skin (Wise), a
rename (cabinet → counter, bay → slip) and one shape claim: "a list-shaped receipt
… not a map, route or topology". A receipt of fact rows is what C's shared fact
card already is, and "receipt / ledger of facts" is adjacent to the round-2
anti-repeat entry "editorial ledger of facts" (v3, *Anti-repeat*), which §7 and
§11 never acknowledge.

**Why it matters.** With the display identity UNKNOWN and two signatures, the
build has no committed look, the "unique thing" the OpenDesign options were meant
to produce has not been chosen, and the required difference-from-C paragraph
reads as a restyle of C. The reference lock (Wise transfer breakdown) is doing
structural work that §11 does not yet show.

**Fix.** (a) Commit the display decision now: name the actual system stack with
weights, sizes and leading mapped onto `ds-wise` tokens, and state the trade
(Wise Sans 900 abandoned; body at weight 600 to keep the confident voice).
(b) Choose ONE hero and say which: either the receipt-with-Dot is the structural
spine (facts are the primary list, the frame a secondary strip) or the receipt
goes and the difference lives elsewhere; stop claiming C's docked pairing as the
signature. (c) Rewrite §11 as one testable sentence about a changed *interaction*,
and state explicitly how the receipt separates from "ledger of facts".
(d) Measure the selected-slip pair before the build, not after it.
